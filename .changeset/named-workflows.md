Breaking: telemetry traces named workflows instead of exposing a tracer (§59). `MfeTelemetry.tracer` is removed; `telemetry.workflow(name)` returns the mount's `Workflow` with that name, the same object every call, with `start(attributes?)`, `step(name, attributes?)`, `headers()`, `succeed(attributes?)` and `fail(error, attributes?)`. A workflow is one trace: a root span with a child span per step. `fail` records the error on both and reports it as an error record whose `spanContext` is the workflow's. Starting a workflow that is open abandons the open run (`mfe.span.end_reason: abandoned`, not an error); steps and ends while it is not open are ignored. `headers()` returns `{ traceparent }` for the current step while open, and `{}` otherwise or with tracing off. `telemetry.workflow(name, key)` takes an optional key, such as an upload's id, so several runs of one name can be open at once; the pair picks the run, one object per pair, and the key is never recorded. A workflow also has `event`, `debug`, `info`, `warn`, `error` and `measure`, with `MfeTelemetry`'s signatures: each emits the same record, with the `spanContext` of the current step, or the workflow before its first step, while open, and unlinked otherwise or with tracing off.

Nothing is ambient any more: `Tracer.startActiveSpan` is removed, records are no longer stamped with an active span's `spanContext`, and `#mfe/fetch` no longer reads an active span — spread `workflow.headers()` into a request to make it part of the workflow. `Tracer` is now only the provider seam, `{ startSpan(name, options?) }`, and `TelemetryProvider.createTracer` returns it. Disposing a mount with an open workflow closes its spans as cancelled without a `dispose/failure` diagnostic. `@company/mfe-react` and `@company/mfe-angular` export `Workflow` and no longer export `SpanKind`, `SpanStatusCode`, `Span`, `SpanOptions`, `SpanStatus` or `Tracer`; they remain in `@company/mfe-core` for providers.

Every request through `#mfe/fetch` to a declared API is now traced when the shell passes its provider to `installShellAuth({ tokens, telemetry })`: a `CLIENT` span named for the method, with `http.request.method`, `server.address`, `server.port`, `http.response.status_code` and `http.request.resend_count` after a 401 retry, never the path or query, ended as an error on a 4xx, a 5xx or a network failure. The request sends `traceparent` naming that span, as the root of a new trace, or, when the caller's headers carry a valid `traceparent` such as from `headers()`, as a child of the span it names, whose header it replaces. An invalid caller `traceparent` and any request to an undeclared origin go out untouched and untraced; without a provider nothing changes. The span is attributed to the container: `ContainerAuthBinding` requires `kind: 'app' | 'widget'`, which the generated `#mfe/fetch` now emits beside `id`, so regenerate a container's `.mfe` files.
