Breaking: telemetry traces named workflows instead of exposing a tracer (§59). `MfeTelemetry.tracer` is removed; `telemetry.workflow(name)` returns the `Workflow` with that name, the same object every call, with `start(attributes?)`, `step(name, attributes?)`, `headers()`, `succeed(attributes?)` and `fail(error, attributes?)`. A workflow is one trace: a root span with a child span per step. `fail` marks both as errors, each with an `exception` event, and reports the error as an error record whose `spanContext` is the workflow's. A run is the page's: every App and Widget that uses the name, with the same key, acts on the same run, and spans and records are attributed to the mount that made them. `start()` begins the run, or joins the open one and adds its attributes; any mount may then `step`, `succeed`, `fail`, read `headers()` or record through it, and a step ends the current step whichever mount marked it. `succeed` or `fail` ends it for everyone. The run ends as abandoned (`mfe.span.end_reason: abandoned`, not an error) when every mount taking part has been disposed; a mount disposed while others remain leaves the run and its spans open. Prefix names by domain, such as `orders.checkout`: in development, a run with an unprefixed name whose participants come from different Apps or Widgets is reported once. Steps and ends while it is not open are ignored. `headers()` returns `{ traceparent }` for the current step while open, and `{}` otherwise or when the run has no spans, as when the mount that opened it has tracing off. `telemetry.workflow(name, key)` takes an optional key, such as an upload's id, so several runs of one name can be open at once; the pair picks the run, one object per pair, and the key is never recorded. A workflow also has `event`, `debug`, `info`, `warn`, `error` and `measure`, with `MfeTelemetry`'s signatures: each emits the same record, with the `spanContext` of the current step, or the workflow before its first step, while open, and unlinked otherwise or when the run has no spans.

Nothing is ambient any more: `Tracer.startActiveSpan` is removed, records are no longer stamped with an active span's `spanContext`, and `#mfe/fetch` no longer reads an active span — spread `workflow.headers()` into a request to make it part of the workflow. `Tracer` is now only the provider seam, `{ startSpan(name, options?) }`, and `TelemetryProvider.createTracer` returns it. Disposing the last mount in an open workflow ends it as abandoned without a `dispose/failure` diagnostic. `@company/mfe-react` and `@company/mfe-angular` export `Workflow` and no longer export `SpanKind`, `SpanStatusCode`, `Span`, `SpanOptions`, `SpanStatus` or `Tracer`. For providers, `Span` keeps only what the framework calls — `setAttributes`, `setStatus({ code })`, `recordException(error)` and `end(endTime?)` — so `setAttribute`, `addEvent`, `isRecording`, `SpanStatus.message`, `SpanOptions.startTime` and `SpanRecord.exceptions` are removed. `@company/mfe-runtime` now re-exports `SpanOptions` beside `Span` and `SpanStatus`, so a provider can name every type `Tracer` uses, exports `SpanEmitterOptions` for `createSpanEmitter` and `RequestTracer` and `RequestTrace` for `createAuthenticatedFetch`, and no longer exports `nonRecordingSpan`, `createMountTelemetry`, `RESERVED_ATTRIBUTE_KEYS`, `isReservedAttributeKey` or their types.

Every request through `#mfe/fetch` to a declared API is now traced when the shell passes its provider to `installShellAuth({ tokens, telemetry })`: a `CLIENT` span named for the method, with `http.request.method`, `server.address`, `server.port`, `http.response.status_code` and `http.request.resend_count` after a 401 retry, never the path or query, ended as an error on a 4xx, a 5xx or a network failure. The request sends `traceparent` naming that span, as the root of a new trace, or, when the caller's headers carry a valid `traceparent` such as from `headers()`, as a child of the span it names, whose header it replaces. An invalid caller `traceparent` and any request to an undeclared origin go out untouched and untraced; without a provider nothing changes. The span is attributed to the container: `ContainerAuthBinding` requires `kind: 'app' | 'widget'`, which the generated `#mfe/fetch` now emits beside `id`, so regenerate a container's `.mfe` files.
