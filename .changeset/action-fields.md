**Breaking:** an action declares what the agent needs, and every caller's run is checked against it (§42). `ActionRegistration` gains `description`, `inputSchema`, `outputSchema`, `effect` (`'read' | 'write' | 'destructive'`, undeclared counting as `'write'`), `needsApproval`, `parallelSafe`, `timeoutMs` and `followUp`, and `execute(input, { signal })` receives the parsed input and a signal that aborts when the run is given up. `'agent'` is a placement and one of the defaults, so an absent `placements` is `['palette', 'agent']`. `ActionRegistry.execute(id, { caller, input })` validates the input (`invalid`) and the returned value, and for an agent's call applies the approval policy (`actionApprovalPolicy` on `createMfeRuntime`, `actions.setApprover` for the surface that asks; `declined` when the user says no) and runs writes one at a time. An agent's call has a deadline, `timeoutMs` or 30 seconds (`DEFAULT_ACTION_TIMEOUT_MS`), counted from when `execute` starts: past it the run is `failed` with `action/timeout` and the next write runs. A run still queued or running when its registration goes away resolves `unavailable`, and one whose call's `signal` aborts resolves `cancelled`; either way, and at the deadline, the action's signal aborts and whatever `execute` returns afterwards is dropped. An approval policy that throws denies the call, and an agent's call that waited is checked again for its placement and `canExecute` before it runs. A run's promise never rejects: a hook or a schema that throws makes it `failed`, and it is audited. `update` validates a registration as `register` does. `ActionRegistrationHandle.execute(call)` runs that registration and no other, and resolves `unavailable` once it is removed. `@company/mfe-core` exports `ActionExecutionContext`, the type of `execute`'s second argument. When two mounts of one definition register the same name, the second action's id is `<definitionId>:<name>-2`, then `-3`. `useAction` and `injectAction` return a run with the caller `'ui'`, which runs through their own handle; a `useAction` run made before its component registered, from a child's effect, waits for that registration. An `ActionEntry` carries `description`, `effect`, `followUp` and both schemas as JSON Schema, and `actionEntryEqual` compares them. The handle's `qualifiedId` follows a rename.
