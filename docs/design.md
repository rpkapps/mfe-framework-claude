# Design map

This page is the map: what is deployed where, what happens between a page load and a rendered screen, which package owns which concern, and where the seams between teams are drawn.

## Who this is for, and the one rule

A **micro-frontend** is a piece of a single web page built, versioned and deployed on its own, by its own team, and loaded at run time into a page it does not own. There are no iframes: the page is one browser document with one React tree. Two readers are expected — someone about to write such a piece, and someone maintaining the shell.

The design rule is one sentence, and the code follows it: every micro-frontend concern is expressed through a mechanism TanStack Router already has, or is invisible — an author's `basepath` is a router `basepath`, and loading, style isolation and federation plumbing stay behind the container entry and the build plugin. The second rule decides what you are building: **Apps take URLs, Widgets take props**. An **App** owns a stretch of the URL and routes everything below it with its own router; a **Widget** owns no URL and takes props inside somebody else's page. What cannot be expressed as a URL is a Widget.

## The system at rest

![The shell origin with the registry, three container origins, the browser document and the API.](./diagrams/system-at-rest.svg)

**In words.** Titled `system-at-rest`, under "What is deployed where, before anyone opens the page. Nothing is running yet." Left: a yellow box "The shell origin — the host; dev: `http://localhost:3000`" holding `index.html`, `the shell bundle`, and a purple `registry.json` annotated "one record per definition: id, container, manifestUrl". Right of it, three blue container boxes stacked — "operations — an App" on `http://localhost:3001`, "alert-panel — one Widget" on `http://localhost:3003`, "insights — four Widgets" on `http://localhost:3004` — each holding the same four purple tiles: `mf-manifest.json`, `remoteEntry.js`, `styles.css`, `runtime-config.json`. Three arrows labelled `manifestUrl` fan out from `registry.json` to those boxes. Below the shell origin, a grey box "The browser page" reads "One document, served from the shell origin. Every container above is fetched into this one page: its chunks, its stylesheet and its configuration", with an arrow labelled "served from" running up into the shell origin. Right: an orange "The API — dev: `http://localhost:3010`" holding `GET /api/assets`, reached by an arrow from the operations container's `runtime-config.json`, beside the note "runtime-config.json names the API. `#mfe/fetch` resolves a request against it and attaches the session token to the origins declared `{ api: true }`, and to no others." The legend "What the colours mean": yellow the shell (the host page), blue a container (an App, or Widgets), purple generated by the build, orange network and API, grey the browser document.

The **shell**, or **host**, is the one application on the page not listed in the registry: it serves the document, owns the chrome, the theme and the routes above a boundary, installs the page's one session, and mounts Apps and Widgets into itself. The **registry** is the JSON array it fetches at boot, one **registry entry** per definition — `id`, `kind`, `manifestUrl`, the federation container name and expose path, an optional `version`, and either a Widget's published contract or an App's capabilities. It is generated from each container's own descriptor, because a hand-written second copy drifts.

A **container** is one deployable: its own build, version and origin, one `src/mfe.ts` exporting at most one App and any number of Widgets. It publishes `remoteEntry.js` — the **remote entry**, the file that lets a host load code out of another build — described by `mf-manifest.json`, plus its scoped stylesheet and its registry descriptor.

`runtime-config.json` is never built into the container: the deployment publishes it beside the container's assets, and the generated `#mfe/config` fetches it against the container's own public path and validates it against the author's Zod schemas in a top-level `await`. Changing a value takes a new deployment and a reload. `#mfe/fetch`, generated for every container, is the way to the API: a relative URL resolves against the first field declared `env(…, { api: true })`, and the session token reaches only the declared origins.

| Party       | Owns                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------ |
| the shell   | the document, the theme, the session, the registry fetch, the boundary routes, diagnostics |
| a container | its definitions, its route tree, the classes its CSS needs, its `runtime-config.json`      |
| the build   | the `#mfe/*` modules, the container entry, the federation options, the descriptor, the CSS |

## From boot to a mounted App

![Twelve numbered steps from the shell booting to an App rendering, with the failure branches.](./diagrams/boot-to-mount.svg)

**In words.** Titled `boot-to-mount`, under "Page load to a rendered App, in the order the code runs, with the branches that fail." Two columns of numbered cards, each a title, a line of code and a grey note, chained downward by arrows. Left column, "In the shell — `apps/shell/src/boot.tsx`": **1** "The document boots", `src/boot.tsx`, "index.html has already set the theme, before first paint"; **2** "The diagnostics hub is built first", `new DiagnosticsHub([telemetryDiagnosticsSink(t)])`, "the runtime adopts this hub rather than making one"; **3** "The shell installs the page's one session", `installShellAuth({ tokens, diagnostics })`, "before any remote is registered"; **4** "The registry is fetched", `await fetch('/registry.json')`, "a registry that fails to load is a diagnostic, not a crash"; **5** "The runtime is assembled", `createMfeRuntime({ registryEntries, loader })`, "developer overrides are read before anything registers"; **6** "Every entry is normalized on its own", `normalizeRegistry: accepted, or quarantined`, "one malformed entry loses only itself". An elbow arrow carries card 6 right and up into the second column, "In the framework — `@company/mfe-react`": **7** "The URL picks the boundary", `/operations/wells matches the shell route /$appId`, "a definition id is the only path the shell claims"; **8** "The boundary hands the page over", `<AppHost appId='operations' basePath='/operations'>`, "below this the shell renders nothing of its own"; **9** "The container is loaded, once", `registerRemotes, then loadRemote('operations/app')`, "one load per container, shared by every waiter"; **10** "The mount is made by the effect that ends it", `useOwnedMount(() => createMount({ ... }))`, "token, overlay root, telemetry, Query client, storage"; **11** "The factory runs once, and is checked", `createRouter({ basepath: basePath, history })`, "basepath through unchanged; the supplied history itself"; **12** "The App is on the page", `MfeScopeRoot, StyleRoot, RouterProvider`, "the App owns every URL below its boundary". A third column holds the branches: an arrow from card 9 into "When step 9 fails", holding the red tiles `load/manifest-failure`, `load/entry-failure` and `registry/invalid-descriptor`, and an arrow from card 11 into "When step 11 fails", holding `app/invalid-base-path` and `app/invalid-router`. Arrows lead down from both into a grey "What the page shows": "'operations could not be loaded', the message the error carries, its code, and a Retry button that makes a genuinely fresh attempt. The chrome stays. Every other App stays reachable. One boundary is the whole cost of the failure."

What the picture leaves implicit. Normalization never falls back silently: the first adapter rule whose `advertises()` returns true owns an entry, even when its `normalize` then fails, and a failure **quarantines** it — sets it aside with a reason and an error — rather than dropping it; two entries claiming one id quarantine all the claimants.

A **boundary** is the stretch of URL assigned to one App mount, and the shell can claim `/$appId` for it because a definition id is lower-case letters, digits and single hyphens. **Module Federation** is the bundler mechanism that loads code from another build at run time; its load promise is cached per runtime per id, a rejection included, because React needs the same settled promise to surface the failure. There is no time budget: the load suspends until it settles or fails, and retry is explicit. (`CreateRuntimeOptions` accepts `deadlines` and `MfeRuntime` carries it, but nothing on the React path reads it, and `load/timeout`, `mount/timeout` and `dispose/timeout` are never raised.)

The **mount** is one live instance of a definition: its mount token, base path, telemetry surface, storage handles, abort signal, Query client and overlay root. It is created by the effect that destroys it, because building it in a memo and disposing it in an effect does not survive the mount-unmount-mount React performs in StrictMode. The **definition** is a side-effect-free descriptor, so the adapter can check what the author did with it — the supplied `basePath` passed through as `basepath`, the supplied history by identity, `context.mfe` and `context.queryClient` unchanged — and a violation throws during render, naming the repair.

On any of those failures the consumer's `fallback` receives the error and a `retry` that forgets the cached definition and remounts the loader. There is no automatic retry and no backoff.

| `@company/eslint-plugin-mfe`  | The `framework` and `author` lint presets. Development-only.                                                               |
| `@company/mfe-devtools`       | The developer tools overlay: lazy-loaded, in every build, gated on one key.                                                |
| `apps/shell`                  | The host page: the document, the chrome, the boundary routes, the session, the registry.                                   |

The real DAG, as the manifests have it: the core depends on nothing in the workspace; the host on the core; the two adapters each on the core and the host, never on each other; the developer tools on the core, the host and the React adapter; `@company/mfe-rspack` on the core alone, since it runs in the build rather than on the page; the scaffold and the lint plugin on neither. `apps/shell` sits on the React adapter, the host and the developer tools. The README's ASCII version draws only the first four.

`pnpm boundaries` enforces it by naming forbidden specifiers per package and reading the `src/**` imports and the manifest's dependencies alike, so a forbidden edge cannot be added by editing a `package.json`. Five packages carry a rule: the core and the host may reach no React, router, Query, single-spa, Module Federation, vendor telemetry SDK or state library; the React adapter no single-spa, vendor SDK or developer tools; the legacy adapter no React; the developer tools no build plugin.

**What an author touches:** `src/mfe.ts`, the route tree under `src/routes/`, `src/mfe.config.ts`, the generated `#mfe/config`, `#mfe/fetch` and `#mfe/meta`, the exports of `@company/mfe-react`, and one `pluginMfe()` line in `rsbuild.config.ts`. Authors import from `@company/mfe-react` and nowhere else; the core, the host and any deep path are blocked by the `author` lint preset.

**What stays invisible:** Module Federation, which appears in one framework file and one shell file; the registry JSON; everything under `.mfe/`; the mount token, the scope root and the overlay root; and the diagnostics wiring.

## The isolation boundaries

![One mounted App ringed by six seams: URL, styles, storage, network, errors, shared singletons.](./diagrams/isolation-boundaries.svg)

**In words.** Titled `isolation-boundaries`, under "Six boundaries between one mounted container and the rest of the page." A blue box sits in the centre: "One mount of the operations App — its mount token, its basePath, its own scope root", with the line "Everything around it is a seam the framework owns." Six grey panels surround it, three above and three below, each reached by its own arrow from the centre. Top row: **URL** — "basePath is assigned by the host and passed straight through to `createRouter({ basepath })`. The history is built over the navigation bridge by `createBoundaryHistory`, never by `createBrowserHistory`, which reassigns `window.history.pushState` for everyone." **Styles** — "The container ships only the utilities for its own classes, wrapped by the build in `@scope ([data-mfe-scope="operations"]) to ([data-mfe-scope])`. The shell keeps the document half: preflight, the fonts, `@property`, the theme variables." **Storage** — "Every record goes through the storage boundary, under the key `<definitionId>:<name>`. `retention: 'user'` is the default, and is wiped when the identity or the group set changes. State the page owns rather than any definition goes in the reserved `@host` scope." Bottom row: **Network** — "The generated `#mfe/fetch` resolves a relative request against the base URL that `runtime-config.json` supplied, and attaches the shell's session token to the origins declared `{ api: true }`: an exact scheme, host and port set, with no wildcards and no substrings." **Errors** — "Every failure is an `MfeError` carrying a code from a closed union, the definition id, the operation and the repair to make. It reaches the shell's `DiagnosticsHub`, which forwards it to telemetry. A failed mount costs its own boundary and nothing else." **Shared singletons** — "`react`, `react-dom`, `@tanstack/react-router`, `@tanstack/react-query` and `@company/mfe-*` resolve once per page, through the Module Federation share scope. The host declares `shareStrategy: 'loaded-first'`, so one unreachable manifest cannot take the whole page down with it."

### URL

The **base path** is the literal string form of the boundary, and after `createRouter({ basepath })` it never appears again: `basepath` makes every route, `Link` and `navigate` relative, so the author writes ordinary absolute-looking paths. The **boundary history** is hand-built because `createBrowserHistory()` reassigns `window.history.pushState` for the whole page — action at a distance that breaks anything else wrapping it (decisions §1).

### Styles

Scope proximity, not injection order, is what the `@scope` rule buys: two builds that both spell `bg-primary` no longer resolve by whichever stylesheet was parsed last. Each mount renders a **scope root** carrying `data-mfe-scope`, with a build-attached **style root** inside it supplying the design system's context from the container's own copy of the library; overlays portal into a body-level **overlay root** carrying the same attribute, which is what keeps a popover in its container's styles while it sits outside its subtree. `@scope` is the narrowest-supported feature the framework requires — Chrome and Edge 118, Safari 17.4, Firefox 146 — with no fallback, below which the last stylesheet loaded wins the page unscoped (decisions §17).

### Storage

The key is never scoped by mount token, so two mounts of one definition read the same record. **Retention** says who may read a value back rather than how long it lives: `'user'` is fenced by the session generation, and `'browser'` is never cleared by the framework, so every user of that browser profile reads it. `@host` is spelled with an `@` because no definition id can contain one, which is what makes the scope unclaimable (decisions §24).

### Network

`#mfe/fetch` is a standard `fetch` bound to one container's **transport**, so a route loader passes its own `signal` and otherwise writes ordinary code. It retries once after a 401 when the request can be replayed, and a 403 passes through untouched: attaching a token is not authorization. The allowlist has no wildcards because a wildcard would hand the session bearer token to any host the pattern happens to match; a request to an undeclared origin goes out without one.

### Errors and diagnostics

The message is composed to a fixed shape — `<id>[@<version>] failed to <operation>[ <path>][: expected …, received ….] <repair>` — and `code` comes from a closed union, so adding one is a deliberate contract change. A sink that throws cannot stop the others, and a hub with no sinks discards everything. An author wires none of it: the definition id, kind, version, build hash, mount token and trace id ride along as attributes nobody can override.

### Shared singletons

The full singleton set is `react`, `react-dom`, `sonner`, `@company/mfe-core`, `@company/mfe-host`, `@company/mfe-react`, `@tanstack/react-router` and `@tanstack/react-query`, each with `strictVersion`, because a second copy makes every hook fail with "rendered outside any mount" while both copies look correct on their own. `@tecton/react/` is a prefix share and deliberately not a singleton, nor is `react-aria-components`; `recharts` is shared but never eagerly. A container may add to that list and cannot remove from it — opting out of sharing React would load a second one into a page that already has one (decisions §30).
