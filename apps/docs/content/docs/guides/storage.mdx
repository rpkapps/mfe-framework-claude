---
title: '7. Storage'
description: 'Scoped keys, retention, and what survives a reload, a sign-out and another user on the same browser.'
---

You want to keep a filter, a draft or a collapsed panel across a reload, and `localStorage` is
right there. Do not use it. One browser profile carries several people over a day, one page carries
several <Term>containers</Term> — independently deployed pieces of the same document — and Web
Storage is a single flat key space shared by all of them and by the <Term>shell</Term>, the
application that owns the page. Keys collide, the shell cannot clear yours when somebody signs out,
and a quota failure escapes as an unhandled exception in whichever container happened to write last.

Instead you declare a key with a schema and get back a subscribed value and a stable setter. The
key is namespaced under your definition id, and fenced to the signed-in identity unless you say
otherwise.

- **What survives what** — storage decides how long the browser keeps it; retention decides who may
  read it back. Two columns, `retention: 'user'` (default) and `retention: 'browser'`. The identity

  group set changes: wiped / kept. A reload: kept / kept. The tab closes, with `storage: 'session'`:

## `useStoredState(name, schema, options)`

```tsx title="src/routes/storage.tsx"
import { useStoredState } from '@company/mfe-react'
import { z } from 'zod'

/** Module scope: a schema rebuilt in a component body is a different object on every render. */
const filtersSchema = z.object({ status: z.enum(['open', 'closed']) })

export function Filters() {
  const [filters, setFilters] = useStoredState('filters', filtersSchema, {
    defaultValue: { status: 'open' },
  })

  return <StatusPicker value={filters.status} onChange={status => setFilters({ status })} />
}
```

**The name.** A non-empty string, stable across renders. The physical key is
`<definitionId>:<name>` — `operations:filters` — so two definitions may use the same name without
colliding, and two <Term>mounts</Term> of one definition read the same record: there is no mount
token in the key. Your definition id may not contain a `:`, because that is what separates the id
from the name. `local` and `session` are separate spaces, so `operations:filters` in each is two
different records.

**The schema.** A Zod schema, declared at **module scope**. It is the single source of truth for
what is stored and for the type you get back, and the framework compares it **by reference** when
two components bind the same key. A schema built inside a component body is a new object every
render, which rebinds the key on every render.

**`defaultValue`** is required, and it is validated where it is declared rather than on first use.
It is what you read when the key is absent, and what a user-retained record resets to when the
session is retired.

**The setter** takes a value or an updater function, and its identity is stable across a rebinding.
An unreadable stored value **throws** rather than falling back to the default, so a corrupt record
reaches an error boundary instead of looking like missing data.

The remaining options are `storage` (`'local'`, the default, or `'session'`), `retention`,
`version` and `migrate`.

## `retention`: who may read it back

Retention is not about how long a value lives — `storage` decides that. Retention decides **who may
read it back**.

`retention: 'user'` is the default. Every such record is stamped with the <Term>session generation</Term>:
an opaque string the shell mints once per signed-in identity per tab and stores at
`@host:session-generation`. Identity is stored beside it, never baked into it, and
callers compare it for equality and never parse it. A reload of the same tab with the same identity
reuses the generation, so the record survives. When the shell reports that the identity changed
(login, logout, an account or tenant switch) or that the group set genuinely changed, a fresh
generation is minted and every `retention: 'user'` record in both stores is physically removed —
including records belonging to definitions that are not mounted. A record that survives a failed
delete still reads as absent, because its `g` no longer matches. A generation is never reused. A
theme change and a token refresh are not identity changes and retire nothing, and a group list that
was only reordered is the same set and retires nothing either.

`retention: 'browser'` opts out of all of that. The framework never clears it, **which also means
every user of that browser profile reads the same value**.

<Callout type="warning" title="The rule for choosing">
  Use `retention: 'browser'` only for genuinely impersonal state — a display density, a collapsed
  panel, a chosen tab. Anything derived from a signed-in user's data stays on the default. The
  default is the safe answer, so the safe answer is the one you get by not deciding.
</Callout>

```ts title="src/routes/storage.tsx"
// Survives a sign-out, so the next person on this browser reads it.
const [draft, setDraft] = useStoredState('draft', draftSchema, {
  defaultValue: { note: '', pinned: false },
  retention: 'browser',
})

// Dies with the tab, and is wiped on sign-out.
const [visits, setVisits] = useStoredState('visits', visitsSchema, {
  defaultValue: 0,
  retention: 'user',
  storage: 'session',
})
```

## The `@host` scope

Outside any mount — shell chrome, a boot script — `useStoredState` resolves to the reserved scope
`@host`, and the key becomes `@host:dashboard`. The `@` reserves it: a definition id is lower-case
letters, digits and single hyphens, so no registry entry can ever claim that name.

As an App or Widget author you never reach it, and cannot: you are always inside a mount, so the
scope is always your definition. It matters to you as the reason the shell's own records can never
collide with yours. Reaching `@host` deliberately through the definition surface is refused:

<Callout type="error" title="storage/failure">
  @host failed to bind a storage key: expected a definition id, received the reserved host scope
  '@host'. Use bindHost() or hostStorage() for state the host page owns; they reach the same scope
  deliberately.
</Callout>

## `useMfeStorage` for imperative access

When you need a value outside a render — in an event handler, a loader, a cleanup — take the
imperative handle. `get()` does not subscribe, so anything you render still uses `useStoredState`.

```ts title="src/export.ts"
import { useMfeStorage } from '@company/mfe-react'

const storage = useMfeStorage() // 'local' by default; pass 'session' for the other area
const key = storage.key('filters', filtersSchema, { defaultValue: { status: 'open' } })

key.get() // the value, or null for a missing key — never null for an invalid one
key.set({ status: 'closed' })
key.remove()
storage.clear() // only keys under the exact `operations:` prefix
```

`get()` forces a fresh read of the browser store where `useStoredState` serves a cached snapshot,
and an imperative write notifies the reactive subscribers of that key. `clear()` removes only the
exact `<id>:` prefix: `acme-orders` never touches `acme-orders-legacy:`, the shell's keys, or a
third party's. The store never removes what it did not write.

## Versioning and migration

`version` defaults to `1` and must be an integer of 1 or more. Raise it whenever the persisted shape
changes, and declare `migrate(value, fromVersion)` — synchronous and side-effect-free — to convert
what is already on disk.

```ts title="src/filters.ts"
const [filters] = useStoredState('filters', filtersSchema, {
  defaultValue: { status: 'open' },
  version: 2,
  migrate: (value, fromVersion) =>
    fromVersion === 0
      ? { status: 'open' }
      : { status: (value as { open: boolean }).open ? 'open' : 'closed' },
})
```

A record written by a **newer** build is an error and is never overwritten. An older one without a
`migrate` is an error. A record that is valid JSON but not a framework envelope — anything written
before this boundary existed — is handed to `migrate(parsed, 0)`. A migration converts, validates,
then writes, and only while the generation it started in is still in force; nothing is written when
the conversion throws, produces an invalid value, or the session moved on.

## Size and serialization

There is no framework size limit; the limit is the browser's, and it surfaces as a quota error with
the serialized character count in the message. The value is stored with `JSON.stringify`, so store
plain JSON. Unlike a Widget's inputs, a stored value is not screened for non-serializable types
first: a `Date` round-trips as a string and then fails your own schema on the next read.

## The lint rule

`mfe/no-raw-storage` is on in the `author` preset. It reports a global reference to `localStorage`
or `sessionStorage`, and `window.localStorage`-style member access; a shadowing local of the same
name and a type position are not runtime access. It is off in test files only, because a storage
test has to reach the storage it verifies.

<Callout type="error" title="mfe/no-raw-storage">
  `localStorage` bypasses the MFE storage boundary: the key is not namespaced, so another MFE in
  this origin can read or overwrite it, the shell cannot clear it on sign-out, and a quota failure
  escapes as an unhandled exception. Use `useStoredState()` for component state or `useMfeStorage()`
  for imperative access, both from @company/mfe-react. The storage adapter and a documented shell
  override bootstrap opt out through this rule's `allowedScopes` option.

The editor also offers a suggestion: "Read and write through the MFE storage boundary: replace
`localStorage` with `storage` from `const storage = useMfeStorage()`." It is a suggestion rather
than a fix because it only compiles once the file binds `useMfeStorage()`.

</Callout>

## Every storage failure, and its fix

All of them carry `code: 'storage/failure'` and compose as
`<id> failed to <verb> the <area> storage key <name>: expected …, received …. <repair>` — for
example `lab failed to write the local storage key draft: …`. The verb is one of `bind`, `read`,
`write`, `remove`, `migrate` or `clear`. Every one is also reported to the diagnostics hub with
`context: { definitionId, area, key }` before it is thrown.

**Binding a key**

| You see: expected / received                                                                  | Do                                                                                |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `a non-empty storage key name`                                                                | "Give the key a stable name, e.g. `bind(id, { name: 'filters', schema })`."       |
| `a definition id without a colon`                                                             | "Use the registry definition id; the colon separates the id from the key name."   |
| `an integer schema version of 1 or more`                                                      | "Start at 1 and raise it whenever the persisted shape changes, adding migrate()." |
| `a default matching the declared schema (…)`                                                  | "Fix defaultValue; it is validated where it is declared, not on first use."       |
| `the same schema object every active consumer already declared` / `a different schema object` | "Declare 'lab:draft' in one shared module so every consumer agrees on schema."    |
| `retention 'user'` / `retention 'browser'` — or a differing `version` or default              | The same repair, naming the field that differs                                    |

A disagreement is always reported to the consumer that disagrees, not to whoever rendered first. The
schema comparison is by reference, which is the whole reason the schema belongs at module scope; the
`defaultValue` comparison is structural, so an inline object literal is fine.

<Callout type="error" title="storage/failure, at bind">
  lab failed to bind the local storage key draft: expected the same schema object every active
  consumer already declared, received a different schema object. Declare 'lab:draft' in one shared
  module so every consumer agrees on schema.

**Fix.** Move the `z.object({ … })` out of the component and export it from one module both
consumers import.

</Callout>

**Reading a key**

| You see: expected / received                                                            | Do                                                                                                                                                       |
| --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `a record written through the framework storage boundary` / `text that is not JSON (…)` | `Remove 'lab:draft' from local storage.`                                                                                                                 |
| `a framework envelope at version 1` / `an unversioned record (an object)`               | `Declare migrate() on 'draft' to convert it, or remove the key.`                                                                                         |
| `the session generation to be established before a user value is read`                  | "Give the store its generation before mounting anything that reads session state."                                                                       |
| `a stored value matching the declared schema (…)`                                       | `Raise the version of 'draft' and declare migrate(), or remove the key.`                                                                                 |
| `version 1` / `version 2, written by a newer build`                                     | "Reload into the current build; a record from the future is never overwritten."                                                                          |
| `version 1` / `version 2 with no migrate() declared`                                    | `Declare migrate() on 'draft', or remove the key.`                                                                                                       |
| `local storage to be readable`                                                          | "Storage is unavailable here — private mode, blocked cookies, or a disabled store. The framework never falls back to memory or to the declared default." |

**Migrating**

| You see: received                                          | Do                                                                                |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `migrate() threw (…)`                                      | `Fix migrate() for 'draft'. The previous record is preserved.`                    |
| `a migrated value matching the declared schema (…)` failed | `Fix migrate() for 'draft'. Nothing was overwritten.`                             |
| `the session moved on while it ran`                        | "A retired session's data is never migrated into a new one. Nothing was written." |

**Writing a key**

| You see: expected / received                                                                      | Do                                                                                                                                          |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `the session generation to be established before a user value is written` / `no session in force` | "Establish the generation before mounting, or declare retention: 'browser'."                                                                |
| `a readable current value for the functional update to apply to`                                  | `Write an explicit value to 'draft', or remove the key first: a functional update has no valid base while the stored record is unreadable.` |
| `a value matching the declared schema (…)`                                                        | `Fix the value passed to set() for 'draft'. The stored value is unchanged.`                                                                 |
| `a JSON-serializable value`                                                                       | "Store plain JSON; the stored value is unchanged."                                                                                          |
| `local storage to accept 2097152 characters` / `QuotaExceededError`                               | "The store is full or blocked. Persist less, or clear this definition. The stored value is unchanged."                                      |
| `the write to commit in the generation it started in ('…')` / `the session moved on to '…'`       | "Drop the result: work started in a retired session never commits into the new one."                                                        |
| `to remove 'lab:draft'`                                                                           | "Retry the removal; the stored value is unchanged."                                                                                         |

**Clearing**

| You see: expected                                  | Do                                                        |
| -------------------------------------------------- | --------------------------------------------------------- |
| `to enumerate local storage for keys under 'lab:'` | "The framework never clears a store it cannot enumerate." |
| `to remove 'draft'`                                | `Retry; nothing outside 'lab:' was touched.`              |

<Callout type="error" title="storage/failure, at write">
  lab failed to write the local storage key draft: expected local storage to accept 2097152
  characters, received QuotaExceededError: The quota has been exceeded. The store is full or
  blocked. Persist less, or clear this definition. The stored value is unchanged.

**Fix.** Persist an identifier and refetch the body, or call `storage.clear()` for this
definition. The previous stored value is untouched.

</Callout>
