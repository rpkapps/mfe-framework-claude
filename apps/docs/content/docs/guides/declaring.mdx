One file tells the framework what you built: `src/mfe.ts`. `createApp` and `createWidget` each
return a <Term>definition</Term> there, a plain value the build reads, the host loads and the mount
checks. This page is every option of both calls, the `package.json` block beside them, and every
check you can trip.

## Declare an App

```ts title="examples/operations/src/mfe.ts"
import { createApp, type AppRouterOptions, type MfeStaticData } from '@company/mfe-react'
import { createRouter } from '@tanstack/react-router'

import { routeTree } from './routeTree.gen'

function makeRouter({ basePath, history, context }: AppRouterOptions) {
  return createRouter({
    routeTree,
    basepath: basePath,
    history,
    context: { ...context },
    defaultPreload: 'intent',
  })
}

// TanStack Router's own type registration. `Register` gives Link, navigate and useParams the
// route types of this App's generated tree, which `ReturnType<typeof makeRouter>` names.
// `MfeStaticData` types the four staticData fields the framework reads off a route:
// capability, label, icon and breadcrumb.
declare module '@tanstack/react-router' {
  interface Register {
    router: ReturnType<typeof makeRouter>
  }

  // eslint-disable-next-line @typescript-eslint/no-empty-object-type -- an augmentation declares no field of its own.
  interface StaticDataRouteOption extends MfeStaticData {}
}

export default createApp({ id: 'operations', version: '2.1.0', router: makeRouter })
```

Discovery reads the container entry and nothing else: `src/mfe.ts`, or `src/mfe.tsx` when the entry
itself holds JSX. Export every definition from that file. An unexported definition is never built
into the container, and one declared in another module is reported as a stray.

The scaffold writes the `declare module` block for you. The second interface types the
`staticData` slot, so a misspelt capability is a compile error. Without it,
`staticData: { capability: 'setings' }` is a capability page the shell never opens.

## Declare a Widget

```ts title="examples/alert-panel/src/mfe.ts"
export const alertPanelContract = {
  inputs: z.object({
    alertId: z.string(),
    severity: z.enum(['info', 'warning', 'critical']).default('info'),
  }),
  events: {
    acknowledged: z.object({ alertId: z.string(), acknowledgedAt: z.string() }),
    dismissed: z.object({ alertId: z.string() }),
  },
}

export const alertPanel = createWidget({
  id: 'alert-panel',
  version: '1.4.0',
  title: 'Alert panel',
  description: 'Open alerts for one asset, acknowledged or dismissed in place.',
  tags: ['alerts', 'operations', 'safety'],
  icon: BellIcon,
  ...alertPanelContract,
  render: AlertPanel,
})
```

`inputs` and `events` together are the Widget's <Term>contract</Term>. They are the single source
of truth for runtime validation and for the author-facing types, so the two cannot drift. The build
publishes them in the <Term>registry</Term>, the generated list the shell reads at boot. A
catalogue can then offer the Widget before the container has been fetched.

Keep `render` in its own module, as the example does. React Refresh replaces a module in place only
when every export of it is a component, and `src/mfe.ts` exports a definition
([9. Daily workflow](/docs/guides/daily-workflow#keep-hot-updates-working)).

## Every option

| Option        | Used by | Type                                       | Required | What it is                                                                                                                                            |
| ------------- | ------- | ------------------------------------------ | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`          | both    | `string`                                   | yes      | The only public identity field, unique across every App and Widget. Also the storage prefix and the CSS scope value.                                  |
| `version`     | both    | `string`                                   | no       | Stamped onto every failure the mount reports, so you know which build produced it. Nothing checks that it is semantic or matches the package version. |
| `router`      | App     | `(options: AppRouterOptions) => AnyRouter` | yes      | Called once per mount, never once per module. Two mounts get two routers.                                                                             |
| `breadcrumbs` | App     | `false`                                    | no       | Opts this App out of its own breadcrumb segment, not out of a nested App's.                                                                           |
| `inputs`      | Widget  | a Zod object schema                        | yes      | What the Widget takes. Validated at the provider boundary on every update. A Widget that takes nothing declares `z.object({})`.                       |
| `events`      | Widget  | `Record<string, z.ZodType>`                | yes      | What it emits, by name. A Widget that emits nothing declares `{}`.                                                                                    |
| `render`      | Widget  | `(props: { inputs, emit }) => ReactNode`   | yes      | The component, imported from its own module. Its props are typed from the two schemas.                                                                |
| `title`       | both    | `string`                                   | no       | What a catalogue shows before anything is loaded. The host's presentation map may override it.                                                        |
| `description` | both    | `string`                                   | no       | The same, in one sentence.                                                                                                                            |
| `tags`        | both    | `readonly string[]`                        | no       | Free-form. A catalogue filters on them and never interprets them.                                                                                     |
| `icon`        | both    | an imported identifier                     | no       | An icon component or an imported `.svg`. The build follows the import and publishes the shapes.                                                       |

Write the presentation fields as literals: `id`, `version`, `title` and `description` as plain
strings, `tags` as an array of strings, `icon` as an imported identifier. The build reads them out
of the syntax without executing your module, because the registry crosses an origin boundary and
carries data rather than components. A computed title is a build error, and so is an icon the build
cannot resolve.

### The router factory: `AppRouterOptions`

The factory receives three values, and all three have to reach `createRouter` unchanged.

| Field      | What it is                                                                                                              | What you do with it                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `basePath` | The <Term>base path</Term>: the literal string form of the boundary the shell assigned, the URL prefix this mount owns. | Pass it as `createRouter({ basepath })`. It never appears again: every route, `Link` and `navigate` is relative to it.             |
| `history`  | The framework's boundary history, over the shell's navigation bridge.                                                   | Forward it. Never call `createBrowserHistory()`: it reassigns `window.history.pushState`, and two routers then fight over the URL. |
| `context`  | `{ mfe, queryClient }` — the mount's services and its Query client.                                                     | Spread it: `context: { ...context, yourKey }`. Your own top-level keys survive every framework context update.                     |

`context.mfe` carries `user`, `groups`, `theme`, `telemetry`, `storage.local`, `storage.session`
and `signal`. A route `loader` or `beforeLoad` reads it from there. `user`, `groups` and `theme` are
snapshots, and the framework rebuilds the namespace on every shell-state transition, so a value
captured across an `await` is stale. `RESERVED_CONTEXT_KEYS` is `['mfe', 'queryClient']`: add keys
beside them, never replace one, and never add a field inside `mfe`.

## Export a contract for consumers

```json title="examples/alert-panel/package.json"
"exports": {
  "./contracts": "./.mfe/widgets/alert-panel.contract.ts"
}
```

The build generates a side-effect-free contract module per Widget, and publishing it is one
`exports` entry you add yourself. For a container with several Widgets, one pattern covers them
all: `"./contracts/*": "./.mfe/widgets/*.contract.ts"`. The generated module exports `widgetId`,
`inputs`, `events` and the types `Inputs` and `Events`, so a consumer writes:

```ts title="examples/operations/src/widgets.ts"
import { events, inputs } from '@example/alert-panel/contracts'

export const AlertPanel = lazyWidget('alert-panel', { contract: { inputs, events } })
```

The build copies the schema into that module, so it has to be able to read the schema without
running anything. Declare it inline in `src/mfe.ts`, or as an exported top-level `const` in another
module of the same container. Never import it from the entry itself or from a bare package.

## The `mfe` block in `package.json`

```json title="examples/operations/package.json"
"mfe": {
  "port": 3001,
  "definitions": ["operations"]
}
```

| Field         | What it does                                                                                                                                                                                                                                                                               |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `port`        | The container's dev-server port. Its own `rsbuild.config.ts`, `pnpm dev` and the registry builder all read it back, and the builder writes the dev URL into the shell registry. `server.strictPort` is set for you, because a container that fell back to another port would be invisible. |
| `definitions` | The ids `pnpm dev` prints the developer-override snippet for. Nothing validates it against what `src/mfe.ts` exports, so keeping it accurate is a convention.                                                                                                                              |

A container with no `mfe.port` stops the registry build:
`<name>: package.json declares no mfe.port, so its dev URL is unknown.`

## Errors you will see

Build errors name the file, the line and the column. The identity and event checks run when your
entry module is evaluated, which in the browser is when the shell loads your container. The router
checks run at mount, the moment your factory returns.

### At mount: the router checks

| What went wrong                         | The message                                                                                                                                                                                                                                                                                     | Fix                                                                  |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `basePath` never reached `createRouter` | `operations@2.1.0 failed to mount App: expected the supplied basePath "/operations" passed through unchanged as createRouter({ basepath }), received no basepath on the router. Forward the basePath your factory received: createRouter({ basepath: basePath, … }).` (`app/invalid-base-path`) | Add `basepath: basePath` to the `createRouter` call.                 |
| A history of your own                   | `operations@2.1.0 failed to mount App: expected the exact history instance the framework supplied, received a different history object. Do not create, wrap, replace or mutate the history; forward the one your factory received.` (`app/invalid-router`)                                      | Drop `createBrowserHistory()` and forward `history`.                 |
| The context was replaced                | `operations@2.1.0 failed to mount App: expected the supplied context.mfe namespace, spread into the router context unchanged, received no mfe key. Spread the supplied context: add your own top-level keys freely, but do not replace mfe or add fields inside it.` (`app/invalid-router`)     | Write `context: { ...context, yourKey }`.                            |
| Your own Query client                   | `operations@2.1.0 failed to mount App: expected the supplied top-level queryClient, forwarded unchanged, received a different Query client. Spread the supplied context rather than constructing your own Query client; the mount owns one.` (`app/invalid-router`)                             | Spread the context instead of building a client. The mount owns one. |

A hard-coded `basepath` produces the same base-path failure, with the string you wrote in place of
`no basepath on the router`. That case is worth knowing. An App delegated inside another App
is mounted at a different boundary from the one it has on its own.

A child route may return its own `mfe` or `queryClient` from `beforeLoad`. That is a
development-only diagnostic rather than a throw. It names the route:
`Rename the key you return from beforeLoad in /assets.`

## Why the entry file is read, never run

A shell has to know what your container offers before it runs a line of it. It fetches the registry
at boot, long before it loads any container. The registry has to say what the surface is called and
whether it takes a URL or props. For a Widget it also carries what that Widget expects.

So the build reads `src/mfe.ts` as syntax. A definition is a value rather than a component, and the
presentation fields are literals. A Widget's schemas are declarations the build can copy into a
contract module. Nothing in the file runs at build time, which is also why a computed value in any
of those places fails instead of being evaluated.
