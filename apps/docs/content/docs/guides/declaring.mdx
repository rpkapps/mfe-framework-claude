---
title: '2. Declaring it'
description: 'The definition file that tells the shell what you built, and how the build turns it into a container.'
---

A shell has to know what your container offers before it has run a line of it — what the surface
is called, whether it takes a URL or props, what a Widget expects — and it cannot render your code
to find out. So everything the framework knows about you comes from one file that is read and never
executed: `src/mfe.ts`. The build reads it statically, the host loads what it exports, and the mount
validates what you returned. This page is every option of `createApp` and `createWidget`, the
`package.json` block that goes with them, and every check you can trip, each with the message you
will see and the change that fixes it.

A <Term>definition</Term> is the plain, side-effect-free descriptor that `createApp` or
`createWidget` returns. It is a value, not a component: the build discovers it statically, and the
host loads it and mounts it. A <Term>container</Term> is the deployable unit that holds them — one
package, one build, one `src/mfe.ts`, at most one App and any number of Widgets. One live instance
of a definition on the page is a <Term>mount</Term>.

## The one file the framework reads

Discovery reads the container entry and nothing else: `src/mfe.ts`, or `src/mfe.tsx` when the entry
itself contains JSX, exactly one of the two. Every definition has to be exported from it. An
unexported one is never built into the container and can never be mounted; one declared in another
module is reported as a stray rather than picked up.

```ts title="src/mfe.ts"
import { createApp, type AppRouterOptions, type MfeStaticData } from '@company/mfe-react'
import { createRouter } from '@tanstack/react-router'

import { routeTree } from './routeTree.gen'

function makeRouter({ basePath, history, context }: AppRouterOptions) {
  return createRouter({
    routeTree,
    basepath: basePath,
    history,
    context: { ...context },
    defaultPreload: 'intent',
  })
}

declare module '@tanstack/react-router' {
  interface Register {
    router: ReturnType<typeof makeRouter>
  }

  // eslint-disable-next-line @typescript-eslint/no-empty-object-type -- an augmentation declares no field of its own.
  interface StaticDataRouteOption extends MfeStaticData {}
}

export default createApp({ id: 'operations', version: '2.1.0', router: makeRouter })
```

The `declare module` block is TanStack Router's own type registration: it gives `Link`, `navigate`
and `useParams` the route types from this App's generated tree, and it sits beside the factory
because `ReturnType<typeof makeRouter>` is what names that tree.

The second interface in that block types TanStack's `staticData` slot with `MfeStaticData`, the
four fields the framework reads off a route: `capability`, `label`, `icon` and `breadcrumb`. With it
in place a misspelt capability — `staticData: { capability: 'setings' }` — is a compile error
instead of a capability page the shell never opens. The scaffold's App writes it; an App made
before it gets the same by adding those two lines, as `examples/operations/src/mfe.ts` does.

## `createApp`

| Option        | Type                                       | Default     | What it is                                                                                                           |
| ------------- | ------------------------------------------ | ----------- | -------------------------------------------------------------------------------------------------------------------- |
| `id`          | `string`                                   | required    | The only public identity field, unique across every App and Widget. Also the storage prefix and the CSS scope value. |
| `version`     | `string`                                   | none        | Recorded in diagnostics, so a failure names which build was running.                                                 |
| `router`      | `(options: AppRouterOptions) => AnyRouter` | required    | Called once per mount, never once per module. Two mounts get two routers.                                            |
| `title`       | `string`                                   | none        | What a catalogue shows before anything is loaded. The host's presentation map may override it.                       |
| `description` | `string`                                   | none        | The same, in one sentence.                                                                                           |
| `tags`        | `readonly string[]`                        | none        | Free-form. A catalogue filters on them and never interprets them.                                                    |
| `icon`        | an imported identifier                     | none        | An icon component or an imported `.svg`. The build follows the import and publishes the shapes.                      |
| `breadcrumbs` | `false`                                    | contributes | Opts this App out of its own breadcrumb segment, not out of a nested App's.                                          |

### The router factory: `AppRouterOptions`

The factory receives three values, and all three have to reach `createRouter` unchanged.

| Field      | What it is                                                                                                                           | What you do with it                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `basePath` | The <Term>base path</Term>: the literal string form of the <Term>boundary</Term> the shell assigned, the URL prefix this mount owns. | Pass it as `createRouter({ basepath })`. It never appears again: every route, `Link` and `navigate` is relative to it.             |
| `history`  | The framework's boundary history, over the shell's navigation bridge.                                                                | Forward it. Never call `createBrowserHistory()`: it reassigns `window.history.pushState`, and two routers then fight over the URL. |
| `context`  | `{ mfe, queryClient }` — the mount's services and its Query client.                                                                  | Spread it: `context: { ...context, yourKey }`. Your own top-level keys survive every framework context update.                     |

`context.mfe` carries `user`, `groups`, `theme`, `telemetry`, `storage.local`, `storage.session` and
`signal`, and is what a route `loader` or `beforeLoad` reads. `user`, `groups` and `theme` are
snapshots: the framework rebuilds the namespace on every shell-state transition, so a value captured
across an `await` is stale. `RESERVED_CONTEXT_KEYS` is `['mfe', 'queryClient']`: add keys beside
them, never replace one, and never add a field inside `mfe`.

## `createWidget`

| Option                                 | Type                                     | Default  | What it is                                                                 |
| -------------------------------------- | ---------------------------------------- | -------- | -------------------------------------------------------------------------- |
| `id`                                   | `string`                                 | required | As above, and under the same character rule.                               |
| `version`                              | `string`                                 | none     | As above. Versions are per definition, not per container.                  |
| `inputs`                               | a Zod object schema                      | required | What the Widget takes. Validated at the provider boundary on every update. |
| `events`                               | `Record<string, z.ZodType>`              | required | What it emits, by name. Use `{}` for a Widget that emits nothing.          |
| `render`                               | `(props: { inputs, emit }) => ReactNode` | required | The component. Its props are typed from the two schemas.                   |
| `title`, `description`, `tags`, `icon` | as for `createApp`                       | none     | Read statically and published in the registry.                             |

`inputs` and `events` together are the Widget's <Term>contract</Term>: the single source of truth
for runtime validation and for the author-facing types, so the two cannot drift. The build
publishes them in the <Term>registry</Term> — the generated list the shell reads at boot — so a
catalogue can offer the Widget before the container has been fetched.

```ts title="examples/alert-panel/src/mfe.ts"
export const alertPanelContract = {
  inputs: z.object({
    alertId: z.string(),
    severity: z.enum(['info', 'warning', 'critical']).default('info'),
  }),
  events: {
    acknowledged: z.object({ alertId: z.string(), acknowledgedAt: z.string() }),
    dismissed: z.object({ alertId: z.string() }),
  },
}

export const alertPanel = createWidget({
  id: 'alert-panel',
  version: '1.4.0',
  title: 'Alert panel',
  description: 'Open alerts for one asset, acknowledged or dismissed in place.',
  tags: ['alerts', 'operations', 'safety'],
  icon: BellIcon,
  ...alertPanelContract,
  render: AlertPanel,
})
```

### Presentation is read, never run

`id`, `version`, `title` and `description` must be plain string literals, `tags` an array of string
literals, and `icon` an imported identifier. The build reads them out of the syntax without
executing your module, because the registry crosses an origin boundary and carries data rather than
components or markup. A computed title is a build error, and so is an icon the build cannot
resolve.

### The render function lives in its own module

React Refresh replaces a module in place only when it can prove that every export is a component.
One exported schema, constant or definition beside them makes the module unable to accept an
update; the update propagates to whatever imported it, and onward, until it reaches an entry, which
accepts nothing. The page then reloads and every piece of state on it is lost. `src/mfe.ts` exports
a definition and usually a contract, so it can never be a boundary, and the failure is silent — the
page reloads a little more often than it used to, and nothing says why.

```tsx title="examples/alert-panel/src/alert-panel.tsx"
/** Every export here is a component, so React Refresh replaces this module in place instead of
 * reloading the page (§18). */

export function AlertPanel({
  inputs,
  emit,
}: WidgetRenderProps<typeof alertPanelContract>): ReactNode {
```

Nothing enforces this. `pnpm hmr:probe <file>` is the tool that answers the question: it reports
`hot-updated in place` or `(the page reloaded)`. See
[decision 18](/docs/decisions#18-react-refresh-only-replaces-a-module-whose-every-export-is-a-component).

## Default export or named exports

Named exports are canonical. A default export is accepted only when it is the container's only
definition, which is why `examples/operations` can write `export default createApp(…)` and
`examples/insights`, with four Widgets, writes four `export const`s.

<Callout type="error" title="registry/invalid-descriptor, at build time">

``/home/you/orders/src/mfe.ts: 'order-row' failed to collect the definitions this container
exports: expected named exports when a container exports more than one definition, found a default
export alongside 2 other definition(s). This expectation is declared by static discovery. Give
the default export a name, for example `export const orderRow = createWidget({ … })`. Named exports
are canonical; a default export is only accepted when it is the container's only definition.``

**Fix.** Replace `export default createWidget({ … })` with `export const orderRow = createWidget({ … })`.

</Callout>

## The `mfe` block in `package.json`

Two fields, in every container:

```json title="examples/operations/package.json"
"mfe": {
  "port": 3001,
  "definitions": ["operations"]
}
```

`port` is the container's dev-server port, declared once and read back by its own
`rsbuild.config.ts`, by `pnpm dev`, and by the registry builder that writes the container's dev URL
into the shell registry. That is why it is fixed rather than a preference: `server.strictPort` is
set for you, because a container that fell back to another port would be invisible to the shell. A
missing one stops the registry build: `<name>: package.json declares no mfe.port, so its dev URL is
unknown.`

`definitions` is read only by `pnpm dev`, to print the developer-override snippet for each id.
Nothing validates it against what `src/mfe.ts` exports; keeping it accurate is a convention.

### Exporting a contract for consumers

The build generates a side-effect-free contract module per Widget. Publishing it is one `exports`
entry you add yourself:

```json title="examples/alert-panel/package.json"
"exports": {
  "./contracts": "./.mfe/widgets/alert-panel.contract.ts"
}
```

For a container with several Widgets, one pattern covers them all:
`"./contracts/*": "./.mfe/widgets/*.contract.ts"`. The generated module exports `widgetId`,
`inputs`, `events` and the types `Inputs` and `Events`, so a consumer writes:

```ts title="examples/operations/src/widgets.ts"
import { events, inputs } from '@example/alert-panel/contracts'

export const AlertPanel = lazyWidget('alert-panel', { contract: { inputs, events } })
```

For the build to copy a schema into that module it has to be able to read it without running
anything: declare it inline in `src/mfe.ts`, or as an exported top-level `const` in another module
of the same container, and never import it from the entry itself or from a bare package.

## Every check you can trip

The four router checks run at mount, the moment your factory returns. The identity and event checks
run when your entry module is evaluated, which in the browser is when the shell loads your
container. The rest are build errors, which name the file, the line and the column.

### The base path must be passed through

<Callout type="error" title="app/invalid-base-path, at mount">

`operations@2.1.0 failed to mount App: expected the supplied basePath "/operations" passed through
unchanged as createRouter({ basepath }), received no basepath on the router. Forward the basePath
your factory received: createRouter({ basepath: basePath, … }).`

</Callout>

```ts
// Before
return createRouter({ routeTree, history, context: { ...context } })

// After
return createRouter({
  routeTree,
  basepath: basePath,
  history,
  context: { ...context },
})
```

A hard-coded `basepath` produces the same failure with the string you wrote in place of `no
basepath on the router` — the case worth knowing about, because an App delegated inside another App
is mounted at a different boundary from the one it has on its own.

### The history must be the one you were given

<Callout type="error" title="app/invalid-router, at mount">

`operations@2.1.0 failed to mount App: expected the exact history instance the framework supplied,
received a different history object. Do not create, wrap, replace or mutate the history; forward
the one your factory received.`

</Callout>

```ts
// Before
return createRouter({
  routeTree,
  basepath: basePath,
  history: createBrowserHistory(),
})

// After
return createRouter({ routeTree, basepath: basePath, history })
```

### The context is spread, not replaced

<Callout type="error" title="app/invalid-router, at mount">

`operations@2.1.0 failed to mount App: expected the supplied context.mfe namespace, spread into the
router context unchanged, received no mfe key. Spread the supplied context: add your own top-level
keys freely, but do not replace mfe or add fields inside it.`

</Callout>

```ts
// Before
return createRouter({
  routeTree,
  basepath: basePath,
  history,
  context: { session },
})

// After
return createRouter({
  routeTree,
  basepath: basePath,
  history,
  context: { ...context, session },
})
```

Replacing `queryClient` instead reports `expected the supplied top-level queryClient, forwarded
unchanged, received a different Query client. Spread the supplied context rather than constructing
your own Query client; the mount owns one.` A child route that returns its own `mfe` or
`queryClient` from `beforeLoad` is a development-only diagnostic rather than a throw, and it names
the route: `Rename the key you return from beforeLoad in /assets.`

### `version` is not validated

Nothing checks that `version` is semantic, or that it matches the package version. It is a plain
string literal, read at build time, carried into the registry, and stamped onto every failure the
mount reports — the `@2.1.0` in the router messages above is it. A definition declared without one
mounts all the same, and its failures name the id alone. Keeping it in step with the package
version is a convention with no check behind it, and worth keeping: it is what tells you which
build produced the failure you are reading.
