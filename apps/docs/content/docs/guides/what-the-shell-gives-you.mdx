title: '4. What the shell gives you'
description: 'The hooks a mounted container calls to read the page around it: identity, theme, boundary, breadcrumbs, commands, telemetry and storage.'
---

The <Term>shell</Term> is the application that owns the document, the header, the theme and the
session, and it mounts your container into itself. One import gives you what the shell holds: who
is signed in, the theme, your URL boundary, breadcrumbs, commands, telemetry and storage. Each
service belongs to one <Term>mount</Term>, a single live instance of your definition on the page.

## The hooks, at a glance

```ts
import { useBasePath, useTelemetry, useTheme, useUser } from '@company/mfe-react'
```

| Hook                                    | What it gives you                                              | Where it works      |
| --------------------------------------- | -------------------------------------------------------------- | ------------------- |
| `useUser()`                             | the signed-in person, or `null` until the shell has a session  | mount or host page  |
| `useGroups()`                           | the group set, as strings                                      | mount or host page  |
| `useTheme()`                            | `'light'` or `'dark'`                                          | mount or host page  |
| `useCommand(registration)`              | nothing — it publishes an action into the palette              | mount or host page  |
| `useBreadcrumbs(items)`                 | nothing — it replaces your App's part of the trail             | mount or host page  |
| `useStoredState(name, schema, options)` | `[value, setValue]`, validated and namespaced                  | mount or host page  |
| `useBasePath()`                         | the URL prefix the shell assigned this mount                   | inside a mount only |
| `useTelemetry()`                        | `event`, `debug`, `info`, `warn`, `error`, `measure`, `tracer` | inside a mount only |
| `useMfeSignal()`                        | the `AbortSignal` that fires when the mount goes away          | inside a mount only |
| `useMfeStorage(area?)`                  | the imperative handle for stored records                       | inside a mount only |
| `useNavigationBlock(shouldBlock)`       | the pending navigation, plus `proceed` and `stay`              | inside a mount only |

A hook marked _mount or host page_ also works above your container, where it resolves to the page's
reserved [`@host` scope](/docs/glossary). `@company/mfe-react` is the only framework package you
import, and lint
blocks the rest
([5. What you must not do](/docs/guides/what-you-must-not-do#do-not-import-past-a-packages-entry-point)).

## Who is signed in: `useUser`, `useGroups`, `useTheme`

```tsx title="examples/lab/src/routes/shell-state.tsx"
const user = useUser()
const groups = useGroups()
const theme = useTheme()
```

Each hook subscribes to one field, so a theme change never re-renders a component that reads only
the user. Each takes an optional selector, `useUser(u => u?.name ?? 'Nobody')`, cached per
snapshot, so an inline one does not loop. `useUser()` returns `null` until the shell publishes a
session, which is a state to render. The user and the groups are data for rendering, and **not an
authorization API**: the server decides what a user may do.

## Your URL boundary: `useBasePath`

```ts
const basePath = useBasePath()
```

Call it when an external system needs an absolute path into your App, such as an email or a work
order. You do not need it for routing, because `basepath` already makes every `Link` and `navigate`
relative. An App gets `/operations`, or `/operations/reports` when another App delegates to it. A
Widget owns no URL and gets `''`.

## Breadcrumbs: `useBreadcrumbs`

```ts title="examples/lab/src/routes/breadcrumbs.tsx"
const FLOW = [
  { key: 'wizard', label: 'New study' },
  { key: 'step-2', label: 'Step 2 · Inputs' },
]

// Replaces only this App's own portion of the trail, and clears on unmount and on navigation.
useBreadcrumbs(override ? FLOW : [])
```

Call `useBreadcrumbs` for a flow the URL does not describe. Without it, your App's portion of the
trail comes from its router matches. The framework takes a route's `staticData.breadcrumb`, else
its `head` title, else the humanized last path segment.

An empty array means _no override_ rather than an empty trail, which makes that conditional safe.
The identifier field is `key`, because `id` stays reserved for definition identity. An App that
should contribute nothing sets `breadcrumbs: false` on its definition.

<Callout type="warning" title="Two overrides at once">

In development, a second override warns: `expected at most one active breadcrumb override per App
mount, received a second override while another is still mounted.`

**Fix.** Keep one `useBreadcrumbs` call live per App mount.

</Callout>

## Commands: `useCommand`

```ts title="examples/lab/src/routes/commands.tsx"
useCommand({
  name: 'run-simulation',
  label: 'Run the simulation',
  canExecute: () => (armed ? allow() : deny('Arm the simulation first.')),
  execute: () => {
    record('Ran the simulation')
  },
})
```

A command is an action your mount publishes into the shell's palette, opened with <Kbd>⌘K</Kbd> or <Kbd>Ctrl</Kbd>+<Kbd>K</Kbd>.
Registration follows component lifetime. Put the call in a layout route to keep the command for as
long as the App is mounted. Put it in a page route to scope it to that page.

`placements` defaults to `['command-palette']`, the only standardized placement today.

A denied command stays in the palette, greyed out, with the reason you gave. `canExecute` must be a
pure synchronous read of reactive state. One that throws counts as a denial, and the user sees
`This command is unavailable because its availability check failed.`

<Callout type="error" title="command/duplicate-name">

`lab failed to register command: expected a name of letters, digits and hyphens starting with a
letter (for example "refresh"), received "run simulation". Rename the command. The runtime
qualifies it internally as <definitionId>:<name>, which needs an unambiguous local name.`

**Fix.** Rename it to `run-simulation`. Two registrations of one name inside a mount are both
rejected, so neither silently wins.

</Callout>

## Block a navigation when work is unsaved

```ts title="examples/lab/src/routes/unsaved.tsx"
const blocker = useBlocker({
  shouldBlockFn: () => isDirty,
  // A reload is not a navigation and no page may draw its own UI for one.
  enableBeforeUnload: () => isDirty,
  withResolver: true,
})
```

Inside an App, use TanStack's own `useBlocker`. The framework widens it to cover the navigations
your router never sees: the application finder, a breadcrumb, the palette, the back button.

A Widget has no router of its own, so it uses `useNavigationBlock` instead. That hook hands back the
pending intent, so you render your own confirmation rather than `window.confirm`.

```tsx
const { pending, proceed, stay } = useNavigationBlock(isDirty)

if (pending) return <ConfirmDialog onConfirm={proceed} onCancel={stay} />
```

## Telemetry: `useTelemetry`

```tsx title="examples/lab/src/routes/telemetry.tsx"
telemetry.tracer.startActiveSpan('lab.compute', span => {
  span.setAttribute('lab.rows', 128)
  span.setStatus({ code: SpanStatusCode.OK })
  span.end()
})
```

`telemetry` gives you `event`, `debug`, `info`, `warn`, `error`, `measure(name, value, { unit })`
and `tracer`. Every record carries the definition id, kind, version, build hash, mount token and
trace id, so you write no attribution. `SpanKind` and `SpanStatusCode` come from
`@company/mfe-react`, and importing an OpenTelemetry package directly is a lint error.

| Attributes                                     | The framework's limit                   |
| ---------------------------------------------- | --------------------------------------- |
| Small scalars only: strings, numbers, booleans | never a body, a credential or a raw URL |
| Number of attributes on one record             | 64, and the rest are dropped            |
| Length of a string value                       | 1024 characters, then truncated         |
| Length of an attribute name                    | 256 characters, then truncated          |

Trace parentage is a synchronous slot, so a span started **after an `await`** inside a
`startActiveSpan` callback becomes a root with a fresh trace id. Start child spans synchronously,
or use `startSpan` and correlate by an attribute
([decision 4](/docs/decisions#4-browser-async-context-does-not-propagate-across-await-and-we-do-not-pretend-it-does)).

<Callout type="error" title="dispose/failure">

A span left open at disposal is reported in development: `lab@1.0.0 failed to dispose the mount
telemetry: expected every span started by the mount to be ended by its author, received 1 span(s)
still open: lab.compute. End each span in a finally block; they were closed as cancelled.`

**Fix.** End the span in a `finally` block, so a throw inside the callback still closes it.

</Callout>

## Cancel background work: `useMfeSignal`

```ts
target.addEventListener(type, handler, { signal: useMfeSignal() })
```

`useMfeSignal()` returns the mount's disposal signal, for work started outside a route loader. It
aborts once, when the mount goes away. Inside a loader, keep using the loader's own `signal`, which
cancels with the navigation.

## Storage: `useStoredState` and `useMfeStorage`

```ts title="examples/lab/src/routes/storage.tsx"
const [visits, setVisits] = useStoredState('visits', visitsSchema, {
  defaultValue: 0,
  retention: 'user',
  storage: 'session',
})
```

Your container never touches `localStorage`. You declare a key with a schema and get a subscribed
value and a stable setter, namespaced under this definition's id. `retention` decides who may read
the value back. `'user'`, the default, is limited to the signed-in person and cleared when the
identity or the group set changes, and `'browser'` is never cleared.

`useMfeStorage()` is the imperative handle for reads that should not subscribe, and [7.
Storage](/docs/guides/storage) has versions, migrations and every error.

## Icons: `DefinitionIcon`

```ts title="src/mfe.ts"
import { HardHatIcon } from 'lucide-react'

export default createApp({ id: 'operations', version: '2.1.0', icon: HardHatIcon, router })
```

You never call `DefinitionIcon` yourself. You pass an imported identifier as `icon`, the build
follows the import and publishes the shapes in the registry, and the shell draws them. It draws
from data, against a tag allowlist, because the record arrived from another origin.

## Navigate between Apps

| Where to                                  | How                                                                                                        |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Inside your own boundary                  | `Link` and `navigate` from your router. Write `/settings`, never `/operations/settings`.                   |
| Into an App you delegate at a splat route | A link to your own route: `<Link to="/reports/$" params={{ _splat: '' }}>`. An empty splat lands on index. |
| To an App at another boundary             | Nothing in the framework. The shell owns cross-boundary navigation.                                        |

A document-level link (`<a href="/reports">`) does reach another App, at the cost of a full page
load. The shell boots again and every other mount on the page is discarded. When moving between
two Apps is routine, send the user through the shell's application finder or command palette.

Do not reach for the URL yourself. Assigning to `history.pushState` hijacks navigation for the
whole page and is a lint error
([5. What you must not do](/docs/guides/what-you-must-not-do#do-not-create-your-own-router-or-history)). A
Widget emits a declared event and lets the App around it navigate.

## What the shell does not give you

The shell does not give you any of these.

- **No component library.** The design system is a dependency you and the shell both take.
- **No cross-container messaging.** There is no bus and no shared store.
- **No session of your own.** Your container borrows the page's session through `#mfe/fetch`.
- **No cross-boundary navigation.** Moving a user to another App is the shell's job.
- **No mount deadline.** A load suspends until it settles or fails, and a retry is a person's click.

## Errors you will see

Two errors come from calling a hook in the wrong place. `useBasePath`, `useTelemetry`,
`useMfeSignal`, `useMfeStorage` and `useNavigationBlock` need a mount. Called anywhere else, they
throw:

<Callout type="error" title="mount/failure, outside a mount">

`<unmounted> failed to call useTelemetry: expected a component rendered inside an App or Widget
mount, received a component rendered outside any mount. Move the useTelemetry call into a component
the App or Widget renders.`

**Fix.** Move the call inside your definition's tree: a route component, or anything it renders. A
module-level helper runs before the mount exists.

</Callout>

The six hooks that also work on the host page still need the runtime above them:

<Callout type="error" title="mount/failure, no runtime">

`<no-runtime> failed to render useUser(): expected an MfeProvider above this component, or an
enclosing App or Widget mount, received neither. Wrap the shell in <MfeProvider runtime={runtime}>
once at boot.`

**Fix.** In a shell, wrap the application in `MfeProvider` once at boot. Inside a container, this
message usually means a second copy of `@company/mfe-react` on the page. Every hook in your mount
then fails as though it were rendered outside one.

</Callout>
