title: '5. What you must not do'
description: 'The moves that break the other containers on a shared page, what enforces each one, and the fix.'
---

Your <Term>container</Term> loads into a document the shell already owns, beside other people's
code. Everything global on that page is shared: the URL, the document head, the style cascade and
one flat Web Storage key space. This page lists the moves that break it, each with the message you
will see and the repair.

## The rules, at a glance

Every rule on this page is in this table.

| Rule                                                                                               | Enforced by                                                         | Fix                                        |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------ |
| No `createBrowserHistory`, no patching `window.history`                                            | lint `mfe/no-global-patching`; mount `app/invalid-router`           | Forward the supplied `history`             |
| Do not write to `window.location`                                                                  | convention                                                          | Navigate with your own router              |
| Pass `basePath` through unchanged                                                                  | mount `app/invalid-base-path`                                       | `createRouter({ basepath: basePath })`     |
| Spread the router context; never replace `mfe` or `queryClient`                                    | mount `app/invalid-router`; dev diagnostic for child routes         | `context: { ...context, mine }`            |
| Routes are relative to your boundary                                                               | convention                                                          | Write `/settings`                          |
| A Widget does not touch the URL, `document.title` or `document.head`                               | lint `mfe/no-widget-global-effects`, inside declared `widgetScopes` | Declare an event and `emit` it             |
| No raw `localStorage` / `sessionStorage`                                                           | lint `mfe/no-raw-storage`                                           | `useStoredState` / `useMfeStorage`         |
| No document-root selectors, `@property` or `@font-face`                                            | build throws; convention                                            | Style your own subtree                     |
| No stylesheet entry, no stock Tailwind colours                                                     | convention                                                          | Semantic tokens or palette steps           |
| Export only components beside components                                                           | convention                                                          | `pnpm hmr:probe`; render in its own module |
| No timestamps, counters or random ids in generated output; never edit it                           | convention                                                          | Regenerate                                 |
| `lazyWidget`, `createApp`, `createWidget` at module scope                                          | lint `mfe/stable-definitions`                                       | Hoist the call; or `DynamicWidget`         |
| Id, event, input and presentation format rules                                                     | build, mount, registry                                              | Rename; write literals                     |
| Inputs and payloads are JSON-serializable                                                          | mount                                                               | Send data, subscribe to events             |
| No deep imports; no `mfe-core`, `mfe-host`, `react-dom/client`, `@module-federation/*`, OTel, Faro | lint `no-restricted-imports`                                        | Import from `@company/mfe-react`           |
| Container-aware asset references                                                                   | build diagnostic                                                    | `new URL(…, import.meta.url)`              |
| No `console.log`                                                                                   | lint `no-console`                                                   | `useTelemetry()`                           |
| No async context across `await` in tracing                                                         | convention                                                          | Create child spans synchronously           |

Five mechanisms appear in that column.

- **Lint** — a rule in the `author` ESLint preset. You see it in the editor and in `pnpm lint`.
- **Build** — `pluginMfe()` stops the build, with the file, the line and the repair.
- **Mount** — a structured `MfeError` at run time, which the consumer sees as a failure box.
- **Registry** — the shell sets your entry aside. Your container never appears, and every other
  container still loads.
- **Convention** — nothing checks it.

`pnpm boundaries` guards the framework's own package graph, not `examples/`. Nothing you write is
covered by it.

## Do not create your own router or history

```ts title="src/mfe.ts"
import { createApp, type AppRouterOptions } from '@company/mfe-react'
import { createRouter } from '@tanstack/react-router'

import { routeTree } from './routeTree.gen'

function makeRouter({ basePath, history, context }: AppRouterOptions) {
  return createRouter({
    routeTree,
    basepath: basePath,
    history,
    context: { ...context },
    defaultPreload: 'intent',
  })
}

export default createApp({ id: 'lab', version: '1.0.0', router: makeRouter })
```

There is one address bar and one history stack, and the shell owns both. Your factory runs once per
mount and receives the boundary, its history, the `mfe` namespace and the Query client. Forward all
four. TanStack's `createBrowserHistory()` reassigns `window.history.pushState`, so two routers on
the page start correcting each other's URL.

<Callout type="error" title="mfe/no-global-patching">
  Patching `window.history.pushState` hijacks navigation for the whole page, so the host router and
  the other MFEs learn about a navigation only by accident. Navigate through the framework instead:
  `navigate` or `Link` from your App's boundary router, which already resolve under the MFE base
  path, or the host `BoundaryNavigator` (@company/mfe-host) in the shell.

**Fix.** Forward the `history` your factory received, and navigate with your own router.

</Callout>

The rule reports assignment, `delete` and `defineProperty` on `globalThis.fetch`,
`history.pushState`, `history.replaceState`, `window.history`, and `addEventListener` or
`removeEventListener` on `window`, `document` or `globalThis`. Reading or calling a global is not
patching. No rule covers `window.location`, and writing to it reloads the page out from under every
other container, so treat that as forbidden.

<Callout type="error" title="app/invalid-base-path">

operations@2.1.0 failed to mount App: expected the supplied basePath "/operations" passed through
unchanged as createRouter(\{ basepath \}), received "/orders". Forward the basePath your factory
received: createRouter(\{ basepath: basePath, … \}).

**Fix.** Pass the `basePath` argument straight into `createRouter({ basepath })`.

</Callout>

Three more rules follow from that factory.

- **Spread the context. Never replace `mfe` or `queryClient`.** `RESERVED_CONTEXT_KEYS` is
  `['mfe', 'queryClient']`, and your own top-level keys survive every framework context update.
  Enforced at mount (`app/invalid-router`). A child route that returns its own `mfe` from
  `beforeLoad` is reported in development, with the repair
  `Rename the key you return from beforeLoad in /orders/$id.`
- **Write your routes relative to your boundary.** Use `/settings`, not `/operations/settings`.
  `basepath` resolves them under whatever boundary the shell assigned. Nothing checks this, because
  the shell owns `/`, `/$appId` and `/$appId/$` and nothing else, and a definition id may not
  contain a `/`.
- **A Widget does not drive the URL or the document head.** Several Widgets can be on screen at
  once. The last one to render would win, and the tab title would flicker. The rule has one message
  per access, and each names the event to declare instead.

<Callout type="error" title="mfe/no-widget-global-effects">

A Widget does not drive the URL: `history.pushState` navigates the whole page, and the host router,
the owning App and every sibling MFE learn about it only by accident. Declare a navigation event in
this Widget's `events` contract and call `emit('navigate', { to })` from its render props; the
owning App receives it as `onNavigate` and navigates with its boundary router, or the shell with the
host `BoundaryNavigator`.

`document.title` is shell-owned: several Widgets can be mounted at once, so the last one to render
would win and the tab title would flicker. Declare a title event in this Widget's `events` contract
and call `emit('title', { text })` from its render props; the owning App receives it as `onTitle`
and sets what it owns.

Document head metadata (favicon, `<meta>`, `<title>`) belongs to the shell; a Widget that reaches
for `document.head` changes the page for every other MFE and leaves the change behind on unmount.
Declare an event for the value in this Widget's `events` contract and `emit` it from the render
props; the owning App receives it as an `onX` prop and applies it to what it owns, which is also
what reverts it.

**Fix.** Declare the event in your `events` contract and `emit` it from the render props
([2. Declaring it](/docs/guides/declaring#declare-a-widget)). The App receives it as `onNavigate`,
`onTitle` or another `onX` prop, and acts on it.

</Callout>

The rule covers `history.pushState`, `replaceState`, `back`, `forward` and `go`, assignment to
`document.title`, and mutation of `document.head`. It is **inert until the repository declares
`widgetScopes`**, which here are `examples/alert-panel/src/**` and `examples/insights/src/**`.
Declare your own Widget scopes, or the rule is silently off for your code. Reading is not mutating,
so `const current = document.title` is fine.

## Do not read another user's state

Put every stored value behind `useStoredState` or `useMfeStorage`. One browser profile can hold
several people over a day, and every container in the origin writes into one flat key space.

<Callout type="error" title="mfe/no-raw-storage">
  `localStorage` bypasses the MFE storage boundary: the key is not namespaced, so another MFE in
  this origin can read or overwrite it, the shell cannot clear it on sign-out, and a quota failure
  escapes as an unhandled exception. Use `useStoredState()` for component state or `useMfeStorage()`
  for imperative access, both from @company/mfe-react. The storage adapter and a documented shell
  override bootstrap opt out through this rule's `allowedScopes` option.

**Fix.** Use `useStoredState(name, schema, { defaultValue })` for rendered state, and
`useMfeStorage()` for imperative access. Both namespace the key under your definition id
([7. Storage](/docs/guides/storage)).

</Callout>

The rule is off in test files only, because a storage test has to reach the storage it verifies.

## Do not ship unscoped styles

Write your styles as utilities and design-system components in TSX, and ship no stylesheet of your
own. The build compiles the CSS for your classes and wraps it in
`@scope ([data-mfe-scope="alert-panel"]) to ([data-mfe-scope])`. The shell owns the document half:
preflight, fonts, `@property` and the theme variables, all of which inherit into you.

| Rule                                                                        | Why                                                                                                 | Enforced by                                    | Fix                                                                                            |
| --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| No `:root`, `:host`, `html` or `body` selector except as a leading compound | The scope root is not the document root, so the selector matches nothing                            | build — the scope plugin throws                | Style your own subtree                                                                         |
| No `@property` and no `@font-face` in a container                           | Both register page-wide; two containers defining the same one get whichever the browser parsed last | convention                                     | Ask the shell to define it                                                                     |
| No stylesheet entry and no `postcss.config.mjs`                             | The build produces `.mfe/styles.css` from your TSX; a second entry ships an unscoped sheet          | convention — none of the five examples has one | Write utilities and design-system components in TSX                                            |
| No stock Tailwind colour classes (`bg-red-500`)                             | The palette is the design system's; a stock colour generates no CSS at all                          | nothing in a scaffolded container              | Use a semantic token (`bg-primary`, `text-muted-foreground`) or a palette step (`bg-blue-120`) |

`@keyframes` is safe, because the build renames the ones your sheet defines.
[8. Styling](/docs/guides/styling) has the whole picture.

## Do not break hot updates

Hot updates break unless the render function sits in a module whose every export is a component.
React Refresh replaces a module in place only when it can prove **every** export is a component. One
exported hook, constant, schema or factory beside them makes the module unable to accept an update.

The update then travels to whatever imported it, until it reaches an entry that accepts nothing. The
page reloads, every piece of state on it is lost, and nothing reports why.

| Module                | What it exports                          | What an edit to it does |
| --------------------- | ---------------------------------------- | ----------------------- |
| `src/mfe.ts`          | the definition, and usually its contract | reloads the page        |
| `src/alert-panel.tsx` | the render function, and nothing else    | hot-updates in place    |

```ts title="src/mfe.ts"
export const alertPanelContract = { inputs, events }
export const alertPanel = createWidget({
  id: 'alert-panel',
  ...alertPanelContract,
  render: AlertPanel,
})
```

This is convention: no `react-refresh/only-export-components` rule runs here. The tool that answers
the question is `pnpm hmr:probe <file>`, which reports `hot-updated in place` or
`(the page reloaded)`.

**Generated output must be a pure function of its sources.** The build regenerates before every
compilation, and your container imports what it generates. A timestamp, a counter or a random id in
a generated module makes every compilation a source change, so the container rebuilds forever. You
see the same symptom: hot updates that fail to fetch, and a page that reloads.

That rule binds you only if you write your own generator. What binds every author is the banner on
each generated file: **never edit generated output**.

## Do not call `lazyWidget` during render

```ts title="src/widgets.ts"
/** Built at module scope because one built during render remounts the Widget every pass. */
import { lazyWidget } from '@company/mfe-react'

import { events, inputs } from '@example/alert-panel/contracts'

export const AlertPanel = lazyWidget('alert-panel', { contract: { inputs, events } })
```

`lazyWidget(id)` returns a component, and a component's identity is what React uses to decide
whether it is looking at the same element. One built during render is a new identity every pass.

<Callout type="error" title="mfe/stable-definitions">
  `lazyWidget` (`lazyWidget` from @company/mfe-react) has to be called once, at module scope.
  Calling it in the body of `Panel` mints a new definition identity on every call, so the host
  treats it as a different MFE: it unmounts the running instance, throws away its state and
  refetches its data. Move the `lazyWidget(...)` call to the top level of this module and reference
  the resulting definition here.

**Fix.** Move the call to the top level of the module, as above.

</Callout>

The rule guards `createApp`, `createWidget` and `lazyWidget`. It reports a call inside a function
body, an arrow function, a class static block or a class field initialiser. A host that learns
which Widgets exist only from the registry cannot obey it. That host uses `DynamicWidget`, which
takes the id as a prop and builds nothing during render.

## Do not hand-write a contract

Declare the contract and every presentation field as literals in `src/mfe.ts`. The build reads your
definition **without running it**, so a host can render a catalogue entry before anything is
fetched. That is only possible if the declarations are literals.

| Rule                                                                                                     | Enforced by                                                                             | Fix                                                                                                      |
| -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| A definition id is lower-case letters, digits and single hyphens (for example `alert-panel`)             | the scaffold, build, mount (`registry/invalid-descriptor`) and registry (`quarantined`) | Rename. The id is also a storage prefix and a CSS scope value                                            |
| Two definitions may not share an id                                                                      | build inside one container; **both** entries set aside across the registry              | Rename one                                                                                               |
| An event name is lower camel case                                                                        | build and mount                                                                         | Consumers subscribe as `onYourEvent`, so the name has to survive that mapping                            |
| An input may not be named `key`, `ref`, `fallback` or `onSomething`                                      | build and mount                                                                         | Rename the input; those names belong to the host                                                         |
| Inputs and event payloads must be JSON-serializable                                                      | mount, before schema validation                                                         | Send data. A consumer that needs a callback subscribes to an event instead                               |
| A Widget declares both `inputs` and `events`                                                             | build                                                                                   | `inputs: z.object({})` when it takes none                                                                |
| The schema must be readable without running the module                                                   | build                                                                                   | Declare it inline in `src/mfe.ts`, or as an exported top-level const in another module of this container |
| `title`, `description`, `version`, `tags` and `id` are inline literals; `icon` is an imported identifier | build                                                                                   | They are read at build time and published in the registry, so they cannot be computed                    |
| A container exports at most one App, and every definition is exported from the entry                     | build                                                                                   | Split them into separate containers; add `export`                                                        |

A consumer contract never calls `.strict()`, so a Widget can add a field without breaking one. That
one is convention, stated in the type.

## Do not import past a package's entry point

Import from `@company/mfe-react`, and from nothing else in the framework.

<Callout type="error" title="@typescript-eslint/no-restricted-imports">
  Public API boundary: @company/mfe-core is a framework-internal contract package whose shape
  changes with the framework, not with its public API. Everything an MFE author needs, types
  included, is re-exported from @company/mfe-react.

**Fix.** Import from `@company/mfe-react`. If what you need is not exported there, that is a
framework bug worth filing.

</Callout>

Also blocked for authors:

- `@company/mfe-host` — "An MFE that imports it can mount itself outside the host lifecycle and
  will leak on unmount".
- `react-dom/client` — "the host owns the React root".
- `single-spa` and `@module-federation/*`.
- `@opentelemetry/*` and `@grafana/faro*`, type imports included.

Zustand, Redux, MobX, Jotai and `@tanstack/store` are allowed, because an MFE owns its own state.

**Do not reference an asset with a bare relative string.** `'./icons/gear.svg'` in a string literal
resolves against the shell document, not against your container. It works in development, where the
two share a host, and breaks the first time they do not. The build reports it with the repair:
import the asset, or write `new URL('./icons/gear.svg', import.meta.url).href`.

## Do not hide failures from diagnostics

Three habits hide a failure from the [diagnostics hub](/docs/glossary).

**Do not use `console.log`.** `no-console` is `['error', { allow: ['warn', 'error'] }]` in both
presets. In a container's `src/`, that makes `log`, `info`, `debug` and `table` errors. Use
`telemetry.info(…)` and `telemetry.error(err)` from `useTelemetry()`, which carry your definition
id, version and build hash.

**Do not rely on async context across an `await` for tracing**. A span created after an `await`
inside `startActiveSpan` becomes a root with a fresh trace id. You get no parent rather than a
wrong one, because a wrong parent corrupts a production trace tree silently. Start child spans
synchronously, or use `startSpan` and correlate by an explicit attribute.

**When you must suppress a rule**, the suppression names one rule, sits on the line it applies to,
and carries a specific reason. "Noisy" is not a reason. A check is never disabled across a package
to accommodate one exception.

These rules defend six boundaries: URL, styles, storage, network, errors and shared singletons. The
design map draws them in the
[`isolation-boundaries` diagram](/docs/design#the-six-isolation-boundaries).
