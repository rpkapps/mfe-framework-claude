---
title: '5. What you must not do'
description: 'The page is shared, so these are the moves that break the containers around you.'
---

Your App or Widget does not get a page to itself. It is loaded into a document the shell already
owns, beside other people's code, and everything global on that page — the URL, the document head,
the style cascade, one flat Web Storage key space — is shared with every other piece on it. A
mistake that is invisible when you run your container alone is what breaks somebody else's product
surface at three in the afternoon.

This page is the list of those mistakes, grouped by the failure each one causes. A <Term>micro-frontend</Term>
is a piece of a page that is built, versioned and deployed on its own and loaded into a page it does
not own at run time; a <Term>container</Term> is one such deployable, with its own build and its own
`src/mfe.ts`; the <Term>shell</Term> is the one application on the page that is not listed in the
registry and that mounts the others into itself. An <Term>App</Term> owns a stretch of URL and routes
below it; a <Term>Widget</Term> owns no URL and takes props. A <Term>mount</Term> is one live
instance of a definition on the page, with its own abort signal, Query client, storage surfaces and
overlay root.

## How each rule is enforced

Several of these are checked, and several are convention. Assuming the wrong one is how a rule gets
broken, so each rule below names its mechanism.

| Mechanism  | What it is                                                                                | What you see                                                   |
| ---------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| lint       | a rule in the `author` ESLint preset (`packages/eslint-plugin-mfe/src/configs/author.ts`) | an error in the editor and in `pnpm lint`                      |
| build      | `pluginMfe()` — a thrown build error or a compilation diagnostic                          | the build stops, with the file, line and repair                |
| mount      | a structured `MfeError` thrown or reported at run time                                    | the consumer's failure box, and a diagnostic                   |
| registry   | the shell's normalizer sets the entry aside                                               | your container never appears; the rest of the page still loads |
| convention | nothing checks it                                                                         | nothing, until it bites                                        |

`pnpm boundaries` guards the framework's own package graph — its manifests and its imports — not
`examples/`. Nothing you write is covered by it.

## Two routers fighting over the URL

There is one address bar and one history stack. The shell owns them, and hands each App a <Term>boundary</Term>
— the stretch of URL assigned to that mount — together with a history object built over the shell's
navigation bridge.

**Do not call `createBrowserHistory`, and do not assign to `window.history` or its methods.**
TanStack's `createBrowserHistory()` reassigns `window.history.pushState` and `replaceState`, so
anything else wrapping them breaks and two routers on the page start correcting each other's URL.

<Callout type="error" title="mfe/no-global-patching">
  Patching `window.history.pushState` hijacks navigation for the whole page, so the host router and
  the other MFEs learn about a navigation only by accident. Navigate through the framework instead:
  `navigate` or `Link` from your App's boundary router, which already resolve under the MFE base
  path, or the host `BoundaryNavigator` (@company/mfe-host) in the shell.

**Fix.** Forward the `history` your factory received into `createRouter`, and navigate with
`Link` and `navigate` from your own router.

</Callout>

Reading a global is not patching, and calling one is not patching: the rule reports assignment,
`delete` and `defineProperty` on `globalThis.fetch`, `history.pushState`, `history.replaceState`,
`window.history`, and `addEventListener`/`removeEventListener` on `window`, `document` or
`globalThis`. `window.location` is covered by no rule at all — writing to it reloads the whole page
out from under every other container, so treat it as forbidden by convention.

**Do not ignore `basePath`, and do not substitute the history, the `mfe` namespace or the Query
client.** Your router factory runs once per mount and receives all four. The framework checks the
router it gets back, so the failure names the one-line repair instead of rendering your App at the
wrong boundary and surfacing an hour later.

<Callout type="error" title="app/invalid-base-path, at mount">
  operations@2.1.0 failed to mount App: expected the supplied basePath "/operations" passed through
  unchanged as createRouter(\{ basepath \}), received "/orders". Forward the basePath your factory
  received: createRouter(\{ basepath: basePath, … \}).
</Callout>

```ts title="src/mfe.ts"
import { createApp, type AppRouterOptions } from '@company/mfe-react'
import { createRouter } from '@tanstack/react-router'

import { routeTree } from './routeTree.gen'

function makeRouter({ basePath, history, context }: AppRouterOptions) {
  return createRouter({
    routeTree,
    basepath: basePath,
    history,
    context: { ...context },
    defaultPreload: 'intent',
  })
}

export default createApp({ id: 'lab', version: '1.0.0', router: makeRouter })
```

Three more rules follow from that factory.

- **Spread the context; never replace `mfe` or `queryClient`.** `RESERVED_CONTEXT_KEYS` is
  `['mfe', 'queryClient']`. Your own top-level keys survive every framework context update; a child
  route returning its own `mfe` from `beforeLoad` is reported in development with the repair
  `Rename the key you return from beforeLoad in /orders/$id.` Enforced at mount
  (`app/invalid-router`).
- **Write your routes relative to your boundary.** `/settings`, not `/operations/settings`:
  `basepath` resolves them under whatever boundary the shell assigned. Convention; nothing checks
  it, because there is nothing to check — the shell claims `/`, `/$appId` and `/$appId/$` and
  nothing else, and a definition id may not contain a `/`.
- **A Widget does not drive the URL or the document head.** Several Widgets can be on screen at
  once, so the last one to render would win and the tab title would flicker.

<Callout type="error" title="mfe/no-widget-global-effects">
  `document.title` is shell-owned: several Widgets can be mounted at once, so the last one to render
  would win and the tab title would flicker. Publish the title through the Widget's declared outputs
  (`ctx.emit("titleChange", ...)`) and let the owning App apply it with the host document-metadata
  API.

**Two things in that message are not real API.** A Widget's render props are `{ inputs, emit }` —
there is no `ctx` — and there is no host document-metadata API in this repository. **Fix.**
Declare the event in your contract and call `emit('titleChange', { title })`; the consuming App
receives it as `onTitleChange` and acts on it with its own router.

</Callout>

The rule covers `history.pushState`/`replaceState`/`back`/`forward`/`go`, assignment to
`document.title`, and mutation of `document.head`. It is **inert until the repository declares
`widgetScopes`**, and this repository declares only `examples/alert-panel/src/**`. Declare your own
Widget scopes, or the rule is silently off for your code. Reading is not mutating: `const current =
document.title` is fine.

## One user reading another user's state

One browser profile can hold several people over a day, and every container in the origin writes
into one flat Web Storage key space.

<Callout type="error" title="mfe/no-raw-storage">
  `localStorage` bypasses the MFE storage boundary: the key is not namespaced, so another MFE in
  this origin can read or overwrite it, the shell cannot clear it on sign-out, and a quota failure
  escapes as an unhandled exception. Use `useStoredState()` for component state or `useMfeStorage()`
  for imperative access, both from @company/mfe-react. The storage adapter and a documented shell
  override bootstrap opt out through this rule's `allowedScopes` option.

**Fix.** `useStoredState(name, schema, { defaultValue })` for rendered state,
`useMfeStorage()` for imperative access. Both namespace the key under your definition id and
fence it to the signed-in identity. See [Storage](/docs/guides/storage).

</Callout>

The rule is off in test files only, because a storage test has to reach the storage it verifies.

## Styles that leak onto the rest of the page

A container compiles only the CSS for its own classes, and the build wraps that sheet in
`@scope ([data-mfe-scope="alert-panel"]) to ([data-mfe-scope])`. The shell owns the document-level
half: preflight, fonts, `@property`, theme variables. All of it inherits into you.

| Rule                                                                        | Why                                                                                                 | Enforced by                                    | Fix                                                                                            |
| --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| No `:root`, `:host`, `html` or `body` selector except as a leading compound | The scope root is not the document root, so the selector matches nothing                            | build — the scope plugin throws                | Style your own subtree                                                                         |
| No `@property` and no `@font-face` in a container                           | Both register page-wide; two containers defining the same one get whichever the browser parsed last | convention                                     | Ask the shell to define it                                                                     |
| No stylesheet entry and no `postcss.config.mjs`                             | The build produces `.mfe/styles.css` from your TSX; a second entry ships an unscoped sheet          | convention — none of the five examples has one | Write utilities and design-system components in TSX                                            |
| No stock Tailwind colour classes (`bg-red-500`)                             | The palette is the design system's; a stock colour generates no CSS at all                          | nothing in a scaffolded container              | Use a semantic token (`bg-primary`, `text-muted-foreground`) or a palette step (`bg-blue-120`) |

`@keyframes` is safe, and only because the build renames the ones your sheet defines.
[Styling](/docs/guides/styling) has the whole picture.

## A page reload on every edit

React Refresh replaces a module in place only when it can prove **every** export is a component.
One exported hook, constant, schema or factory beside them makes the module unable to accept an
update; the update propagates to whatever imported it until it reaches an entry, which accepts
nothing — so the page reloads and every piece of state on it is lost. The failure is silent.

`src/mfe.ts` exports a definition and usually its contract, so it can never be a refresh boundary.
Keep the render function in its own module, where every export is a component.

```ts title="src/mfe.ts"
export const alertPanelContract = { inputs, events }
export const alertPanel = createWidget({
  id: 'alert-panel',
  ...alertPanelContract,
  render: AlertPanel,
})
```

```tsx title="src/alert-panel.tsx"
// Every export in this module is a component, so an edit here hot-updates.
export function AlertPanel({ inputs, emit }: WidgetRenderProps<typeof alertPanelContract>) {
  return <section>{inputs.alertId}</section>
}
```

Convention only: there is no `react-refresh/only-export-components` rule in this repository. The
tool that answers the question is `pnpm hmr:probe <file>`, which reports `hot-updated in place` or
`(the page reloaded)`.

The same symptom has a second cause. **Generated output must be a pure function of its sources.**
The build regenerates before every compilation and your container imports what it generates, so a
timestamp, a counter or a random id in a generated module makes every compilation a source change
and the container rebuilds forever — which reaches you as hot updates that fail to fetch and a page
that reloads. That binds you only if you write your own generator. What binds every author is the
banner on each generated file: **never edit generated output.**

## A Widget that remounts on every render

`lazyWidget(id)` returns a component, and a component's identity is what React uses to decide
whether it is looking at the same element. One built during render is a new identity every pass.

<Callout type="error" title="mfe/stable-definitions">
  `lazyWidget` (`lazyWidget` from @company/mfe-react) has to be called once, at module scope.
  Calling it in the body of `Panel` mints a new definition identity on every call, so the host
  treats it as a different MFE: it unmounts the running instance, throws away its state and
  refetches its data. Move the `lazyWidget(...)` call to the top level of this module and reference
  the resulting definition here.
</Callout>

```ts title="src/widgets.ts"
/** Built at module scope because one built during render remounts the Widget every pass. */
import { lazyWidget } from '@company/mfe-react'

import { events, inputs } from '@example/alert-panel/contracts'

export const AlertPanel = lazyWidget('alert-panel', { contract: { inputs, events } })
```

The rule guards `createApp`, `createWidget` and `lazyWidget`, resolves aliased and namespaced
imports through the scope manager, and reports a call inside a function body, an arrow function, a
class static block or a class field initialiser. The one exception is a host that learns which
Widgets exist only when it reads the registry: it uses `DynamicWidget`, which takes the id as a prop
and builds nothing during render.

## A contract nobody can check

The build reads your definition **without running it**, so a host can render a catalogue entry
before anything is fetched. That is only possible if the declarations are literals.

| Rule                                                                                                     | Enforced by                                                                           | Fix                                                                                                      |
| -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| A definition id is lower-case letters, digits and single hyphens (for example `alert-panel`)             | the scaffold, build, mount (`registry/invalid-descriptor`) and registry (quarantined) | Rename. The id is also a storage prefix and a CSS scope value                                            |
| Two definitions may not share an id                                                                      | build inside one container; **both** entries quarantined across the registry          | Rename one                                                                                               |
| An event name is lower camel case                                                                        | build and mount                                                                       | Consumers subscribe as `onYourEvent`, so the name has to survive that mapping                            |
| An input may not be named `key`, `ref`, `fallback` or `onSomething`                                      | build and mount                                                                       | Rename the input; those names belong to the host                                                         |
| Inputs and event payloads must be JSON-serializable                                                      | mount, before schema validation                                                       | Send data. A consumer that needs a callback subscribes to an event instead                               |
| A Widget declares both `inputs` and `events`                                                             | build                                                                                 | `inputs: z.object({})` when it takes none                                                                |
| The schema must be readable without running the module                                                   | build                                                                                 | Declare it inline in `src/mfe.ts`, or as an exported top-level const in another module of this container |
| `title`, `description`, `version`, `tags` and `id` are inline literals; `icon` is an imported identifier | build                                                                                 | They are read at build time and published in the registry, so they cannot be computed                    |
| A container exports at most one App, and every definition is exported from the entry                     | build                                                                                 | Split them into separate containers; add `export`                                                        |

A consumer contract never calls `.strict()`, so a Widget can add a field without breaking one. That
one is convention, stated in the type.

## Failures that only appear in production

**Do not reach past a package's entry point.**

<Callout type="error" title="@typescript-eslint/no-restricted-imports">
  Public API boundary: @company/mfe-core is a framework-internal contract package whose shape
  changes with the framework, not with its public API. Everything an MFE author needs, types
  included, is re-exported from @company/mfe-react.

**Fix.** Import from `@company/mfe-react`. If what you need is not exported there, that is a
framework bug worth filing.

</Callout>

Also blocked for authors: `@company/mfe-host` ("An MFE that imports it can mount itself outside the
host lifecycle and will leak on unmount"), `react-dom/client` ("the host owns the React root"),
`single-spa`, `@module-federation/*`, and — including type imports — `@opentelemetry/*` and
`@grafana/faro*`. Zustand, Redux, MobX, Jotai and `@tanstack/store` are explicitly allowed: an MFE
owns its own state.

**Do not reference an asset with a bare relative string.** `'./icons/gear.svg'` in a string literal
resolves against the shell document, not against your container. It works in development, where the
two are on the same host, and breaks the first time they are not. The build reports it as a
diagnostic with the repair: import the asset, or write
`new URL('./icons/gear.svg', import.meta.url).href`.

**Do not use `console.log`.** The rule applies to authors, not only to framework packages:
`no-console` is `['error', { allow: ['warn', 'error'] }]` in both presets, so `log`, `info`, `debug`
and `table` are errors in a container's `src/`. Use `useTelemetry()` — `telemetry.info(…)`,
`telemetry.error(err)` — which carries your definition id, version and build hash automatically.

**Do not rely on async context across an `await` for tracing.** Trace parentage is a synchronous
active-span slot, so a span created after an `await` inside `startActiveSpan` loses the ambient
context and becomes a root with a fresh trace id. The framework produces **no parent** rather than a
wrong one, because a wrong parent corrupts a production trace tree silently. Convention, documented
on the type: create child spans synchronously, or start them with `startSpan` and correlate by an
explicit attribute.

**When you genuinely must suppress a rule**, the suppression names one rule, sits on the line it
applies to, and carries a specific reason. "Noisy" is not a reason, and a check is never disabled
across a package to accommodate one exception.

## The rules, end to end

| Rule                                                                                               | Enforced by                                                         | Fix                                        |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------ |
| No `createBrowserHistory`, no patching `window.history`                                            | lint `mfe/no-global-patching`; mount `app/invalid-router`           | Forward the supplied `history`             |
| Do not write to `window.location`                                                                  | convention                                                          | Navigate with your own router              |
| Pass `basePath` through unchanged                                                                  | mount `app/invalid-base-path`                                       | `createRouter({ basepath: basePath })`     |
| Spread the router context; never replace `mfe` or `queryClient`                                    | mount `app/invalid-router`; dev diagnostic for child routes         | `context: { ...context, mine }`            |
| Routes are relative to your boundary                                                               | convention                                                          | Write `/settings`                          |
| A Widget does not touch the URL, `document.title` or `document.head`                               | lint `mfe/no-widget-global-effects`, inside declared `widgetScopes` | Declare an event and `emit` it             |
| No raw `localStorage` / `sessionStorage`                                                           | lint `mfe/no-raw-storage`                                           | `useStoredState` / `useMfeStorage`         |
| No document-root selectors, `@property` or `@font-face`                                            | build throws; convention                                            | Style your own subtree                     |
| No stylesheet entry, no stock Tailwind colours                                                     | convention                                                          | Semantic tokens or palette steps           |
| Export only components beside components                                                           | convention                                                          | `pnpm hmr:probe`; render in its own module |
| No timestamps, counters or random ids in generated output; never edit it                           | convention                                                          | Regenerate                                 |
| `lazyWidget`, `createApp`, `createWidget` at module scope                                          | lint `mfe/stable-definitions`                                       | Hoist the call; or `DynamicWidget`         |
| Id, event, input and presentation format rules                                                     | build, mount, registry                                              | Rename; write literals                     |
| Inputs and payloads are JSON-serializable                                                          | mount                                                               | Send data, subscribe to events             |
| No deep imports; no `mfe-core`, `mfe-host`, `react-dom/client`, `@module-federation/*`, OTel, Faro | lint `no-restricted-imports`                                        | Import from `@company/mfe-react`           |
| Container-aware asset references                                                                   | build diagnostic                                                    | `new URL(…, import.meta.url)`              |
| No `console.log`                                                                                   | lint `no-console`                                                   | `useTelemetry()`                           |
| No async context across `await` in tracing                                                         | convention                                                          | Create child spans synchronously           |

The isolation boundaries these rules defend — URL, styles, storage, network, errors and shared
singletons — are drawn on the design map, in the
[`isolation-boundaries` diagram](/docs/design#the-isolation-boundaries).
