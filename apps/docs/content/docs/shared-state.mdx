---
title: 'Share state across Apps and Widgets'
description: 'Keep a units preference or selected well in sync between React and Angular components.'
---

Share a selection or preference between the shell, React Apps and Angular Widgets.
All consumers read one reactive record. The shell supplies backend persistence and controls its user or workspace scope.

The shell must [configure shared state](/docs/configure-shared-state) before mounting your definition.
For a preference belonging to one definition in this browser, use [browser storage](/docs/remember-a-value).

<Diagram
  src="/diagrams/capability-shared-state.svg"
  alt="React and Angular consumers connect to the shell-owned shared-state store and persistence adapter."
  caption="Both framework adapters connect to the same shell-owned record."
>
  The shell connects a shared-state store to its persistence adapter. React hooks and Angular
  injectors subscribe to that store through their mount. A setter updates subscribed consumers and
  saves through the adapter. The setter's promise resolves after persistence accepts the write.
</Diagram>

Try the [running React and Angular example](https://github.com/rpkapps/mfe-framework-claude/tree/dev/examples/shared-state).
Choosing a well in React updates the Angular planner. Changing units in Angular updates React.

## Steps

<Steps>
<Step>
### 1. Import the schema from its package

Import the schema from your shared contract package. React Lab and Angular Fieldwork both use `@example/shared-state-contracts`.

```ts title="Illustrative src/mfe.ts"
import { sharedStateSchema } from '@example/shared-state-contracts'
```

The package defines `display:units` and `well:selection`. Import your team's published contract instead of copying its Zod declaration.

</Step>
<Step>
### 2. Add the schema to your definition

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```ts title="Illustrative src/mfe.ts"
import { createApp } from '@company/mfe-react'
import { sharedStateSchema } from '@example/shared-state-contracts'

import { makeRouter } from './router'

export default createApp({ id: 'operations', router: makeRouter, sharedStateSchema })
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative src/mfe.ts"
import { createApp } from '@company/mfe-angular'
import { sharedStateSchema } from '@example/shared-state-contracts'

import { routes } from './app.routes'

export default createApp({ id: 'operations', routes, sharedStateSchema })
```

</Tab>
</Tabs>

Widgets use the same `sharedStateSchema` option on `createWidget`. Run `pnpm generate` to create typed bindings in `#mfe/shared-state`.

<Details summary="My container exports more than one definition">
Import from `#mfe/shared-state/<definition-id>` so each App or Widget uses its own declaration.
For example, the `operations` App uses `#mfe/shared-state/operations`.
</Details>

</Step>
<Step>
### 3. Read a key and handle rejected updates

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="Illustrative src/unit-picker.tsx"
import { useState } from 'react'
import { useSharedState } from '#mfe/shared-state'

export function UnitPicker() {
  const [units, setUnits] = useSharedState('display:units')
  const [error, setError] = useState('')

  async function changeUnits() {
    try {
      await setUnits(units === 'metric' ? 'imperial' : 'metric')
      setError('')
    } catch {
      setError('Units could not be saved. Choose again to retry.')
    }
  }

  return (
    <>
      <button onClick={() => void changeUnits()}>{units}</button>
      <p role="status">{error}</p>
    </>
  )
}
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative src/unit-picker.component.ts"
import { Component, signal } from '@angular/core'
import { injectSharedState } from '#mfe/shared-state'

@Component({
  selector: 'unit-picker',
  template: `<button (click)="changeUnits()">{{ units() }}</button>
    <p role="status">{{ error() }}</p>`,
})
export class UnitPicker {
  readonly state = injectSharedState('display:units')
  readonly units = this.state[0]
  readonly error = signal('')

  async changeUnits() {
    try {
      await this.state[1](this.units() === 'metric' ? 'imperial' : 'metric')
      this.error.set('')
    } catch {
      this.error.set('Units could not be saved. Choose again to retry.')
    }
  }
}
```

Angular injectors run in an injection context. Destroying the context ends the subscription.

</Tab>
</Tabs>

The setter updates subscribed components immediately. Await it before reporting a successful save. Catch a rejected promise to display failure.
Always write through the setter.

</Step>
<Step>
### 4. Update only the object fields that changed

```ts title="Illustrative src/selection-actions.ts (inside a mounted consumer)"
await store.set('well:selection', { wellId: 'well-42', runId: 'run-7' })
await store.set('well:selection', { runId: 'run-8' })
```

Take `store` with the generated `useSharedStateStore()` or `injectSharedStateStore()` binding.
The second write changes only `runId`. It preserves `wellId` and the default comparison mode. Nested objects follow the same rule.

To clear this selection, write `null`. Sending an empty object preserves it. `undefined` is not allowed. If a value is an array, send the complete new array.

</Step>
</Steps>

## Check it works

Open a units picker in an App and a Widget. Toggle either picker and confirm both update. Reload and check that persistence restores the preference.

## Errors

<Callout type="error" title="shared-state/unsupported-schema, at build">

```text
shared-state/unsupported-schema: sharedStateSchema must be a fixed-shape z.object
```

Use JSON values with fixed object fields and literal defaults. **Fix.** Replace transforms, coercion, custom refinements or computed defaults with a supported declaration.
Calculate domain values before writing them.

</Callout>

<Callout type="error" title="shared-state/invalid-value, at write">

```text
well:selection: <root> must be finite JSON data
```

**Fix.** Supply the fields needed to form a valid record. From a null selection, `{ runId: 'run-8' }` alone
cannot provide the required `wellId`. To reset this nullable key, write `null`. `undefined` is invalid.

</Callout>

<Callout type="error" title="shared-state/conflict, at write">

```text
well:selection: Record changed since this intention was formed; refresh and choose again
```

Another write changed the record before yours was accepted. **Fix.** Read the refreshed value and let the user choose again.

</Callout>
