---
title: 'Add a help page'
description: 'Mark one route in your App as the help capability, so the shell can send people to your own help page.'
---

Apps only. Mark one route as your help page, and the shell lists it in the command palette and can
open it by name. It is an ordinary route, so you write whatever the page needs.

## Steps

<Steps>

<Step>

### 1. Mark the route

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/operations/src/routes/help.tsx"
import { createFileRoute } from '@tanstack/react-router'
import type { ReactNode } from 'react'

export const Route = createFileRoute('/help')({
  staticData: {
    capability: {
      name: 'help',
      label: 'Operations help',
      icon: 'circle-help',
    },
    breadcrumb: 'Help',
  },
  component: Help,
})

function Help(): ReactNode {
  return <h2>Operations help</h2>
}
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative src/app.routes.ts"
import { Component } from '@angular/core'
import type { Routes } from '@angular/router'
import { mfeRouteData } from '@company/mfe-angular'

@Component({
  selector: 'operations-help',
  template: `<h2>Operations help</h2>`,
})
export class HelpComponent {}

export const routes: Routes = [
  {
    path: 'help',
    component: HelpComponent,
    data: mfeRouteData({
      capability: {
        name: 'help',
        label: 'Operations help',
        icon: 'circle-help',
      },
      breadcrumb: 'Help',
    }),
  },
]
```

</Tab>
</Tabs>

`capability` takes a `name` and a `label`, both required, and an optional `icon`. The build reads
them out of the file without running it, so write them as plain strings.

</Step>

<Step>

### 2. Generate the description record

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```sh
pnpm run generate
```

</Tab>
<Tab value="Angular">

```sh
pnpm exec nx run operations:generate
```

Run this in your Angular Nx workspace. Replace `operations` with your Nx project name.

</Tab>
</Tabs>

This writes your container's registry description. The host includes that record in its registry.
Publish or register that updated record through your host's registry workflow; starting your
container's development server does not update a separately maintained shell registry.

</Step>

<Step>

### 3. Confirm what the build published

```json shared title="examples/operations/.mfe/mfe-registry.json"
"capabilities": [
  { "name": "help", "label": "Operations help", "icon": "circle-help", "path": "/help" }
]
```

`path` comes from `createFileRoute` in React or the route object in Angular. An App publishes at most one help page.

</Step>

</Steps>

## Check it works

Start your container with its own development script and open the separately running shell that
registers your App. Find your help capability in the host's application-page menu or command
palette and select it. Its label should match your registry entry, and navigation should reach
`/help` under the App's assigned mount prefix. The host's own help UI may serve a separate purpose;
confirm which control exposes application help with the shell team.

## Errors

<Callout type="error" title="expected one of 'settings', 'help' and 'releaseNotes'">

```text shared
/home/you/operations/src/routes/help.tsx:7:7: 'operations' failed to extract a capability route:
expected one of 'settings', 'help' and 'releaseNotes', found "Help".
```

**Fix.** The names are case-sensitive. Write `name: 'help'`.

</Callout>

<Callout type="error" title="expected a non-empty `label` string literal">

```text shared
/home/you/operations/src/routes/help.tsx:6:17: 'operations' failed to extract the capability route
'/help': expected a non-empty `label` string literal, found no label.
```

**Fix.** Add the text the palette shows, for example `label: 'Operations help'`.

</Callout>

<Callout type="error" title="expected one route per capability">

```text shared
/home/you/operations/src/routes/support.tsx: 'operations' failed to extract the 'help' capability
route: expected one route per capability, found '/help' and '/support' both declare it.
```

**Fix.** Remove the mark from one of the two routes, and link to it from the other.

</Callout>

<Callout type="error" title="expected a capability declared by an App">

```text shared
/home/you/alerts/src/routes/help.tsx:5:5: the build failed to extract the 'help' capability
route: expected a capability declared by an App, found a container that exports Widgets only.
```

**Fix.** Move the route into a container that exports an App. A Widget has no routes of its own.

</Callout>
