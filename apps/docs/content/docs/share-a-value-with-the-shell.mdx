---
title: 'Share a value with the shell'
description: 'Choose shared state for shell-wide selections, browser storage for local preferences, or Widget inputs and outputs.'
---

Use shared state when the shell, Apps and Widgets need the same selection. Browser storage keeps
preferences under each definition's own scope. Apps and Widgets.

## Steps

<Steps>
<Step>
### 1. Choose the data channel

| Need                                                   | Channel                                                        |
| ------------------------------------------------------ | -------------------------------------------------------------- |
| A units preference or selection across definitions     | [Shared state](/docs/shared-state)                             |
| Data passed to one Widget and events returned          | [Widget inputs and outputs](/docs/define-inputs-and-outputs)   |
| A preference private to one definition's storage scope | [Browser storage](/docs/remember-a-value)                      |
| The shell's current identity or theme                  | [Shell bindings](/docs/reference/hooks-and-components#useuser) |

Choose shared state for shared, reactive records with backend persistence. Choose Widget inputs when
its host controls the value for that specific Widget.

</Step>
<Step>
### 2. Use the shared-state binding

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="Illustrative React component body"
import { useSharedState } from '#mfe/shared-state'

const [units, setUnits] = useSharedState('display:units')
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular component field"
import { injectSharedState } from '#mfe/shared-state'

readonly units = injectSharedState('display:units')
```

Read the Angular signal with `units[0]()`.

</Tab>
</Tabs>

First declare your schema and generate these bindings. Follow [the shared-state guide](/docs/shared-state)
for setup, writing values and handling failed saves.

</Step>
<Step>
### 3. Keep browser preferences in their own scope

```tsx title="examples/operations/src/routes/index.tsx"
const [density, setDensity] = useStoredState('table-density', densitySchema, {
  defaultValue: 'comfortable',
})
```

Inside Operations, this binds `operations:table-density`. The same binding in the shell uses `@host:table-density`.
Angular's `injectStoredState` follows the same scope rule. Neither binding accesses the other's record.
Use [browser storage](/docs/remember-a-value) for complete React and Angular examples.

</Step>
</Steps>

## Check it works

Mount two consumers of `display:units`, then change the units from either one. Both should update.
A browser-storage preference should update only consumers within its own definition scope.
If the shell cannot see your preference, check that you chose shared state rather than browser storage.
