---
title: 'Share a value with the shell'
description: 'How useStoredState picks a scope, what the reserved @host scope holds, and what to use instead.'
---

Your stored records are yours: the shell cannot read them, and you cannot read the shell's. A
component that renders in both places gets one record in each. Apps and Widgets.

## Steps

<Steps>
<Step>
### 1. Bind the key as usual inside your mount

```tsx title="examples/operations/src/routes/index.tsx"
const [density, setDensity] = useStoredState('table-density', densitySchema, {
  defaultValue: 'comfortable',
})
```

Inside an App or a Widget the key is `operations:table-density`. There is no argument that points
it somewhere else.

</Step>
<Step>
### 2. Let a shared component pick its own scope

```ts title="apps/shell/src/shell/hooks.ts"
return useStoredState('dashboard', DashboardLayoutSchema, {
  defaultValue: EMPTY_LAYOUT,
  migrate: migrateLayout,
})
```

The same call outside any mount binds `@host:dashboard`, the page's own scope. Ship one component
to the shell and to your App, and each place keeps its own record under its own prefix. A
definition id holds lower-case letters, digits and single hyphens, so no container can claim
`@host`.

</Step>
<Step>
### 3. Pass a value across the boundary as data

```tsx title="examples/operations/src/routes/index.tsx"
<AlertPanel
  alertId="a-1001"
  severity="warning"
  onAcknowledged={payload => setAcknowledged(payload.acknowledgedAt)}
/>
```

Storage is not a channel between containers. A Widget takes inputs as props and reports what
happened through a declared output. An App reads the page's identity, groups and theme through
`useUser`, `useGroups` and `useTheme`.

</Step>
</Steps>

## Check it works

Open the browser developer tools, then Application, then Local storage. The shell's records sit
under `@host:`, and yours sit under `<your definition id>:`. Two definitions that both chose the
name `theme` keep two records, and neither one can overwrite the other.

## Errors

<Callout type="error" title="storage/failure, at bind">

```text
@host failed to bind a storage key: expected a definition id, received the reserved host scope
'@host'.
```

**Fix.** Only shell code reaches that scope, and it does so by rendering outside a mount. From
inside your App or Widget, bind the key normally and let it resolve to your own definition.

</Callout>
