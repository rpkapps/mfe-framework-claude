---
title: 'Follow the shell theme'
description: 'Read light or dark from React or Angular, and let the shell own the switch.'
---

Apps and Widgets. The shell owns the light/dark switch. Semantic colors follow it automatically, and your component can read the theme for other values.

<Diagram
  src="/diagrams/capability-theme.svg"
  alt="How React and Angular containers connect to the shell for theme."
  caption="How your container connects to the shell"
>
  The shell publishes the theme. React reads it through `useTheme`, and Angular receives a signal
  through `injectTheme`. Your scoped styles inherit shell theme variables. The shell owns the theme
  switch.
</Diagram>

## Steps

<Steps>
<Step>
### 1. Use semantic colors

```tsx title="examples/operations/src/routes/index.tsx"
<p className="text-xs text-muted-foreground">
  The panel below is a Widget served by a different deployment. …
</p>
```

For Angular, use the host-supplied PrimeNG tokens described in [Use PrimeNG](/docs/reference/angular-adapter#use-primeng). Generated containers configure PrimeNG without a preset.

A semantic token resolves against the theme variables the shell declares, and those inherit into
your subtree. The same class is correct in both themes.

</Step>
<Step>
### 2. Read the theme when a value depends on it

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/lab/src/routes/shell-state.tsx (adapted)"
import { useTheme } from '@company/mfe-react'

export function ThemeLabel() {
  const theme = useTheme()
  return <p>Current theme: {theme}</p>
}
```

Use `useTheme(theme => theme === 'dark')` when you need only a selected value.

</Tab>
<Tab value="Angular">

```ts title="examples/fieldwork/src/overview.component.ts (adapted)"
import { Component } from '@angular/core'
import { injectTheme } from '@company/mfe-angular'

@Component({
  selector: 'fieldwork-theme-label',
  template: `<p>Current theme: {{ theme() }}</p>`,
})
export class ThemeLabelComponent {
  readonly theme = injectTheme()
}
```

Read the signal with `theme()`. Create it in a field initializer or constructor.

</Tab>
</Tabs>

Both APIs read `'light'` or `'dark'`.

</Step>
<Step>
### 3. Never set the theme yourself

Let the framework provide your themed root. React containers inherit shell tokens. Angular PrimeNG components read host-supplied tokens that follow the shell theme.
A second root or a document-level `dark` class can put part of the page in the wrong theme.

</Step>
</Steps>

## Check it works

Press <Kbd>⌘J</Kbd> in the shell, or use the user menu at the top right. Your subtree repaints
without a reload and without a prop crossing the boundary. React theme consumers re-render, and Angular theme signals update. In a test, `createMfeTestEnvironment` sets the theme and changes it.

## Errors

<Callout type="error" title="mount/failure, no runtime">

```text
<no-runtime> failed to render useTheme(): expected an MfeProvider above this component, or an
enclosing App or Widget mount, received neither.
```

**Fix.** Inside a container this usually means a second copy of `@company/mfe-react` in your
container's build. Import the framework from that one package.

</Callout>
