---
title: 'Follow the shell theme'
description: 'Read light or dark with useTheme, and let the shell own the switch.'
---

The shell owns the theme. Your colours follow it with nothing wired up, and `useTheme()` tells you
which one is active when a value has to change with it. Apps and Widgets.

## Steps

<Steps>
<Step>
### 1. Do nothing for colours

```tsx title="examples/operations/src/routes/index.tsx"
<p className="text-xs text-muted-foreground">
  The panel below is a Widget served by a different deployment. …
</p>
```

A semantic token resolves against the theme variables the shell declares, and those inherit into
your subtree. The same class is correct in both themes.

</Step>
<Step>
### 2. Read the theme when a value depends on it

```tsx title="examples/lab/src/routes/shell-state.tsx"
import { useTheme } from '@company/mfe-react'

const theme = useTheme()
return theme === 'dark' ? <MoonIcon aria-hidden /> : <SunIcon aria-hidden />
```

`useTheme()` returns `'light'` or `'dark'`. It takes an optional selector,
`useTheme(theme => theme === 'dark')`, and it re-renders only the components that read it.

</Step>
<Step>
### 3. Never set the theme yourself

```tsx title="examples/alert-panel/src/alert-panel.tsx"
// Render your components directly: your build already wraps them in the design system's root.
return (
  <Alert variant={variant} appearance="outline">
    {children}
  </Alert>
)
```

That root inherits the theme from the shell. A second root of your own, or a `dark` class on the
document, would put part of the page in the wrong theme.

</Step>
</Steps>

## Check it works

Press <Kbd>⌘J</Kbd> in the shell, or use the user menu at the top right. Your subtree repaints
without a reload and without a prop crossing the boundary. Anything reading `useTheme()` re-renders
with the new value. In a test, `createMfeTestEnvironment` sets the theme and changes it.

## Errors

<Callout type="error" title="mount/failure, no runtime">

```text
<no-runtime> failed to render useTheme(): expected an MfeProvider above this component, or an
enclosing App or Widget mount, received neither.
```

**Fix.** Inside a container this usually means a second copy of `@company/mfe-react` in your
container's build. Import the framework from that one package.

</Callout>
