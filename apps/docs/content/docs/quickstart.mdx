---
title: 'Quickstart'
description: 'Create a container in your own repository, build it, and connect its generated registry record to a separately running shell.'
---

Build your container in its own repository. Install framework packages from your team's package registry.
The shell runs in a separate repository and loads your container over HTTP.
Your registry credentials and a compatible published framework release are prerequisites.

## Steps

<Steps>
<Step>
### 1. Create your consumer workspace

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```sh
mkdir field-notes-workspace
cd field-notes-workspace
git init
```

```json title="package.json"
{ "name": "field-notes-workspace", "private": true }
```

```yaml title="pnpm-workspace.yaml"
packages:
  - apps/*
```

```json title="tsconfig.base.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "jsx": "react-jsx",
    "strict": true,
    "skipLibCheck": true,
    "esModuleInterop": true,
    "allowImportingTsExtensions": true,
    "resolveJsonModule": true,
    "noEmit": true
  }
}
```

The current React scaffolder requires a pnpm workspace and base TypeScript configuration. This workspace belongs to your container repository.

</Tab>
<Tab value="Angular">

```sh
pnpm dlx create-nx-workspace@22 field-notes-workspace --preset=apps --packageManager=pnpm --nxCloud=skip
cd field-notes-workspace
pnpm add -D @company/mfe-nx@^0.1.0
```

Use the compatible framework version published by your team. This generator supports Nx 20–22 and Angular 19.

</Tab>
</Tabs>

Configure your organization registry before resolving the scoped framework packages.

</Step>
<Step>
### 2. Generate the container and prepare dependencies

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```sh
pnpm create @company/mfe apps/field-notes --id field-notes
```

Before installing, edit `apps/field-notes/package.json`. The current template emits `workspace:*` for framework packages and `catalog:` for third-party packages.
Replace every such value with a compatible published semver version or range. Your consumer workspace does not contain framework source packages.
Keep the generated scripts, build configuration, and source files.

</Tab>
<Tab value="Angular">

```sh
pnpm exec nx g @company/mfe-nx:app field-notes --port 3101
```

The generator writes published dependency ranges, project targets, and `apps/field-notes/src/mfe.ts`.
It updates your consumer workspace's package manifest. Review the generated versions before installation.

</Tab>
</Tabs>

An id uses lower-case letters, digits, and single hyphens. Use the Widget generator or React `--template widget` for a Widget.

</Step>
<Step>
### 3. Install and build your container

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```sh
pnpm install
cd apps/field-notes
pnpm run generate
pnpm run build
```

</Tab>
<Tab value="Angular">

```sh
pnpm install
pnpm exec nx run field-notes:generate
pnpm exec nx build field-notes
```

</Tab>
</Tabs>

These commands run in your consumer repository. They generate the container's registry record and deployment files without building framework source.

</Step>
<Step>
### 4. Start your dev server

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```sh
# From apps/field-notes in your consumer repository.
pnpm run dev
```

</Tab>
<Tab value="Angular">

```sh
# From your Nx consumer workspace root.
pnpm exec nx serve field-notes
```

</Tab>
</Tabs>

Your container serves its manifest at `http://localhost:3101/mf-manifest.json`.
It does not start the shell.

</Step>
<Step>
### 5. Register the container with the shell

Hand `.mfe/mfe-registry.json` or the built `mfe-registry.json` to the shell owner.
The shell's registry process resolves each entry's manifest URL against where you deployed that file.
It must list your definition before an App route or Widget mount can find it.

Start the shell independently using its own repository's install and dev scripts.
If the definition is already registered, use a [local override](/docs/point-the-shell-at-your-dev-server) to select your dev server.
An override changes a URL. It does not create a missing registry entry.

</Step>
<Step>
### 6. Open your App in the shell

```text shared
<your-shell-origin>/field-notes
```

Use the address supplied by the shell owner. Your App's routes resolve below the boundary the shell assigns.

</Step>
</Steps>

## Check it works

Your dev server serves `mf-manifest.json`. The separately running shell lists `field-notes` in its registry and application finder.
Opening the App keeps the shell header visible and renders your home route below it.
Your framework dependencies resolve from the package registry, with no links to a framework checkout.

## Errors

If installation cannot resolve `workspace:*` or `catalog:`, finish replacing the React template's dependency references with published versions.
If your definition is absent, hand over its generated record before configuring a local override.
For a reported framework failure, [look up its code](/docs/reference/error-codes).
