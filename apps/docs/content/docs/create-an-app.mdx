---
title: 'Create an App'
description: 'Scaffold a container, declare an App in src/mfe.ts, and have the shell mount it at its own URL prefix.'
---

An App owns a prefix of the address bar and brings its own router. You declare it once, in the
container's entry file, and the shell mounts it at whatever prefix it assigns.
Create the container in your own consumer repository, using the [quickstart setup](/docs/quickstart).

## Steps

<Steps>

<Step>

### 1. Scaffold the container

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```sh
pnpm create @company/mfe apps/operations --id operations
```

</Tab>
<Tab value="Angular">

```sh title="terminal"
pnpm exec nx g @company/mfe-nx:app operations --id operations --port 3001
```

</Tab>
</Tabs>

Run the generator in your own consumer workspace. Before installing a React scaffold, replace its `workspace:*` and `catalog:` dependencies with compatible published versions.
Angular generates published dependency ranges. Install with `pnpm install` in your consumer repository.

</Step>

<Step>

### 2. Declare the App in the entry file

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```ts title="apps/operations/src/mfe.ts"
import { createApp, type AppRouterOptions, type MfeStaticData } from '@company/mfe-react'
import { createRouter } from '@tanstack/react-router'

import { routeTree } from './routeTree.gen'

function makeRouter({ basePath, history, context }: AppRouterOptions) {
  return createRouter({
    routeTree,
    basepath: basePath,
    history,
    context: { ...context },
    defaultPreload: 'intent',
  })
}

declare module '@tanstack/react-router' {
  interface Register {
    router: ReturnType<typeof makeRouter>
  }

  // eslint-disable-next-line @typescript-eslint/no-empty-object-type -- an augmentation adds no field.
  interface StaticDataRouteOption extends MfeStaticData {}
}

export default createApp({ id: 'operations', version: '2.1.0', router: makeRouter })
```

</Tab>
<Tab value="Angular">

```ts title="src/mfe.ts"
import { createApp } from '@company/mfe-angular'
import { routes } from './app.routes'

export default createApp({ id: 'operations', version: '2.1.0', routes })
```

</Tab>
</Tabs>

React forwards `basePath`, `history`, and `context` to its router factory. Angular supplies `routes` and gets a mount-owned router.
Both resolve paths under the boundary assigned by the shell.

</Step>

<Step>

### 3. Declare the dev port

```json title="apps/operations/package.json" shared
"mfe": {
  "port": 3001,
  "definitions": ["operations"]
}
```

This metadata records the local port and definition ids. Angular's Nx generator also configures its `serve` target with the same port.
Register the generated container record with the shell separately. This package metadata does not register your App with a remote shell.

</Step>

</Steps>

## Check it works

React runs `pnpm run generate`, `pnpm run build`, and `pnpm run dev` in its container directory.
Angular runs `pnpm exec nx run operations:generate`, `pnpm exec nx build operations`, and `pnpm exec nx serve operations` in its consumer workspace.
Hand the generated `mfe-registry.json` record to the shell owner, together with your manifest URL.

Start the shell independently in its repository. Open `/operations` at that shell's origin after its registry includes your App.
The entry file is read without executing it. Export every definition from `src/mfe.ts` and declare ids and metadata as literal strings.

## Errors

<Callout type="error" title="expected lower-case letters, digits and single hyphens">

```text shared
Order_Book failed to createApp: expected lower-case letters, digits and single hyphens (for
example "alert-panel"), received "Order_Book".
```

**Fix.** Rename the id to `order-book`. The registry sets aside an entry whose id breaks the rule.

</Callout>

<Callout type="error" title="expected a router factory function">

```text shared
orders failed to create App definition: expected a router factory function, received nothing.
```

**Fix.** Pass `router: makeRouter`, the factory itself. It runs for each mount, not once per
module, and twice in development under StrictMode.

</Callout>

<Callout type="error" title="expected the supplied basePath passed through unchanged">

```text shared
operations@2.1.0 failed to mount App: expected the supplied basePath "/operations" passed through
unchanged as createRouter({ basepath }), received no basepath on the router.
```

**Fix.** Add `basepath: basePath` to the `createRouter` call. A hard-coded prefix fails the same
check, because a nested App is mounted somewhere else.

</Callout>

<Callout type="error" title="expected the supplied context.mfe namespace">

```text shared
operations@2.1.0 failed to mount App: expected the supplied context.mfe namespace, spread into the
router context unchanged, received no mfe key.
```

**Fix.** Write `context: { ...context, yourKey }`. Add your own top-level keys freely, and leave
`mfe` and `queryClient` alone.

</Callout>
