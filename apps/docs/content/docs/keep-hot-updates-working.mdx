---
title: 'Keep hot updates working'
description: 'Keep your render function in a module of components only, and one edit updates the page instead of reloading it.'
---

Apps and Widgets. The state-preserving behavior below describes React Refresh. Angular uses its Nx webpack dev server. React Refresh replaces a module in place only when every export in it is a
component. One exported schema, constant or definition beside them costs you a full page reload on
every edit, with the state on the page.

## Steps

<Steps>

<Step>

### 1. Keep the definition in one module

<Tabs items={['React', 'Angular']} defaultIndex={0}>
<Tab value="React">

```ts title="src/mfe.ts (trimmed)"
export const alertPanelContract = {
  inputSchema: z.object({ alertId: z.string() }),
  outputSchema: z.object({
    acknowledged: z.object({ alertId: z.string(), acknowledgedAt: z.string() }),
  }),
}

export const alertPanel = createWidget({
  id: 'alert-panel',
  version: '1.4.0',
  ...alertPanelContract,
  render: AlertPanel,
})
```

</Tab>
<Tab value="Angular">

```ts title="src/mfe.ts (trimmed)"
import { createWidget } from '@company/mfe-angular'
import { z } from 'zod'
import { WellInspectionComponent } from './well-inspection.component'

export const wellInspection = createWidget({
  id: 'well-inspection',
  version: '0.1.0',
  inputSchema: z.object({}),
  outputSchema: z.object({}),
  component: WellInspectionComponent,
})
```

Keep Angular definitions separate from components too. React Refresh's component-only export rule applies to React.

</Tab>
</Tabs>

This module exports a contract and a definition, so editing it reloads the page. That is fine,
because you edit it rarely.

</Step>

<Step>

### 2. Keep the render function in another

<Tabs items={['React', 'Angular']} defaultIndex={0}>
<Tab value="React">

```tsx title="src/alert-panel.tsx (trimmed)"
export function AlertPanel({
  inputs,
  emit,
}: WidgetRenderProps<typeof alertPanelContract>): ReactNode {
  return <OneAlert key={inputs.alertId} inputs={inputs} emit={emit} />
}
```

</Tab>
<Tab value="Angular">

```ts title="src/well-inspection.component.ts (shape)"
import { Component } from '@angular/core'

@Component({
  selector: 'well-inspection',
  template: '<p>Well inspection</p>',
})
export class WellInspectionComponent {}
```

Angular uses the Nx webpack dev server. Check its observed update behavior rather than assuming React Refresh preserves Angular state.

</Tab>
</Tabs>

For React, keep exports to components. Use the probe to verify the behavior of your own dev server.

</Step>

<Step>

### 3. Check an edit in your own repository

Start your container's dev server and the separate shell. Open your screen, change a visible label, and save the component. Check whether the shell reloads and whether the component keeps its local state.

React Refresh should update a component-only module in place. Angular's Nx webpack server has its own update behavior. Verify what your configured server does rather than assuming React Refresh's guarantees.

</Step>

</Steps>

## Check it works

Your new label appears without manually refreshing. For React, a component-only edit preserves component state. Definition or contract changes can reload the page.

The framework repository includes a maintainer probe for its example harness. It is not a CLI installed in independent container repositories. See [CLI and scripts](/docs/reference/cli-and-scripts) for that harness.
