---
title: 'Set breadcrumbs'
description: 'Name the crumb a route contributes, hide one, or replace your part of the trail while a flow is running.'
---

Apps only. The shell owns the first crumbs, the workspace and your App. Everything below them
comes from your routes, and you can name, hide or replace that part.

<Diagram
  src="/diagrams/capability-breadcrumbs.svg"
  alt="How React and Angular containers connect to the shell for breadcrumbs."
  caption="How your container connects to the shell"
>
  Your router supplies route crumbs. `useBreadcrumbs` or `injectBreadcrumbs` overrides your App
  portion while a flow is active. The shell combines these contributions with its own crumbs and
  displays the trail in the header.
</Diagram>

## Steps

<Steps>

<Step>

### 1. Name a route's crumb

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/operations/src/routes/assets.tsx"
export const Route = createFileRoute('/assets')({
  staticData: { breadcrumb: 'Assets' },
  component: Assets,
})
```

</Tab>
<Tab value="Angular">

```ts title="examples/fieldwork/src/app.routes.ts (adapted)"
import type { Routes } from '@angular/router'
import { mfeRouteData } from '@company/mfe-angular'
import { SettingsComponent } from './settings.component'

export const routes: Routes = [
  {
    path: 'settings',
    component: SettingsComponent,
    data: mfeRouteData({ breadcrumb: 'Settings' }),
  },
]
```

Use `mfeRouteData({ breadcrumb: false })` to hide a segment.

</Tab>
</Tabs>

<span id="2-hide-a-segment" />

Set the breadcrumb field to `false` to hide a route segment.
React falls back to its head title, then its path. Angular falls back to its route title, then its path.
Named parameters show their values. Generic `id` parameters and layout routes contribute no crumb.

</Step>

<Step>

<span id="3-replace-the-trail-for-a-flow" />

### 2. Replace the trail for a flow

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/lab/src/routes/breadcrumbs.tsx"
import { useBreadcrumbs } from '@company/mfe-react'

const FLOW = [
  { key: 'wizard', label: 'New study' },
  { key: 'step-2', label: 'Step 2 · Inputs' },
]

useBreadcrumbs(inFlow ? FLOW : [])
```

</Tab>
<Tab value="Angular">

```ts title="examples/fieldwork/src/settings.component.ts (adapted)"
import { injectBreadcrumbs } from '@company/mfe-angular'

// Inside a component constructor, with inFlow as a signal:
injectBreadcrumbs(() =>
  this.inFlow()
    ? [
        { key: 'wizard', label: 'New study' },
        { key: 'inputs', label: 'Inputs' },
      ]
    : [],
)
```

</Tab>
</Tabs>

A wizard has steps your route tree does not name, so you supply them. An empty array means no
override, and the override clears itself when you navigate away or unmount.

</Step>

</Steps>

## Check it works

Run `pnpm dev` and open `http://localhost:3000/lab/breadcrumbs`. The trail in the header reads
"Discovery / Framework lab / Breadcrumbs". The last two come from the registry and from
`staticData.breadcrumb` on the route. Press "Override the trail" and your part becomes the two
flow steps, with the workspace crumb untouched.

For Angular, open the labeled route and confirm “Settings” appears. End the flow and check the original route trail returns.

## Errors

<Callout type="error" title="expected at most one active breadcrumb override per App mount">

```text
operations failed to install a breadcrumb override: expected at most one active breadcrumb
override per App mount, received a second override while another is still mounted.
```

**Fix.** Lift the override into one component, or unmount the first before the second appears.
This is reported to the developer tools in development, and the second override is refused.

</Callout>
