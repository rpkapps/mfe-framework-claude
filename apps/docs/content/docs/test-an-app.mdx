---
title: 'Test an App'
description: 'Render your App over a memory history and assert on the page your routes produce.'
---

Apps only. React uses `renderApp` and Angular uses `mountApp`. Both exercise the production mount tree, a memory history
and in-memory stores. You assert on the page your routes render, with the real router, the real
validation and the real teardown.

## Steps

<Steps>

<Step>

### 1. Render the App at one of its own URLs

<Tabs items={['React', 'Angular']} defaultIndex={0}>
<Tab value="React">

```tsx title="Illustrative src/routes/accounts.test.tsx"
import { renderApp, setMfeConfig } from '@company/mfe-react/testing'
import { screen, waitFor } from '@testing-library/react'
import { afterEach, expect, it } from 'vitest'

import reports from '../mfe.ts'

let mounted: (() => Promise<void>) | null = null

it('reads its path parameter from its own URL', async () => {
  setMfeConfig({ apiBaseUrl: 'https://api.example.test/v1/' })

  const rendered = renderApp(reports, { initialEntries: ['/accounts/fda-1-02'] })
  mounted = rendered.dispose

  await waitFor(() => {
    expect(screen.getByText('accountId=fda-1-02')).toBeInTheDocument()
  })
  expect(screen.getByText('accountId=fda-1-02')).toBeInTheDocument()
})
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative src/routes/accounts.spec.ts"
import { mountApp } from '@company/mfe-angular/testing'
import { expect, it } from 'vitest'
import { reports } from '../mfe'

it('reads its path parameter from the host URL', async () => {
  const mounted = await mountApp(reports, {
    basePath: '/reports',
    initialEntries: ['/reports/accounts/fda-1-02'],
  })
  expect(mounted.element.textContent).toContain('accountId=fda-1-02')
})
```

`mountApp` is asynchronous and waits for Angular to settle. This example assumes your App displays
its account id at `accounts/:accountId`. Replace the definition, URL and assertion with your own.
If your App reads stored values, seed them by key with the environment's `storage` option ([test storage](/docs/test-storage-and-lifecycle)).

</Tab>
</Tabs>

React entries are relative to the App. Wait for React’s first route assertion with `waitFor`. Angular entries include the boundary.

</Step>

<Step>

### 2. Dispose after every test

<Tabs items={['React', 'Angular']} defaultIndex={0}>
<Tab value="React">

```tsx title="Illustrative src/routes/accounts.test.tsx"
afterEach(async () => {
  // Cleared before the await: a later test may have assigned a new handle by the time this resolves.
  const dispose = mounted
  mounted = null
  await dispose?.()
})
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative vitest.setup.ts (trimmed)"
import '@angular/compiler'
import { cleanup, resetGeneratedAliases } from '@company/mfe-angular/testing'
import { afterEach } from 'vitest'

afterEach(async () => {
  await cleanup()
  resetGeneratedAliases()
})
```

`cleanup()` disposes every mount the helpers created. Use `await mounted.dispose()` for earlier teardown.

</Tab>
</Tabs>

`dispose()` unmounts the tree and runs the real teardown. Keep this cleanup in your own repository's test setup.

</Step>

<Step>

### 3. Check the App at the boundary the shell gives it

<Tabs items={['React', 'Angular']} defaultIndex={0}>
<Tab value="React">

```tsx title="Illustrative src/routes/accounts.test.tsx"
const rendered = renderApp(reports, {
  basePath: '/workspace/reports',
  initialEntries: ['/accounts/fda-1-02'],
})
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative src/routes/accounts.spec.ts (boundary example)"
const mounted = await mountApp(reports, {
  basePath: '/workspace/reports',
  initialEntries: ['/workspace/reports/accounts/fda-1-02'],
})
expect(mounted.element.textContent).toContain('accountId=fda-1-02')
```

Angular's `initialEntries` contains the full host URL, including `basePath`. React's `renderApp` accepts App-relative entries.

</Tab>
</Tabs>

`basePath` is the prefix the shell mounts you at. Your paths do not change, which is the point of
the test.

</Step>

<Step>

### 4. Run it

```sh shared
pnpm test
```

Run this in your container repository after configuring its `test` script.
React projects generate their modules before Vitest. Angular repositories can use a script wrapping
`nx test <project>`; that project's target must depend on generation.
Both need the [test alias and runner setup](/docs/test-with-env-and-a-fake-api#configure-your-repositorys-test-runner).

</Step>

</Steps>

## Check it works

The suite passes. React returns Testing Library queries. Angular returns `element`, `injector` and `whenStable()`. Both return `environment` and `dispose`. Pass
`shellState` to sign a different user in. A route that reads configuration needs
[values installed first](/docs/test-with-env-and-a-fake-api).

## Errors

<Callout type="error" title="failed to read the configuration field">

```text shared
the test environment failed to read the configuration field 'apiBaseUrl': expected configuration
installed by the test, received nothing installed.
```

**Fix.** Call `setMfeConfig({ apiBaseUrl: … })` before rendering, with every field your routes read.

</Callout>

<Callout type="error" title="failed to mount App">

<Tabs items={['React', 'Angular']} defaultIndex={0}>
<Tab value="React">

```text
reports@1.0.0 failed to mount App: expected the supplied basePath "" passed through unchanged as
createRouter({ basepath }), received no basepath on the router.
```

**Fix.** Forward what your router factory receives: `createRouter({ basepath: basePath, … })`.

</Tab>
<Tab value="Angular">

Angular creates its router through the adapter, so it has no `makeRouter` callback to forward a base path through.
For an Angular boundary failure, keep route paths relative and give `mountApp` the full host URL in `initialEntries`.
Do not replace the adapter's location strategy through custom providers.

</Tab>
</Tabs>

</Callout>
