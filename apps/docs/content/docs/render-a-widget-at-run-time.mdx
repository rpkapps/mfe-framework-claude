---
title: 'Render a Widget chosen at run time'
description: 'Render DynamicWidget when the Widget id is a value, and hear every output by name.'
---

Render a Widget selected at run time with React's `DynamicWidget` or Angular's `<mfe-widget>`. Both deliver each output by name.

## Steps

<Steps>

<Step>

### 1. Read what the registry offers

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```ts title="apps/shell/src/shell/dashboard/page.tsx (trimmed)"
import { useWidgets } from '@company/mfe-react'

const widgets = useWidgets()
```

</Tab>
<Tab value="Angular">

```ts title="src/widget-picker.component.ts"
import { injectWidgets } from '@company/mfe-angular'

// Component field initializer; read widgets() in the template.
readonly widgets = injectWidgets()
```

</Tab>
</Tabs>

Each entry carries `id`, `title`, `description`, `tags`, `icon` and `contract`, and all of it is
readable before any container is fetched.

</Step>

<Step>

### 2. Render the Widget by id

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="apps/shell/src/shell/dashboard/tile.tsx (trimmed)"
import { DynamicWidget } from '@company/mfe-react'

;<DynamicWidget
  widgetId={tile.widgetId}
  {...tile.inputs}
  onOutput={onOutput}
  pending={<MountingSkeleton />}
  fallback={({ error, retry }) => (
    <div role="alert">
      <p>{error.message}</p>
      <Button onClick={retry}>Retry</Button>
    </div>
  )}
/>
```

</Tab>
<Tab value="Angular">

```ts title="src/dynamic-tile.component.ts"
import { Component, signal } from '@angular/core'
import { MfeWidgetComponent, type MfeWidgetOutput } from '@company/mfe-angular'

@Component({
  selector: 'dynamic-tile',
  imports: [MfeWidgetComponent],
  template: `<mfe-widget
      [widgetId]="widgetId()"
      [inputs]="inputs()"
      (output)="onOutput($event)"
      [pending]="loading"
      [fallback]="failed"
    />
    <ng-template #loading>Loading Widget…</ng-template>
    <ng-template #failed let-error let-retry="retry">
      <p>{{ error.message }}</p>
      <button (click)="retry()">Retry</button>
    </ng-template>`,
})
export class DynamicTile {
  readonly widgetId = signal('alert-panel')
  readonly inputs = signal<Record<string, unknown>>({ alertId: 'a-1001' })
  readonly outputs = signal<MfeWidgetOutput[]>([])
  onOutput(event: MfeWidgetOutput) {
    this.outputs.update(events => [event, ...events])
  }
}
```

</Tab>
</Tabs>

React spreads collected inputs into `DynamicWidget`. Angular binds an input object. The Widget validates every supplied value.

</Step>

<Step>

### 3. Handle every output by name

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx
const onOutput = useCallback((name: string, payload: unknown) => {
  setOutputs(current => [{ name, payload, at: Date.now() }, ...current])
}, [])
```

</Tab>
<Tab value="Angular">

```ts title="src/dynamic-tile.component.ts"
import { signal } from '@angular/core'
import type { MfeWidgetOutput } from '@company/mfe-angular'

// Members of the component hosting <mfe-widget>.
readonly outputs = signal<MfeWidgetOutput[]>([])
onOutput(event: MfeWidgetOutput) {
  this.outputs.update(events => [event, ...events])
}
```

</Tab>
</Tabs>

React's `onOutput` receives a name and payload. Angular's `(output)` receives one object containing both. Call
`describeOutputs(entry.contract)` to list the names and each payload's fields.

</Step>

</Steps>

## Check it works

Run `pnpm dev` and open the shell at `http://localhost:3000`. Add a Widget from the dashboard
catalogue, fill in its inputs, and watch the activity list record what it emits. The inputs dialog
comes from `contract.inputSchema`, and each output's tooltip from `contract.outputSchema`. Change `widgetId`
and the old mount is replaced rather than handed the new Widget's inputs.

## Errors

<Callout type="error" title="registry/invalid-entry">

```text shared
alert-panel failed to resolve Widget: no registry entry with this id.
```

**Fix.** Check the id you passed against the registry. Give every tile a `fallback`, because a
saved layout outlives the registry that produced it.

</Callout>

<Callout type="error" title="contract/input-mismatch">

```text shared
alert-panel@1.4.0 failed to accept input severity: "urgent"; ✖ Invalid option: expected one of "info"|"warning"|"critical"
  → at severity.
```

**Fix.** Offer only what the published schema allows. A `z.enum([…])` in the schema is a fixed
list of choices.

</Callout>
