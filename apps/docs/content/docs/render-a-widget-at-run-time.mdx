---
title: 'Render a Widget chosen at run time'
description: 'Render DynamicWidget when the Widget id is a value, and hear every output by name.'
---

When the id is a value rather than a name in your source, render `DynamicWidget`. It takes the id
as a prop and delivers every declared output by name.

## Steps

<Steps>

<Step>

### 1. Read what the registry offers

```ts title="apps/shell/src/shell/dashboard/page.tsx (trimmed)"
import { useWidgets } from '@company/mfe-react'

const widgets = useWidgets()
```

Each entry carries `id`, `title`, `description`, `tags`, `icon` and `contract`, and all of it is
readable before any container is fetched.

</Step>

<Step>

### 2. Render the Widget by id

```tsx title="apps/shell/src/shell/dashboard/tile.tsx (trimmed)"
import { DynamicWidget } from '@company/mfe-react'

;<DynamicWidget
  widgetId={tile.widgetId}
  {...tile.inputs}
  onOutput={onOutput}
  pending={<MountingSkeleton />}
  fallback={({ error, retry }) => (
    <div role="alert">
      <p>{error.message}</p>
      <Button onPress={retry}>Retry</Button>
    </div>
  )}
/>
```

Spread the inputs you collected: `DynamicWidget` takes no contract, and the Widget validates
every input it is handed.

</Step>

<Step>

### 3. Handle every output by name

```tsx
const onOutput = useCallback((name: string, payload: unknown) => {
  setOutputs(current => [{ name, payload, at: Date.now() }, ...current])
}, [])
```

`onOutput` receives each declared output as a name and a payload. Call
`describeOutputs(entry.contract)` to list the names and each payload's fields.

</Step>

</Steps>

## Check it works

Run `pnpm dev` and open the shell at `http://localhost:3000`. Add a Widget from the dashboard
catalogue, fill in its inputs, and watch the activity list record what it emits. The inputs dialog
comes from `contract.inputSchema`, and each output's tooltip from `contract.outputSchema`. Change `widgetId`
and the old mount is replaced rather than handed the new Widget's inputs.

## Errors

<Callout type="error" title="registry/invalid-entry">

```text
alert-panel failed to resolve Widget: no registry entry with this id.
```

**Fix.** Check the id you passed against the registry. Give every tile a `fallback`, because a
saved layout outlives the registry that produced it.

</Callout>

<Callout type="error" title="contract/input-mismatch">

```text
alert-panel@1.4.0 failed to accept input severity: "urgent"; ✖ Invalid option: expected one of "info"|"warning"|"critical"
  → at severity.
```

**Fix.** Offer only what the published schema allows. A `z.enum([…])` in the schema is a fixed
list of choices.

</Callout>
