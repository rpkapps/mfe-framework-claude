---
title: 'Evolve a shared-state schema'
description: 'Add a comparison mode while older Apps keep reading and writing the selected well.'
---

The independently versioned contract package already defines a well and a run. Now one App needs a comparison mode, but the
other Apps have not been updated yet. Add the field with a default so those Apps can keep using
the selection they already know.

## Steps

<Steps>
<Step>
### 1. Update the schema in its owning package

```ts shared title="Illustrative contract repository: src/index.ts (selection fields)"
z.strictObject({
  wellId: z.string(),
  runId: z.string().nullable(),
  comparisonMode: z.enum(['baseline', 'overlay']).default('baseline'),
})
```

An existing selection without `comparisonMode` reads as `baseline`. Once the user chooses
`overlay`, an older App writing `{ runId: 'run-8' }` keeps that choice. The older App does not have
to know about the new field to preserve it.

You can also add an optional field. Keep the fields existing Apps depend on: renaming `wellId`
would leave them unable to read it. Changes to existing types, defaults, enums, validation rules
or array items need a new key and a plan to move the Apps that use it.

</Step>
<Step>
### 2. Configure the production release check

The production build needs a policy file with two fields. `schema` is the new compiled schema.
`baselines` contains copies of the schemas you have already released. Keep those released copies
unchanged. For the first release, the list is empty: `baselines: []`.

Publish that policy as `@acme/shared-state-contracts/release-policy.json` alongside the compiled schema,
authoring declaration and `shared-state.manifest.json`. The package name is illustrative.
Preserve released baselines in contract-package CI rather than recreating an empty list on each release.

Each consumer repository installs a released package version. Its build resolves the policy from that installed release.
The running shell needs only the current `sharedState.schema`.

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

Pass the policy to your existing `pluginMfe()` call:

```ts title="Illustrative rsbuild.config.ts (MFE plugin)"
import { createRequire } from 'node:module'
import { pluginMfe } from '@company/mfe-rspack'

const require = createRequire(import.meta.url)
pluginMfe({
  sharedStatePolicy: require.resolve('@acme/shared-state-contracts/release-policy.json'),
})
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative webpack.config.ts"
import { createRequire } from 'node:module'
import { withMfe } from '@company/mfe-nx/webpack'

const require = createRequire(import.meta.url)
export default withMfe({
  sharedStatePolicy: require.resolve('@acme/shared-state-contracts/release-policy.json'),
})
```

</Tab>
</Tabs>

Build, test and publish the updated contract in its owning repository. Each consumer updates its dependency and lockfile independently.
Run production builds in each consumer's own CI. React uses its build script. Angular uses its Nx project's production target. If it reports a changed field that older Apps depend on,
fix that change before publishing. A successful development build does not perform the same
release check.

</Step>
<Step>
### 3. Deploy the shell schema before the new consumer

Update the shell and backend to the published contract release, then deploy them first. Then deploy the App that uses
`comparisonMode`. Older Apps continue to work with that schema. Deploying the App first would
leave it asking the old shell for a field the shell does not have, so it would fail to mount.

</Step>
</Steps>

## Check it works

Run an older and a newer consumer against the current schema. Set the new comparison field from
the newer one, then change only `runId` from the older one. Both should read the updated run and
the preserved comparison mode. Try the new consumer against the old shell and confirm mounting fails.

## Errors

<Callout type="error" title="shared-state/missing-baseline, at production build">

```text shared
shared-state/missing-baseline: Production builds require sharedStatePolicy with explicit baselines and the current schema; use baselines: [] only for a first release
```

**Fix.** Provide the release policy path and ensure the file is available to the build. A first release
still needs an explicit policy with an empty baseline list.

</Callout>

<Callout type="error" title="An incompatible schema change">
  Read the key and field named by the build diagnostic. **Fix.** Restore its compatible shape or
  introduce a new key. Suppressing lint does not bypass the build check.
</Callout>
