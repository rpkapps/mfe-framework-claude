---
title: 'Undeploy or roll back'
description: 'Take a container out or put an earlier build back, and know what open pages see.'
---

Rolling back is a redeploy under the same id, and undeploying is one entry removed from the
registry. What people see depends on whether their page loaded before or after the change.

## Steps

<Steps>

<Step>
### 1. Roll back by redeploying the earlier build

<Tabs items={['React', 'Angular']} defaultIndex={0}>
<Tab value="React">

```sh
git checkout v2.0.3
pnpm install --frozen-lockfile
pnpm run build
```

</Tab>
<Tab value="Angular">

```sh
git checkout v2.0.3
pnpm install --frozen-lockfile
pnpm exec nx build operations --configuration=production
```

</Tab>
</Tabs>

Publish that build to the same origin under the same id, and register its record again.

</Step>

<Step>
### 2. Undeploy by removing the entry

Remove the container record through your platform's registry integration. Publish the updated registry from the shell repository or registry service. Remove every definition exported by the container.

Your platform owns this registry update.

</Step>

<Step>
### 3. Publish the registry update independently

Verify the registry your shell fetches no longer contains the removed definitions. For a rollback, supply the earlier artifact's generated `mfe-registry.json` and its deployment origin instead.

Prefer redeploying a retained release artifact. If rebuilding an earlier tag, use that container repository's lockfile and dependency versions. Keep old chunks reachable while open pages still reference them.

</Step>

<Step>
### 4. Expect the stored records to stay

```text shared
lab:draft
lab:visits
```

Removing an entry removes no storage, so a redeploy under the same id reads these keys back.

</Step>

</Steps>

## Check it works

Reload the shell. Your definition is gone from the developer tools' **Registry** tab, and no page
loading now reaches it. What everyone else gets depends on when their page loaded.

| Who                                  | What they get                                                |
| ------------------------------------ | ------------------------------------------------------------ |
| a page loaded after the change       | the failure box, code `registry/invalid-entry`               |
| an open tab yet to load you          | the failure box with **Retry**, code `load/manifest-failure` |
| an open tab with your Widget mounted | nothing. It runs until that page reloads                     |
| a saved dashboard in this shell      | the tile marked "not in the registry"                        |

## Errors

<Callout type="error" title="registry/invalid-entry">

```text shared
operations failed to resolve App: no registry entry with this id.
```

**Fix.** Nothing, when you meant to remove it. If you did not, register the container's record
again, or point the id at a dev server with a local override.

</Callout>

<Callout type="error" title="load/manifest-failure">

```text shared
Check that https://operations.example.com/mf-manifest.json is reachable and serves a valid manifest.
```

**Fix.** A tab that loaded before the removal still holds the old entry. Reload the page, or leave
the container's files reachable until those tabs have gone.

</Callout>
