---
title: 'Open the devtools panel'
description: 'Open the panel that lists what the shell registered, where each container loaded from, and what it rejected.'
---

Apps and Widgets. A shell can enable the framework developer tools package. The panel described here
uses the supplied shell integration. Ask your shell team if its deployment exposes different controls.
The tools tell you which containers the shell registered, which URL each one loaded from, and which entries
it set aside.

## Steps

<Steps>

<Step>

### 1. Open the panel

Press <Kbd>g</Kbd> <Kbd>d</Kbd> for the **Overrides** tab, or <Kbd>g</Kbd> <Kbd>r</Kbd> for the
**Registry** tab. Either shortcut turns the tools on and remembers it. The command palette
(<Kbd>⌘</Kbd> <Kbd>K</Kbd>) has "Open the registry" too.

</Step>

<Step>

### 2. Or turn them on from the address bar

```text shared
https://shell.example.test/?devtools=1
```

Use your shell's actual origin. `?devtools=0` turns them off again. The answer is kept under the `company:mfe:devtools` key, so the
next page load needs no parameter.

</Step>

<Step>

### 3. Read the tab you need

| Tab                     | What it shows                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------- |
| **Overrides**           | every registered definition, where it loaded from, and the actions that repoint it                      |
| **Registry → Loaded**   | each accepted entry: id, version, origin, and the pages, inputs and outputs it declares                 |
| **Registry → Rejected** | each entry the shell set aside, the message that says why, and the record as published                  |
| **Storage**             | the user storage load, and every user value by owner and key: its status, stored data, row and revision |

Both registry views carry a count, so a missing container is one glance.

In **Storage**, filter the key list and click a row to inspect it. In a narrow dock, use the
searchable key picker instead. **Stored data** shows the decoded value, or the value being saved,
and **Row** shows the `{ v, d, revision }` the backend holds. Copy controls copy the complete JSON.

The tab is read only, and it covers the `user` area: local and session values are in the browser's
own developer tools. A failed load shows its error with **Retry**, and a failed save shows on its key. A shell without a
`storage.user` adapter shows an explanatory empty state.

</Step>

<Step>

### 4. Put the panel where you want it

Drag the inner edge to resize it, and use **Panel position** to dock it top, right, bottom or left.
**Outline the micro-frontends** draws a box round every App and Widget on the page, and stays on
when you close the panel.

</Step>

</Steps>

## Check it works

The panel docks along the bottom, with the tabs in its header. Closing it leaves a wrench button in
the bottom-left corner, which carries a mark while an override is active. Your dock side, size and
tab are remembered. The palette's "Report a bug" collects the same facts as
Markdown. It carries every rejected entry and every override, for a colleague who cannot open the
page.
