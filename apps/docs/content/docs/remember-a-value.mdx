---
title: 'Store a value'
description: 'Declare a stored key once, then read and write it in local, session or user storage with one API.'
---

Keep a preference across reloads, for one tab, or for the signed-in user on every device. Declare
the value once as a key, then read and write it with React's `useStoredState` or Angular's
`injectStoredState`. Apps and Widgets.

<Diagram
  src="/diagrams/capability-storage.svg"
  alt="React and Angular consumers read and write stored keys through the runtime's storage service."
  caption="The shell supplies storage. Your definition owns its values."
>
  The runtime gives each mount one storage service. React reads a subscribed value through
  `useStoredState`. Angular reads signals through `injectStoredState`. Both validate writes against
  the key's schema. Local and session values live in the browser; user values live in the shell's
  backend.
</Diagram>

## Choose where to store a value

| Need                                                 | Use                                                                         |
| ---------------------------------------------------- | --------------------------------------------------------------------------- |
| A preference for this browser, such as a table split | `storage: 'local'`, the default                                             |
| A draft for this tab alone                           | `storage: 'session'`                                                        |
| A preference that follows the user to every device   | `storage: 'user'`, which the shell [provides](/docs/configure-user-storage) |
| A value another App or the shell owns                | [`storedKey.from`](#read-another-apps-value), read-only                     |
| Data for one hosted Widget                           | [Widget inputs and outputs](/docs/define-inputs-and-outputs)                |

| Area      | Lives in                       | Shared across          | Survives sign-out        |
| --------- | ------------------------------ | ---------------------- | ------------------------ |
| `local`   | the browser's `localStorage`   | tabs of this browser   | yes, per browser profile |
| `session` | the browser's `sessionStorage` | this tab only          | until the tab closes     |
| `user`    | the shell's backend            | every device, per user | yes, per user            |

<Callout type="warning" title="Local and session values survive sign-out">
  The next user of this browser profile reads them. Anything personal belongs in `user` storage.
</Callout>

## Steps

<Steps>
<Step>
### 1. Declare the key once

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```ts title="src/storage.ts"
import { storedKey } from '@company/mfe-react'
import { z } from 'zod'

export const density = storedKey(
  'table-density',
  z.enum(['comfortable', 'compact']).default('comfortable'),
)

export const units = storedKey('units', z.enum(['metric', 'imperial']).default('metric'), {
  storage: 'user',
})
```

</Tab>
<Tab value="Angular">

```ts title="src/storage.ts"
import { storedKey } from '@company/mfe-angular'
import { z } from 'zod'

export const density = storedKey(
  'table-density',
  z.enum(['comfortable', 'compact']).default('comfortable'),
)

export const units = storedKey('units', z.enum(['metric', 'imperial']).default('metric'), {
  storage: 'user',
})
```

</Tab>
</Tabs>

The schema needs a `.default(...)`, and that default is what an absent value reads as. Your App owns
every key it declares, and only the owner writes.

</Step>
<Step>
### 2. Read and write it

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="src/routes/index.tsx"
import { useStoredState } from '@company/mfe-react'

import { density } from '../storage.ts'

// Inside your component.
const { value, set } = useStoredState(density)

set(current => (current === 'compact' ? 'comfortable' : 'compact'))
```

</Tab>
<Tab value="Angular">

```ts title="src/table.component.ts"
import { injectStoredState } from '@company/mfe-angular'

import { density } from './storage'

// Inside your component class, in an injection context.
readonly tableDensity = injectStoredState(density)

toggle(): void {
  void this.tableDensity.set(current => (current === 'compact' ? 'comfortable' : 'compact'))
}
```

Read `tableDensity.value()` in your template.

</Tab>
</Tabs>

`set` takes a value or an updater, validates the result against the schema, and returns a promise.
`reset()` removes the stored value, so the key reads its default again.

</Step>
<Step>
### 3. Show the status of a user value

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="src/units-picker.tsx"
const { value, set, status, error, retry } = useStoredState(units)

return (
  <>
    <UnitsSelect value={value} disabled={status === 'loading'} onChange={next => set(next)} />
    {status === 'error' && <RetryNotice message={error?.message} onRetry={retry} />}
  </>
)
```

</Tab>
<Tab value="Angular">

```ts title="src/units-picker.component.ts"
readonly unitsState = injectStoredState(units)
// unitsState.value(), unitsState.status() and unitsState.error() are signals.
// unitsState.retry() loads again after a failed load, or sends a failed save again.
```

</Tab>
</Tabs>

The value is always a `T`: the schema default while loading or after an error, never `undefined`.
A `user` write renders at once, shows `saving`, and rolls back with `error` if the save fails.

</Step>
</Steps>

## Read another app's value

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="src/storage.ts"
export const labUnits = storedKey.from(
  'lab',
  'units',
  z.enum(['metric', 'imperial']).default('metric'),
  {
    storage: 'user',
  },
)

// Inside a component: no `set` or `reset` on a read-only key.
const { value } = useStoredState(labUnits)
```

</Tab>
<Tab value="Angular">

```ts title="src/storage.ts"
export const labUnits = storedKey.from('lab', 'units', z.enum(['metric', 'imperial']).default('metric'), {
  storage: 'user',
})

// In a component field: no `set` or `reset` on a read-only key.
readonly fromLab = injectStoredState(labUnits)
```

</Tab>
</Tabs>

The first argument is the owner's definition id, or `@host` for the shell's own values. Only `user`
values can be read this way. You bring your own schema and default, so you never import the owner's
code. A value that fails your schema reads as your default with status `error`.

Pass `select` to re-render only when part of a value changes:
`useStoredState(filters, { select: f => f.well })`. Angular takes the same option. `set` still
takes the whole value.

## Read or write outside render

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="src/routes/wells.tsx"
// A route loader: get() waits for user storage to load.
loader: async ({ context }) => {
  const selection = await context.mfe.storage.get(wellSelection)
  return fetchWell(selection.wellId)
}

// A handler: use the setter the component already holds.
const { set: setUnits } = useStoredState(units)
await setUnits('imperial')
```

</Tab>
<Tab value="Angular">

```ts title="src/wells.resolver.ts"
import { injectMfeMount } from '@company/mfe-angular'

export const wellResolver: ResolveFn<Well> = async () => {
  // Capture before any await.
  const { storage } = injectMfeMount()
  const selection = await storage.get(wellSelection)
  return fetchWell(selection.wellId)
}
```

</Tab>
</Tabs>

The mount's `storage` has `get`, `peek`, `set`, `reset`, `subscribe` and `status`, keyed by the same keys.
`peek` is synchronous and returns the default while user storage is still loading.

## Check it works

Reload the page. The value is still on screen. For a local value, open the browser developer tools,
then Application, then Local storage, and look for `operations:table-density`. For a user value,
open the devtools **Storage** tab and find the key under your definition id. Two mounts of one
definition agree on the value.

<Details summary="Give each Widget tile its own value">

Two copies of a Widget read the same stored value by default. To keep a tile's value separate,
give it an `instanceId` in the host:

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx
<DynamicWidget widgetId="well-view" instanceId="dashboard-east-well" />
```

</Tab>
<Tab value="Angular">

```html title="Illustrative Angular host template"
<mfe-widget widgetId="well-view" instanceId="dashboard-east-well" />
```

</Tab>
</Tabs>

Inside the Widget, declare the key with `perInstance: true`:

```ts shared title="src/storage.ts"
export const camera = storedKey('camera', cameraSchema.default(defaultCamera), {
  perInstance: true,
})
```

It works in every area. Reuse the ID when the tile returns after a reload, and keep `user` IDs
stable across devices, such as a dashboard tile id. Reading a `perInstance` key without a host ID
throws `storage/invalid-value`.

</Details>

## Errors

<Callout type="error" title="storage/invalid-value, at write">

```text shared
lab failed to write a stored value density: expected a value matching the key's schema (…),
received "dense". Fix the value passed to set() for 'density'. The stored value is unchanged.
```

**Fix.** Pass a value the schema accepts. The promise rejects and the old value stays.

</Callout>

<Callout type="error" title="storage/not-ready, at write">

```text shared
lab failed to save a user value units: expected the user's stored values to have loaded, received
a failed load. Wait for status "ready", or call retry() after a failed load.
```

**Fix.** Show the `error` status and offer `retry()`. Writes resume once a load succeeds.

</Callout>

<Callout type="error" title="storage/invalid-value, at bind">

```text shared
well-view failed to bind a stored key camera: expected a stable host-supplied instanceId for a
perInstance key, received undefined.
```

**Fix.** Pass `instanceId` where the host places the Widget, or drop `perInstance`.

</Callout>

<Callout type="error" title="storage/persistence-failed, at write">

```text shared
lab failed to write the local storage key draft: …QuotaExceededError… The stored value is unchanged.
```

**Fix.** Store an identifier and fetch the body again, or reset values you no longer need.

</Callout>
