---
title: 'Browser storage'
description: 'Store local or session preferences, read them in handlers and routes, and keep Widget instances separate.'
---

Keep a browser preference across reloads with React's `useStoredState` or Angular's `injectStoredState`.
Apps and Widgets store it under their own definition id.

<Diagram
  src="/diagrams/capability-storage.svg"
  alt="React and Angular consumers receive scoped browser storage from the shell runtime."
  caption="The shell supplies storage. Your definition owns its records."
>
  The shell runtime provides each mount with scoped browser storage. React reads a subscribed value
  through `useStoredState`. Angular reads a signal through `injectStoredState`. Both validate writes
  against your schema. The shell's own records have a separate scope.
</Diagram>

## Choose where to store a value

| Need                                                    | Use                                                          |
| ------------------------------------------------------- | ------------------------------------------------------------ |
| A preference for one definition in this browser         | This guide's local storage                                   |
| A preference for this tab                               | `storage: 'session'`                                         |
| A selection shared with the shell or another definition | [Shared state](/docs/shared-state), with backend persistence |
| Data for one hosted Widget                              | [Widget inputs and outputs](/docs/define-inputs-and-outputs) |

<Callout type="warning" title="Browser storage survives sign-out">
  The next user of this browser profile can read these records. Keep personal data out of browser
  storage.
</Callout>

## Steps

<Steps>
<Step>
### 1. Declare the schema at module scope

```ts shared title="examples/operations/src/routes/index.tsx"
import { z } from 'zod'

// Module scope: a schema rebuilt on every render rebinds the key on every render.
const densitySchema = z.enum(['comfortable', 'compact'])
```

The framework compares schemas by reference. Export one schema object per key from one module.

</Step>
<Step>
### 2. Bind the key

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="examples/operations/src/routes/index.tsx"
import { useStoredState } from '@company/mfe-react'

// Inside your component.
const [density, setDensity] = useStoredState('table-density', densitySchema, {
  defaultValue: 'comfortable',
})
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular component field"
import { injectStoredState } from '@company/mfe-angular'

// Inside your component class, in an injection context.
readonly density = injectStoredState('table-density', densitySchema, {
  defaultValue: 'comfortable',
})
```

Read `density.value()` in your template.

</Tab>
</Tabs>

The stored key is `operations:table-density`. An absent record reads as `comfortable`.

</Step>
<Step>
### 3. Write a value

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="examples/operations/src/routes/index.tsx"
setDensity(current => (current === 'compact' ? 'comfortable' : 'compact'))
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular component method"
this.density.set(current => (current === 'compact' ? 'comfortable' : 'compact'))
```

</Tab>
</Tabs>

Both setters accept a value or an updater function. Both validate the result against the schema.

</Step>
<Step>
### 4. Keep it for this tab alone

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="examples/lab/src/routes/storage.tsx"
const [visits, setVisits] = useStoredState('visits', visitsSchema, {
  defaultValue: 0,
  storage: 'session',
})
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular component field"
readonly visits = injectStoredState('visits', visitsSchema, {
  defaultValue: 0,
  storage: 'session',
})
```

</Tab>
</Tabs>

`storage` defaults to `'local'`. `'session'` clears when the tab closes. The areas keep separate records with the same name.
Angular accepts the same `storage` option.

</Step>
</Steps>

## Read or write outside render

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="examples/lab/src/routes/storage.tsx"
import { useMfeStorage } from '@company/mfe-react'

// Capture inside your component. Use it in handlers or cleanups.
const local = useMfeStorage()
```

React loaders read the same handle from `context.mfe.storage.local` or `context.mfe.storage.session`.

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular component field"
import { injectMfeStorage } from '@company/mfe-angular'

readonly local = injectMfeStorage()
```

Use `this.local` in methods. A resolver captures `injectMfeStorage()` before any `await`.

</Tab>
</Tabs>

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```ts title="Illustrative handler using the density schema above"
const key = local.key('table-density', densitySchema)
const density = key.get()
key.set('compact')
key.remove()
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular handler using the density schema above"
const key = this.local.key('table-density', densitySchema)
const density = key.get()
key.set('compact')
key.remove()
```

</Tab>
</Tabs>

`get()` returns `null` for an absent record and does not subscribe. Writes update mounted consumers
of that key. Reuse the same schema and options as the rendered binding.

`local.clear()` removes definition-wide records for your definition. Pass `{ scope: 'instance' }`
to `key`, `remove` or `clear` for the current Widget instance's records.
The shell's `storage.clearDefinition(id)` clears that definition and its instances.

## Check it works

Reload the page. The value is still on screen. Open the browser developer tools, then Application,
then Local storage, and look for `operations:table-density`. Two mounts of one definition agree on the value. Write through the imperative handle and confirm the displayed value updates.

<Details summary="Give each Widget tile its own preferences">

Two copies of a Widget read the same stored value by default. To keep a tile's preference separate,
give it an `instanceId` in the host:

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx
<DynamicWidget widgetId="well-view" instanceId="dashboard-east-well" />
```

</Tab>
<Tab value="Angular">

```html title="Illustrative Angular host template"
<mfe-widget widgetId="well-view" instanceId="dashboard-east-well" />
```

</Tab>
</Tabs>

Inside the Widget, add `scope: 'instance'` to the key:

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx
const [camera, setCamera] = useStoredState('camera', cameraSchema, {
  defaultValue: defaultCamera,
  scope: 'instance',
})
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular component field"
readonly camera = injectStoredState('camera', cameraSchema, {
  defaultValue: defaultCamera,
  scope: 'instance',
})
```

</Tab>
</Tabs>

Reuse the ID when the tile returns after
a reload. A new ID starts a separate record. Reusing one shares its settings. Omitting `scope`
keeps reading the definition-wide value.

`scope: 'instance'` without a non-empty host ID throws `storage/failure`. The same rule applies
outside a mount, where there is no Widget instance.

</Details>

## Errors

<Callout type="error" title="storage/failure, at bind">

```text shared
lab failed to bind the local storage key draft: expected the same schema object every active
consumer already declared, received a different schema object.
```

**Fix.** Move the `z.object({ … })` out of the component body. Export it from one module, and
import it wherever the key is read.

</Callout>

<Callout type="error" title="storage/failure, at write">

```text shared
lab failed to write the local storage key draft: expected local storage to accept 2097152
characters, received QuotaExceededError: …
```

**Fix.** Store an identifier and fetch the body again, or clear this definition's records. The
stored value is unchanged.

</Callout>
