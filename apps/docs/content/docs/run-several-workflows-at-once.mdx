---
title: 'Run several of the same workflow at once'
description: 'Give each run of a workflow a key, such as a file id, so several uploads are traced at the same time.'
---

Apps and Widgets. A workflow name has one open run at a time, so a second `start()` abandons the first.
To trace several uploads at once, pass a key: `telemetry.workflow('upload', file.id)`. Each key gets a run of its own.
For the basics of telemetry, see [Events, errors and traces](/docs/telemetry).

```tsx title="src/upload-queue.tsx"
import { fetch } from '#mfe/fetch'
import { useTelemetry, type MfeTelemetry } from '@company/mfe-react'

async function uploadOne(telemetry: MfeTelemetry, file: QueuedFile) {
  const upload = telemetry.workflow('upload', file.id)
  upload.start({ bytes: file.blob.size })
  try {
    const body = file.blob
    const response = await fetch('files', { method: 'POST', body, headers: upload.headers() })
    if (!response.ok) throw new Error(`Upload failed: ${response.status}`)
    upload.succeed()
  } catch (error) {
    upload.fail(error)
  }
}

export function UploadQueue({ files }: { files: readonly QueuedFile[] }) {
  const telemetry = useTelemetry()
  const uploadAll = () => Promise.all(files.map(file => uploadOne(telemetry, file)))
  return <button onClick={() => void uploadAll()}>Upload {files.length} files</button>
}
```

```ts title="src/upload-queue.component.ts"
import { Component, input } from '@angular/core'
import { fetch } from '#mfe/fetch'
import { injectTelemetry } from '@company/mfe-angular'

@Component({
  selector: 'app-upload-queue',
  template: `<button (click)="uploadAll()">Upload {{ files().length }} files</button>`,
})
export class UploadQueueComponent {
  readonly files = input.required<readonly QueuedFile[]>()
  private readonly telemetry = injectTelemetry()

  async uploadAll(): Promise<void> {
    await Promise.all(this.files().map(file => this.uploadOne(file)))
  }

  private async uploadOne(file: QueuedFile): Promise<void> {
    const upload = this.telemetry.workflow('upload', file.id)
    upload.start({ bytes: file.blob.size })
    try {
      const body = file.blob
      const response = await fetch('files', { method: 'POST', body, headers: upload.headers() })
      if (!response.ok) throw new Error(`Upload failed: ${response.status}`)
      upload.succeed()
    } catch (error) {
      upload.fail(error)
    }
  }
}
```

## What the key does

- **The key only picks the run.** It is never recorded on a span, a log or a diagnostic. An order or file id is safe to use.
- **The same key twice is the same run.** Starting it again abandons the open run with that key, as without a key.
- **Each keyed workflow lives until the mount ends.** A mount that keys thousands of runs keeps thousands of small objects.

To tell runs apart in your backend, add an attribute you may record, such as `bytes` above.
Attributes are strings, numbers and booleans. Keep bodies, credentials and raw URLs out of them.

## Check it works

In a test, upload two files at once. Your test environment's `telemetry.spansNamed('upload')` then returns two spans, each in its own trace.
Neither span has an `mfe.span.end_reason` of `abandoned`.
