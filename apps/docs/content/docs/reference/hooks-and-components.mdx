`@company/mfe-react` is the one package an App or a Widget imports from. This page lists every export you call, in the order you are likely to need them. Each entry gives the signature, one example and the recipe that uses it.

## Shell state

These three read what the shell owns. Each subscribes to one field, so a theme change never rerenders a component that only reads the user.

### useUser

```ts
useUser(): ShellUser | null
useUser<T>(selector: (user: ShellUser | null) => T): T
```

Returns the signed-in user, or `null` when nobody is signed in. `ShellUser` carries `id`, `name` and the optional `email`, `accountId` and `tenantId`. It is data for rendering, not an authorization check.

```ts
const name = useUser(user => user?.name ?? 'Signed out')
```

### useGroups

```ts
useGroups(): readonly string[]
useGroups<T>(selector: (groups: readonly string[]) => T): T
```

Returns the group names the shell reports for the signed-in user.

```ts title="examples/lab/src/routes/actions.tsx"
const groups = useGroups()

useAction({
  name: 'export-results',
  label: 'Export results',
  description: 'Exports the simulation results to a file the user downloads.',
  canExecute: () =>
    groups.includes('well-planning.read')
      ? allow()
      : deny('You need the well-planning.read group to export.'),
  execute: () => {
    record('Exported the results')
  },
})
```

Recipe: [Add an action to the palette](/docs/add-an-action).

### useTheme

```ts
useTheme(): ShellTheme
useTheme<T>(selector: (theme: ShellTheme) => T): T
```

Returns `'light'` or `'dark'`. The shell owns the value, and your container follows it.

```ts
const theme = useTheme()
```

Recipe: [Follow the shell theme](/docs/follow-the-shell-theme).

## Mount services

These four read services the mount owns. Each needs a component your App or Widget renders.

### useBasePath

```ts
useBasePath(): string
```

Returns the URL prefix this App mount owns, as a literal string. A Widget owns no boundary and gets `''`. Use it for URLs you hand to another system, never for your own routes.

```ts
const basePath = useBasePath()
const shareUrl = new URL(`${basePath}/wells/${wellId}`, location.origin).href
```

Recipe: [Link to another App](/docs/link-to-another-app).

### useMfeSignal

```ts
useMfeSignal(): AbortSignal
```

Returns the signal that aborts when this mount is disposed. Pass it to `fetch`, to an event listener, or to anything else that has to stop with the mount.

```ts
const signal = useMfeSignal()
window.addEventListener('resize', onResize, { signal })
```

Recipe: [Cancel a request on unmount](/docs/cancel-a-request-on-unmount).

### useScopeRoot

```ts
useScopeRoot(): HTMLElement
```

Returns the element carrying this mount's `data-mfe-scope` attributes, which the container's scoped stylesheet matches. The runtime creates it around the element your definition renders into. Read it to measure the mount's region or to give a library a container inside the scope; never replace or restyle it.

```ts
const scopeRoot = useScopeRoot()
const observer = new ResizeObserver(onResize)
observer.observe(scopeRoot)
```

### useMfeStorage

```ts
useMfeStorage(area?: 'local' | 'session'): MfeStorage
```

Returns the imperative storage handle for this definition. `area` defaults to `'local'`. `MfeStorage` has `key(name, schema, options)`, `remove(name)` and `clear()`, and a bound key has `get()`, `set(value)` and `remove()`. `get()` does not subscribe, so rendered state uses `useStoredState` instead.

```ts title="examples/lab/src/routes/storage.tsx"
const local = useMfeStorage()
```

Recipe: [Read or write storage outside render](/docs/storage-outside-render).

### useTelemetry

```ts
useTelemetry(): MfeTelemetry
```

Returns the mount's telemetry handle. It has `event`, `debug`, `info`, `warn`, `error`, `measure` and `tracer`. The handle is stable for the mount's life, and emitting never causes a rerender.

```ts title="examples/lab/src/routes/telemetry.tsx"
const telemetry = useTelemetry()
```

Recipe: [Log an event](/docs/log-an-event).

## Shell features

### useAction

```ts
useAction<Input extends ActionInputSchema, Output>(
  registration: ActionRegistration<Input, Output>,
): ActionRun<Input, Output>
```

Publishes one action for as long as the component is rendered. The shell lists it in the command palette and offers it to its agent as a tool. It returns a stable function that runs the action with the caller `'ui'`, for your own button. The function runs this component's registration, even when another mount of your definition registered the same name.

| Field           | Type                                               | What it does                                                                                                                              |
| --------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `name`          | `string`                                           | Letters, digits and hyphens, starting with a letter. Unique within the mount.                                                             |
| `label`         | `string`                                           | The menu text. It must not be empty.                                                                                                      |
| `description`   | `string`, optional                                 | For the agent: what the action does and when to use it.                                                                                   |
| `execute`       | `(input, { signal }) => Output \| Promise<Output>` | Does the work. It receives the parsed input and a `signal` that aborts when the run is given up; what it returns is the result's `value`. |
| `canExecute`    | `() => Decision`, optional                         | Returns `allow()` or `deny(reason)`. A pure synchronous read of UI state, never an authorization check.                                   |
| `inputSchema`   | a `z.object`, optional                             | The values a call takes, checked before `execute` runs. Absent means the action takes none. Declare it at module scope.                   |
| `outputSchema`  | `z.ZodType<Output>`, optional                      | The value `execute` returns, checked after it runs.                                                                                       |
| `effect`        | `'read' \| 'write' \| 'destructive'`, optional     | What a run can change. Undeclared counts as `'write'`.                                                                                    |
| `needsApproval` | `boolean \| (input) => boolean`, optional          | Whether an agent's call waits for the user's approval. Absent, a `'read'` runs and anything else asks.                                    |
| `parallelSafe`  | `boolean`, optional                                | Lets an agent's write run beside another. Without it, an agent's writes run one at a time.                                                |
| `timeoutMs`     | `number`, optional                                 | How long an agent's call may run once `execute` starts, 30 seconds by default. Then it fails with `action/timeout`.                       |
| `followUp`      | `boolean`, optional                                | Whether the agent carries on once it has the result. Defaults to `true`.                                                                  |
| `placements`    | `('palette' \| 'agent')[]`, optional               | Where the action is offered. Absent is `['palette', 'agent']`, and `[]` lists it nowhere.                                                 |
| `shortcut`      | `string`, optional                                 | A chord such as `'mod+s'` or a sequence such as `'g r'`. It fires while the page is inside your App. A Widget's is ignored.               |

```ts title="examples/lab/src/routes/actions.tsx (trimmed)"
const simulationInput = z.object({ runs: z.number().int().min(1).max(1000).default(100) })

const runSimulation = useAction({
  name: 'run-simulation',
  label: 'Run the simulation',
  description: 'Runs the well-planning simulation. More runs take longer and smooth the result.',
  inputSchema: simulationInput,
  effect: 'read',
  canExecute: () => (armed ? allow() : deny('Arm the simulation first.')),
  execute: ({ runs }) => {
    record(`Ran the simulation ${runs} times`)
  },
})

void runSimulation({ runs: 10 })
```

A field changed on a later render is checked as it was at registration, and one the registry cannot accept throws. The returned run takes the input, which is optional when the schema accepts `{}`. It goes through the same steps as the palette, a shortcut and the agent: `canExecute`, then the input check, then `execute`. It resolves to an `ActionExecutionResult<Output>`:

| `status`      | Carries  | When                                                                                                                                                                                                          |
| ------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `executed`    | `value`  | `execute` ran. `value` is what it returned, parsed by `outputSchema` when there is one.                                                                                                                       |
| `denied`      | `reason` | `canExecute` refused. An agent's call is also denied when it is not placed for the agent, by the host's policy or a policy that throws, or when it needs approval and nothing can ask.                        |
| `declined`    | `reason` | The user was asked about an agent's call and said no.                                                                                                                                                         |
| `cancelled`   | `reason` | The caller stopped waiting before the run ended: the user pressed Stop in the chat.                                                                                                                           |
| `invalid`     | `error`  | The input did not match `inputSchema`, so nothing ran. The code is `contract/input-mismatch`.                                                                                                                 |
| `unavailable` | `error`  | The component that registered the action is gone, or went while a call waited, queued or ran.                                                                                                                 |
| `failed`      | `error`  | `execute` threw, an agent's call passed its deadline (`action/timeout`), its value did not match `outputSchema` (`contract/output-mismatch`), or a schema's own check or a host hook threw (`mount/failure`). |

The promise never rejects: every outcome is one of these results, and every run is audited once. When a run is given up (an agent's call passed its deadline, the component unmounted, or the user pressed Stop), the `signal` `execute` received aborts, and whatever `execute` returns afterwards is dropped. Approval applies to an agent's calls only. A user who runs the action from the palette, a shortcut or your button is its approval, so none of those asks. `ActionEffect`, `ActionInputSchema`, `ActionRun` and `ActionExecutionResult` are exported as types.

Recipe: [Add an action to the palette](/docs/add-an-action).

### allow and deny

```ts
allow(): Decision
deny(reason: string): Decision
```

Build the answer `canExecute` returns. `deny` takes the sentence the palette shows the user. An agent is told the same sentence.

Recipe: [Add an action to the palette](/docs/add-an-action).

### useAgentContext

```ts
useAgentContext<Schema extends z.ZodType>(registration: AgentContextRegistration<Schema>): void
```

Publishes a small snapshot of what is selected or open, for as long as the component is rendered. The shell's agent receives it with each chat turn. Call it on every render with the current value. An equal value publishes nothing.

| Field         | Type               | What it does                                                                                          |
| ------------- | ------------------ | ----------------------------------------------------------------------------------------------------- |
| `description` | `string`           | Tells the model what the value is, such as `'The wells the user has selected'`. It must not be empty. |
| `schema`      | `z.ZodType`        | Parses `value`. What it parsed is what the agent receives.                                            |
| `value`       | the schema's input | Ids and a short label: JSON, at most 4096 characters of it.                                           |

```ts title="examples/operations/src/routes/wells.$wellId.tsx (trimmed)"
const openWell = z.object({ id: z.string(), name: z.string() }).nullable()

useAgentContext({
  description: 'The well design the user has open, or null when its id is unknown',
  schema: openWell,
  value: design === undefined ? null : { id: design.id, name: design.name },
})
```

The agent receives an `AgentContextEntry`: `{ definitionId, description, value, capturedAt }`, where `capturedAt` is the ISO time the value last changed. A value that fails its schema, is not JSON or is too long is left out, and reported once as a warning with `contract/input-mismatch`. An empty `description` throws the same code on the first render. One that becomes empty later is left out and reported, as a bad value is. The entry goes when the component unmounts or the mount is disposed. Outside a mount, it belongs to the host page. Never publish whole records or secrets: offer a read action that takes the id instead.

Recipe: [Tell the agent what is selected](/docs/tell-the-agent-what-is-selected).

### useAgentPrompt

```ts
useAgentPrompt(): (prompt: AgentPrompt) => boolean
```

Returns a stable function that hands a click to the shell's chat as a turn. An `AgentPrompt` is `{ message, context?, submit? }`. The chat shows `message` and sends `context` unseen, under the same JSON size limit. `submit: false` fills the chat's input box for the user to review. `submit` defaults to `true`.

```tsx
const prompt = useAgentPrompt()

prompt({ message: `Why is ${design.name} behind plan?`, context: { wellId: design.id } })
```

The function returns whether a chat took the prompt. The runtime refuses an empty message, or a context that is not JSON or is too long. The function then returns `false` and reports a warning with `contract/input-mismatch`. It returns `false` when the shell has no chat, which is when its deployment names no agent backend (`AGENT_URL`). `AgentContextEntry`, `AgentContextRegistration` and `AgentPrompt` are exported as types.

Recipe: [Tell the agent what is selected](/docs/tell-the-agent-what-is-selected).

### useAgentSuggestions

```ts
useAgentSuggestions(suggestions: readonly AgentSuggestion[]): void
```

Offers prompts the chat shows as ways to start or carry on, while the component is mounted: before the first message, beside the shell's own, and after each answer while nothing waits on the user. An `AgentSuggestion` is an `AgentPrompt` with an optional `label`, the chip's text when shorter than the message. Pressed, a suggestion is handed to the chat as `useAgentPrompt` hands a prompt.

```tsx title="examples/operations/src/routes/index.tsx"
useAgentSuggestions([
  { message: 'Summarise the alternatives on this page' },
  { message: 'Open the wells inventory' },
])
```

Call it with the current list on every render; an equal list publishes nothing. A mount offers at most three. One that is empty, not JSON or too long is left out, and a warning with `contract/input-mismatch` is reported once. `AgentSuggestion` is exported as a type.

Recipe: [Tell the agent what is selected](/docs/tell-the-agent-what-is-selected).

### useBreadcrumbs

```ts
useBreadcrumbs(items: readonly BreadcrumbItem[]): void
```

Overrides this App's own part of the trail while the component is rendered. A `BreadcrumbItem` is `{ key, label, href?, current? }`. An empty array is no override, so a trail derived from your routes stays as it was.

```ts title="examples/lab/src/routes/breadcrumbs.tsx"
useBreadcrumbs(override ? FLOW : [])
```

Recipe: [Set breadcrumbs](/docs/set-breadcrumbs).

### useNavigationBlock

```ts
useNavigationBlock(shouldBlock: boolean | ((intent: NavigationIntent) => boolean)): NavigationBlock
```

Registers this mount as a navigation blocker. It returns `{ pending, proceed, stay }`. While `pending` is set, the mount stays mounted and renders its own confirmation. Inside an App, use TanStack's own `useBlocker` instead, which covers your own routes too.

```tsx
const block = useNavigationBlock(isDirty)

if (block.pending) {
  return <ConfirmLeave onLeave={block.proceed} onStay={block.stay} />
}
```

Recipe: [Block navigation when edits are unsaved](/docs/block-navigation-when-unsaved).

### useStoredState

```ts
useStoredState<T>(
  name: string,
  schema: z.ZodType<T>,
  options: { defaultValue: T; storage?: 'local' | 'session'; version?: number; migrate?: (value: unknown, fromVersion: number) => T },
): readonly [T, (next: T | ((current: T) => T)) => void]
```

Stored state that rerenders when the value changes. Declare the schema at module scope. An unreadable stored value throws, so the failure reaches an error boundary rather than looking like missing data. The record belongs to the browser, so a sign-out keeps it and the next user reads it.

```ts title="examples/lab/src/routes/storage.tsx"
const [draft, setDraft] = useStoredState('draft', draftSchema, {
  defaultValue: { note: '', pinned: false },
})
```

Recipe: [Remember a value across reloads](/docs/remember-a-value).

## Rendering a Widget

### lazyWidget

```ts
lazyWidget(widgetId: string): (props: LazyWidgetProps<undefined>) => ReactNode
lazyWidget<C extends WidgetContract>(widgetId: string, options: { contract: C }): (props: LazyWidgetProps<C>) => ReactNode
```

Returns a component for a Widget you name in your source. Call it once at module scope. Passing the Widget's published `contract` types the props and the `onX` handlers, and validates outputs on your side.

```ts title="examples/operations/src/widgets.ts"
import { lazyWidget } from '@company/mfe-react'

import { inputSchema, outputSchema } from '@example/alert-panel/contracts'

export const AlertPanel = lazyWidget('alert-panel', { contract: { inputSchema, outputSchema } })
```

The returned component takes the Widget's inputs as props and one `onX` handler per declared output. It also takes an optional `pending` node, shown while the container is fetched, and an optional `fallback({ error, retry })`.

Recipe: [Render a Widget inside your App](/docs/render-a-widget).

### DynamicWidget

```tsx
<DynamicWidget widgetId={string} onOutput={(name, payload) => void} pending={ReactNode} fallback={({ error, retry }) => ReactNode} {...inputs} />
```

Renders a Widget whose id is a value rather than a name in your source. It takes no contract, so outputs arrive by name through one `onOutput` handler. Changing `widgetId` replaces the mount rather than feeding new inputs to the old one.

```tsx title="apps/shell/src/shell/dashboard/tile.tsx"
<DynamicWidget
  widgetId={tile.widgetId}
  {...tile.inputs}
  onOutput={onOutput}
  pending={<MountingSkeleton />}
/>
```

Recipe: [Render a Widget chosen at run time](/docs/render-a-widget-at-run-time).

### describeInputs and describeOutputs

```ts
describeInputs(contract: PublishedContract | undefined): readonly WidgetInputField[] | null
describeOutputs(contract: PublishedContract | undefined): readonly WidgetOutput[] | null
```

Read the schemas a registry entry publishes in `contract`. A host uses them for a Widget whose contract it never imports. Both walk the JSON Schema with the same code, so an output's payload and another Widget's inputs are described the same way.

```ts title="apps/shell/src/shell/dashboard/input-schema.ts (trimmed)"
import { describeOutputs } from '@company/mfe-react'

const outputs = describeOutputs(entry.contract)
// [{ name: 'acknowledged', schema: {…}, payload: [{ name: 'alertId', kind: 'string', required: true, … }] }]
```

| Return value         | What it means                                                                                                                 |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `null`               | The build could not read the schema. Show it as unknown.                                                                      |
| `[]`                 | The Widget takes nothing, or emits nothing.                                                                                   |
| `WidgetInputField[]` | One field per input: `name`, `required`, `kind`, `nullable`, and any `enumValues`, `format`, `defaultValue` or `description`. |
| `WidgetOutput[]`     | One entry per declared output, in order: `name`, `schema` and `payload`.                                                      |

A `WidgetOutput`'s `payload` lists the payload's fields as `WidgetInputField`s. It is `null` when the build could not read that payload.

Three helpers work on the input fields:

- `defaultInputsFor(fields)` returns the defaults the schema declares.
- `coerceInputs(fields, values)` converts text from a form into the JSON types the schema asks for.
- `needsInputPrompt(contract)` says whether to ask for inputs before mounting.

`@company/mfe-angular` exports all five too.

Recipe: [Render a Widget chosen at run time](/docs/render-a-widget-at-run-time).

## Icons

### DefinitionIcon

```tsx
<DefinitionIcon icon={IconData} size={number} label={string} />
```

Draws the icon a registry entry carries. `size` is the edge length in pixels and defaults to `24`. Without `label` the icon is decoration and stays hidden from assistive technology. Only `path`, `circle`, `rect`, `line`, `polyline`, `polygon`, `ellipse` and `g` are drawn, and anything else in the record is dropped.

```tsx title="apps/shell/src/shell/dashboard/tile.tsx"
<DefinitionIcon icon={entry.icon} size={16} className="shrink-0 text-muted-foreground" />
```

Recipe: [Show an icon](/docs/show-an-icon).

## Host-side exports

These place or compose containers. A shell calls them. An App calls `mfeRoute` when it nests a child App at a splat route, and nothing else here.

| Export                                                                  | Signature                                  | What it is for                                         |
| ----------------------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------ |
| `AppHost`                                                               | `{ appId, basePath, fallback?, pending? }` | Mounts an App at a boundary the caller chooses.        |
| `mfeRoute`                                                              | `({ appId, basePath? })`                   | Route options that mount a child App. The author path. |
| `MfeProvider`                                                           | `{ runtime, children }`                    | Wraps a shell once at boot.                            |
| `createContainerTransport`, `installShellAuth`                          | see `@company/mfe-runtime`                 | Bind the shell's session to `#mfe/fetch`.              |
| `withStyleRoot`                                                         | —                                          | Used by generated code.                                |
| `createOverlayRoot`, `SCOPE_ATTRIBUTE` (from `@company/mfe-react/host`) | —                                          | Used by the shell's own chrome.                        |

`AppHost`, `DynamicWidget` and the component `lazyWidget` returns render an empty element and mount the definition into it through the runtime's `mountDefinition`, whichever framework built it; a React definition opens a React root of its own there. `pending` fills the region while the container loads and the definition mounts, and `fallback` replaces it after a failure, with a `retry`. Without a `fallback` the failure is thrown to the nearest error boundary. Nothing suspends.

A shell boots from `@company/mfe-react/host`: it re-exports the whole runtime surface — `createMfeRuntime`, `createFederationContainerLoader`, `DiagnosticsHub` and the rest — beside `MfeProvider`, so a shell imports its adapter and never `@company/mfe-runtime` itself. `@company/mfe-react/registry` exports `reactAdapter` alone, with no React import, for a shell written in another framework. `createMfeRuntime` registers no adapter implicitly; list every one in `adapters`.

## Where each hook may be called

| Hook                                                                                                                                            | Inside a mount | On the host page |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------- | ---------------- |
| `useUser`, `useGroups`, `useTheme`, `useAction`, `useAgentContext`, `useAgentPrompt`, `useAgentSuggestions`, `useBreadcrumbs`, `useStoredState` | yes            | yes              |
| `useBasePath`, `useMfeSignal`, `useMfeStorage`, `useScopeRoot`, `useTelemetry`, `useNavigationBlock`                                            | yes            | no               |

Called in the wrong place, a hook throws `mount/failure` and names itself.
