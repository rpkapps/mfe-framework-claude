Every term these pages use, defined once. Each entry says what the thing is and links to the page that explains it in context.

| Term                         | Meaning                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| adapter                      | An `MfeAdapter`: a `kind` such as `react`, `angular` or `legacy-angular`, a `detect` that recognises its own entries, a `parse` that reads one, an `is` guard onto its own fields, and optionally an `aroundLoad` around its containers' loads. The shell lists every adapter it serves. — [Adapters and legacy Angular](/docs/how-it-works/adapters-and-legacy-angular) |
| Angular adapter              | `@company/mfe-angular`: the Angular 19 adapter, zoneless and UI-library agnostic. Each Angular mount is an Angular application of its own. — [The Angular adapter](/docs/reference/angular-adapter)                                                                                                                                                                      |
| App                          | A micro-frontend that is routable: it owns a stretch of the URL and routes everything below it with its own TanStack Router instance. Declared with `createApp`. — [Create an App](/docs/create-an-app)                                                                                                                                                                  |
| base href kind               | How a legacy Angular app gets its `APP_BASE_HREF`. It is app-pinned when the app keeps its own, and delegated when the app takes the one single-spa supplies. — [Legacy Angular](/docs/reference/legacy-angular)                                                                                                                                                         |
| base path                    | The URL prefix one App mount owns, handed to your router factory as `AppRouterOptions.basePath`. Pass it straight into `createRouter({ basepath })`. — [Create an App](/docs/create-an-app)                                                                                                                                                                              |
| boundary                     | The stretch of URL assigned to one App mount. The shell owns `/<id>`, and everything below it belongs to that App. — [Create an App](/docs/create-an-app)                                                                                                                                                                                                                |
| boundary history             | The `RouterHistory` the framework builds for one App mount and hands to your factory. It keeps two routers on one page from fighting over the URL. — [Create an App](/docs/create-an-app)                                                                                                                                                                                |
| breadcrumb                   | One item in the trail the shell's header renders. The shell contributes its own at the top, and an App contributes the rest from its router matches. — [Set breadcrumbs](/docs/set-breadcrumbs)                                                                                                                                                                          |
| BuildProvenance              | `{ hash, time }` on a registry entry, naming the build the container came from. It never gates loading, and its only reader is the bug report. — [Registry entry](/docs/reference/registry-entry)                                                                                                                                                                        |
| capability page              | A route the shell can open by name without loading its App first: `settings`, `help` or `releaseNotes`. Declare it with `staticData` on a file route. — [Add a settings page](/docs/add-a-settings-page)                                                                                                                                                                 |
| command                      | An action a mount publishes into the shell's command palette. The mount decides whether it may run, and the shell lists it and runs it. — [Add a command to the palette](/docs/add-a-command)                                                                                                                                                                            |
| container                    | One deployable unit: one package, one build, one deployed origin and one `src/mfe.ts`. It exports at most one App and any number of Widgets. — [Build and publish a container](/docs/build-and-publish)                                                                                                                                                                  |
| contract (inputs and events) | A Widget's two Zod schemas: `inputs`, one `z.object`, and `events`, a record of event name to payload schema. They drive runtime validation and the author-facing types. — [Define inputs and events](/docs/define-inputs-and-events)                                                                                                                                    |
| contract major               | The framework contract version a container was built against, declared as `mfe.contractMajor` on its registry entry. It is `1`, and the shell rejects any other value. — [Version your container](/docs/version-your-container)                                                                                                                                          |
| `data-tecton-root`           | The marker the design system's `ThemeRoot` puts on its element. The style root sets it on the mount's overlay root too, so the library's colours reach portalled content. — [Render dialogs, menus and tooltips](/docs/render-dialogs-and-tooltips)                                                                                                                      |
| deadline                     | A single total time budget for one lifecycle phase: load, mount or dispose. Every mount runs under the runtime's deadlines, 30, 30 and 5 seconds unless the shell tunes them. — [The mount lifecycle](/docs/how-it-works/the-mount-lifecycle)                                                                                                                            |
| definition                   | The plain, side-effect-free record `createApp` or `createWidget` returns. It is a value, so the build can read it without running a render function. — [createApp and createWidget options](/docs/reference/create-app-and-create-widget)                                                                                                                                |
| definition id                | Your screen's name everywhere: lower-case letters, digits and single hyphens, for example `alert-panel`. It is also the storage prefix and the CSS scope value. — [Naming and contract rules](/docs/reference/naming-and-contract-rules)                                                                                                                                 |
| deployment                   | One place a container's build is serving from, with its own `runtime-config.json` published beside its assets. One build is deployed many times. — [Supply values per deployment](/docs/supply-values-per-deployment)                                                                                                                                                    |
| `DEV`                        | `process.env['NODE_ENV'] !== 'production'`, spelled literally so a bundler folds the guarded statement away in a production build. — [What you must not do](/docs/what-you-must-not-do)                                                                                                                                                                                  |
| depth                        | How deeply a mount is nested: the shell is 0, a top-level App 1, an App nested inside it 2. — [The mount lifecycle](/docs/how-it-works/the-mount-lifecycle)                                                                                                                                                                                                              |
| diagnostics hub              | The fan-out point every framework validation and lifecycle failure reaches, which calls every registered sink. A sink that throws cannot stop the others. — [Report an error](/docs/report-an-error)                                                                                                                                                                     |
| `DynamicWidget`              | The component for a host that learns which Widgets exist only at run time, from the registry. It takes the id as a prop and adds `onEvent(name, payload)`. — [Render a Widget chosen at run time](/docs/render-a-widget-at-run-time)                                                                                                                                     |
| expose name                  | The generated Module Federation path a definition is published at: `./app` for an App, `./widgets/<id>` for a Widget. — [Registry entry](/docs/reference/registry-entry)                                                                                                                                                                                                 |
| generated output             | Everything the build writes into `.mfe/`, plus `routeTree.gen.ts` and the shell's `registry.json`. None of it is committed, and `pnpm run generate` rebuilds all of it. — [CLI and scripts](/docs/reference/cli-and-scripts)                                                                                                                                             |
| host page                    | The document the shell owns, treated as one scope for storage, commands and breadcrumbs. — [Share a value with the shell](/docs/share-a-value-with-the-shell)                                                                                                                                                                                                            |
| `/host` entry point          | `@company/mfe-react/host` or `@company/mfe-angular/host`: the runtime's whole host surface plus that framework's provider. A shell boots from it and never imports the runtime itself. — [Hooks and components](/docs/reference/hooks-and-components)                                                                                                                    |
| `@host` scope                | The scope name for state the page owns. The `@` keeps it reserved, because a definition id holds only lower-case letters, digits and single hyphens. — [Share a value with the shell](/docs/share-a-value-with-the-shell)                                                                                                                                                |
| `lazyWidget`                 | `lazyWidget(id, { contract? })`, called at module scope, returning a component. Call it during render instead and React remounts the Widget on every pass. — [Render a Widget inside your App](/docs/render-a-widget)                                                                                                                                                    |
| legacy Angular adapter       | `@company/mfe-legacy-angular`: the removable adapter that reads legacy single-spa Angular apps' registry entries into a typed entry, so no shell screen learns the legacy vocabulary. No host mounts a legacy app yet. — [Legacy Angular](/docs/reference/legacy-angular)                                                                                                |
| `#mfe/config`                | The module the build generates for a container with `src/mfe.config.ts`. It fetches the deployment's `runtime-config.json`, validates it, and exports the frozen, typed result. — [Read an environment variable](/docs/read-an-env-variable)                                                                                                                             |
| `MfeError`                   | The framework's structured error, carrying a machine-readable code, the definition id, the operation and one repair step. Its message is composed from five parts. — [Read a failure message](/docs/read-a-failure-message)                                                                                                                                              |
| `#mfe/fetch`                 | The module the build generates for every container, exporting `fetch` and `getAccessToken`. It attaches the session token to declared API origins only. — [Call your API](/docs/call-your-api)                                                                                                                                                                           |
| micro-frontend               | A piece of one web page that its own team builds, deploys and loads at run time into a page it does not own. One browser document, with each mount in a root of its own. — [Overview](/docs)                                                                                                                                                                             |
| Module Federation            | The bundler mechanism that lets one page load code from another build at run time. The shell registers each container as a remote and asks it for a module. — [Build and publish a container](/docs/build-and-publish)                                                                                                                                                   |
| mount                        | One live instance of a definition, with the token, depth, base path, telemetry, storage, scope root and overlay root it owns. Every host creates one with `mountDefinition`. Two mounts of one definition are independent. — [The mount lifecycle](/docs/how-it-works/the-mount-lifecycle)                                                                               |
| `mountDefinition`            | The one function every host calls to place a definition, whichever framework built it: it loads the definition, creates the roots and calls the definition's own `mount`. It lives in `@company/mfe-runtime`. — [The mount lifecycle](/docs/how-it-works/the-mount-lifecycle)                                                                                            |
| mount state                  | The lifecycle state of a mount: pending, mounted, error or disposed. A host reads it from the handle `mountDefinition` returns, and a React host shows `pending` or `fallback` from it. — [The mount lifecycle](/docs/how-it-works/the-mount-lifecycle)                                                                                                                  |
| mount token                  | The internal per-mount discriminator, `<definitionId>#<n>`, which tells two mounts of one definition apart. It is never public API. — [The mount lifecycle](/docs/how-it-works/the-mount-lifecycle)                                                                                                                                                                      |
| neutral runtime              | `@company/mfe-runtime`: the package that reads the registry through the adapters the shell lists, loads containers and mounts every definition. It imports no framework, router, single-spa or Module Federation. An application reaches it through its adapter's `/host`. — [Adapters and legacy Angular](/docs/how-it-works/adapters-and-legacy-angular)               |
| origin allowlist             | The exact set of `scheme://host:port` strings that may receive the session bearer token, built from your `env(…, { api: true })` declarations. There are no wildcards. — [Mark a URL as your API](/docs/mark-a-url-as-your-api)                                                                                                                                          |
| overlay root                 | A `<div>` the runtime appends to `document.body` per mount, carrying the same `data-mfe-scope` value as the scope root. Every overlay the container raises portals into it. — [Render dialogs, menus and tooltips](/docs/render-dialogs-and-tooltips)                                                                                                                    |
| override                     | A boot-time redirection of one definition's manifest URL to your dev server, read from `localStorage["company:mfe:overrides"]`. Changing one needs a page reload. — [Point the shell at your dev server](/docs/point-the-shell-at-your-dev-server)                                                                                                                       |
| parcel                       | The single-spa mount and unmount lifecycle the legacy adapter drives: `mountRootParcel`, then `parcel.mountPromise`, then `parcel.unmount()`. A remount creates a fresh parcel. — [Legacy Angular](/docs/reference/legacy-angular)                                                                                                                                       |
| React Refresh boundary       | A module a dev server can replace in place without reloading the page. React Refresh allows it only when every export of the module is a component. — [Keep hot updates working](/docs/keep-hot-updates-working)                                                                                                                                                         |
| registry                     | The JSON array the shell fetches at boot, naming every definition, where its container's manifest lives and what each Widget takes. It is generated, never hand-written. — [Registry entry](/docs/reference/registry-entry)                                                                                                                                              |
| registry entry               | The record one definition's build publishes: its id, kind, adapter and manifest URL, plus the optional version, capabilities, contract, build, title, description, tags and icon. — [Registry entry](/docs/reference/registry-entry)                                                                                                                                     |
| rejected entry (`rejected`)  | A registry entry no adapter could read. The registry sets it aside with a reason and an error, and every other entry still loads. — [Error codes](/docs/reference/error-codes)                                                                                                                                                                                           |
| remote entry                 | The JavaScript file a container publishes for a host to load code from: `remoteEntry.js`. `mf-manifest.json` describes it, and your registry entry points at that manifest. — [Build and publish a container](/docs/build-and-publish)                                                                                                                                   |
| reserved context keys        | `mfe` and `queryClient`: the two router-context keys an App forwards unchanged rather than replaces. — [Naming and contract rules](/docs/reference/naming-and-contract-rules)                                                                                                                                                                                            |
| reserved input names         | `key`, `ref` and `fallback`, plus anything matching `/^on[A-Z]/`. They belong to the host, so a Widget may not declare an input with one. — [Naming and contract rules](/docs/reference/naming-and-contract-rules)                                                                                                                                                       |
| retention                    | Who owns a stored record. `browser` is the default, and the framework never clears it. `user` is the opt-in the shell clears when the signed-in identity or the group set changes. — [Clear a value when the user changes](/docs/clear-a-value-on-sign-out)                                                                                                              |
| `runtime-config.json`        | The deployment's values, published next to the container's assets and never built into it. The generated loader resolves its URL against the container's own public path. — [Supply values per deployment](/docs/supply-values-per-deployment)                                                                                                                           |
| `@scope`                     | The CSS at-rule that bounds a block of rules to a subtree. The framework emits one per container, and no fallback exists for a browser without it. — [The isolation boundaries](/docs/how-it-works/the-isolation-boundaries)                                                                                                                                             |
| `SCOPE_ATTRIBUTE`            | `'data-mfe-scope'`, exported from `@company/mfe-react/host`. Every mount root and every overlay root carries it, and the container's `@scope` rule selects on it. — [Add styles beyond utilities](/docs/add-custom-styles)                                                                                                                                               |
| scope root                   | The `display: contents` element the runtime creates around every mount's element, carrying `data-mfe-scope="<id>"`. It anchors a selector without becoming a box in the layout. — [The isolation boundaries](/docs/how-it-works/the-isolation-boundaries)                                                                                                                |
| scoped stylesheet            | The CSS a container ships for its own classes, wrapped by the build in an `@scope` rule so it applies only inside that container's mount roots. — [Add styles beyond utilities](/docs/add-custom-styles)                                                                                                                                                                 |
| session generation           | An opaque string the shell creates once per signed-in identity per tab, stored at `@host:session-generation`. Every `retention: 'user'` record is stamped with it. — [Clear a value when the user changes](/docs/clear-a-value-on-sign-out)                                                                                                                              |
| share scope                  | A Module Federation map of packages that containers share one copy of. Each framework has one per exact version, such as `react@19.3.0`, and the neutral packages share `default`. A second copy inside one scope makes every hook fail with "rendered outside any mount". — [The isolation boundaries](/docs/how-it-works/the-isolation-boundaries)                     |
| shell (host)                 | The application that serves the page, owns the document and mounts containers into it. It is the only application on the page with no registry entry. — [Overview](/docs)                                                                                                                                                                                                |
| style root                   | The component the build generates and attaches to your definition, so the design system's context comes from your container's own copy of the library. — [Use the design system](/docs/use-the-design-system)                                                                                                                                                            |
| transport                    | The `{ fetch, getAccessToken }` object `#mfe/fetch` is built from. It resolves the shell's session on the first call, so a wiring mistake fails that request rather than the load. — [Call your API](/docs/call-your-api)                                                                                                                                                |
| Widget                       | A micro-frontend that takes props and renders inside somebody else's page, owning no URL. Declared with `createWidget`. — [Create a Widget](/docs/create-a-widget)                                                                                                                                                                                                       |
| zoneless                     | Angular change detection without `zone.js`. Each Angular mount schedules its own, and no container loads `zone.js`, which would patch timers and listeners for the whole page. — [The Angular adapter](/docs/reference/angular-adapter)                                                                                                                                  |
