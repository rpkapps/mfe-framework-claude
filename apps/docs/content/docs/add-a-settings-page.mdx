---
title: 'Add a settings page'
description: 'Mark one route in your App as the settings capability, and the shell links to it from its own settings panel.'
---

Apps only. Mark one route as your settings page, and the shell links to it from its own settings
panel and from the command palette. The shell decides where the link goes and never reads the page.

## Steps

<Steps>

<Step>

### 1. Mark the route

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/operations/src/routes/settings.tsx"
import { createFileRoute } from '@tanstack/react-router'
import type { ReactNode } from 'react'

import { SettingsPage } from '../components/settings-01/page.tsx'

export const Route = createFileRoute('/settings')({
  staticData: {
    capability: {
      name: 'settings',
      label: 'Operations settings',
      icon: 'settings',
    },
    breadcrumb: 'Settings',
  },
  component: Settings,
})

function Settings(): ReactNode {
  return <SettingsPage />
}
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative src/app.routes.ts"
import { Component } from '@angular/core'
import type { Routes } from '@angular/router'
import { mfeRouteData } from '@company/mfe-angular'

@Component({
  selector: 'operations-settings',
  template: `<h2>Operations settings</h2>`,
})
export class SettingsComponent {}

export const routes: Routes = [
  {
    path: 'settings',
    component: SettingsComponent,
    data: mfeRouteData({
      capability: {
        name: 'settings',
        label: 'Operations settings',
        icon: 'settings',
      },
      breadcrumb: 'Settings',
    }),
  },
]
```

</Tab>
</Tabs>

`capability` holds everything the shell reads about the page. Its `name` and `label` are required
and `icon` is optional. Write every field as a plain string, because the build reads the mark out
of the file without running it.

</Step>

<Step>

### 2. Generate the description record

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```sh
pnpm run generate
```

</Tab>
<Tab value="Angular">

```sh
pnpm exec nx run operations:generate
```

Run this in your Angular Nx workspace. Replace `operations` with your Nx project name.

</Tab>
</Tabs>

This writes your container's registry description. The host includes that record in its registry.
Publish or register that updated record through your host's registry workflow; starting your
container's development server does not update a separately maintained shell registry.

</Step>

<Step>

### 3. Confirm what the build published

```json shared title="examples/operations/.mfe/mfe-registry.json"
"capabilities": [
  { "name": "settings", "label": "Operations settings", "icon": "settings", "path": "/settings" }
]
```

`path` comes from the route: React uses `createFileRoute`, and Angular uses a literal `path`. One App publishes at most
one settings page.

</Step>

</Steps>

## Check it works

Start your container with its own development script and open the separately running shell that
registers your App. Find your capability in the host's application-settings menu or command
palette. Check the published `label`, select it, and confirm that `/settings` resolves under your
App's assigned mount prefix. For example, a mount at `/operations` produces
`/operations/settings`. The shell team determines the menu and keyboard shortcuts.

## Errors

<Callout type="error" title="expected one of 'settings', 'help' and 'releaseNotes'">

```text shared
/home/you/operations/src/routes/settings.tsx:10:7: 'operations' failed to extract a capability
route: expected one of 'settings', 'help' and 'releaseNotes', found "setings".
```

**Fix.** Use one of the names. To make a misspelling a compile error instead, type the
`staticData` slot as [Create an App](/docs/create-an-app) shows.

</Callout>

<Callout type="error" title="expected an inline object literal { name, label, icon? }">

```text shared
/home/you/operations/src/routes/settings.tsx:9:5: 'operations' failed to extract a capability
route: expected an inline object literal { name, label, icon? }, found 'settings'.
```

**Fix.** Move the name, label and icon into one object, for example
`capability: { name: 'settings', label: 'Operations settings' }`. Routes written before the
capability was one object hit this.

</Callout>

<Callout type="error" title="expected a non-empty `label` string literal">

```text shared
/home/you/operations/src/routes/settings.tsx:9:17: 'operations' failed to extract the capability
route '/settings': expected a non-empty `label` string literal, found no label.
```

**Fix.** Add the text the shell puts in its menu, for example `label: 'Operations settings'`.

</Callout>

<Callout type="error" title="expected one route per capability">

```text shared
/home/you/operations/src/routes/preferences.tsx: 'operations' failed to extract the 'settings'
capability route: expected one route per capability, found '/settings' and '/preferences' both
declare it.
```

**Fix.** Remove the mark from one of the two routes. The shell opens exactly one page per
capability.

</Callout>

<Callout type="error" title="expected a capability declared by an App">

```text shared
/home/you/alerts/src/routes/settings.tsx:9:5: the build failed to extract the 'settings'
capability route: expected a capability declared by an App, found a container that exports
Widgets only.
```

**Fix.** Move the route into a container that exports an App. A Widget has no routes of its own.

</Callout>
