---
title: 'Run the checks before you push'
description: 'Run the same command CI runs, and read what lint tells you when it stops you.'
---

Apps and Widgets. Run your container repository’s checks before publishing its artifact. CI installs compiled framework releases from your package registry.

## Steps

<Steps>

<Step>

### 1. Install the locked dependencies

```sh shared
pnpm install --frozen-lockfile
```

Run from your container repository. Configure access to the package registry that distributes your framework releases.

</Step>

<Step>

### 2. Run generation, lint, types and tests

<Tabs items={['React', 'Angular']} defaultIndex={0}>
<Tab value="React">

```sh
pnpm run generate
pnpm run format:check
pnpm run lint
pnpm run typecheck
pnpm run test
pnpm run build
```

Run in your React package directory, such as `apps/field-notes` in the quickstart repository. Its scripts generate before type checking, tests and builds.

</Tab>
<Tab value="Angular">

```sh
pnpm exec prettier --check .
pnpm exec nx lint operations
pnpm exec nx typecheck operations
pnpm exec nx test operations
pnpm exec nx build operations --configuration=production
```

Run in your container's Nx workspace. Replace the project name. Its lint, typecheck, test and build targets depend on generation.

</Tab>
</Tabs>

</Step>

<Step>

### 3. Use the same commands in your release pipeline

Run these commands against the same lockfile CI installs. Add a `check` script if your repository wants one combined command. Browser smoke checks should open your independently running shell and container.

The framework repository's package-boundary and combined-example checks are maintainer tasks, not prerequisites for publishing your container.

</Step>

<Step>

### 4. Read what lint says

<Tabs items={['React', 'Angular']} defaultIndex={0}>
<Tab value="React">

```text
src/routes/settings.tsx
  12:10  error  `localStorage` bypasses the MFE storage boundary: the key is not namespaced, so
  another MFE in this origin can read or overwrite it … Use `useStoredState()` for component state
  or `useMfeStorage()` for imperative access, both from @company/mfe-react  mfe/no-raw-storage
```

</Tab>
<Tab value="Angular">

```text
src/settings.component.ts
  12:10  error  `localStorage` bypasses the MFE storage boundary: the key is not namespaced, so
  another MFE in this origin can read or overwrite it, it carries no version to migrate a changed
  shape from, and a quota failure escapes as an unhandled exception. Use `injectStoredState()`
  for component state or `injectMfeStorage()` for imperative access, both from @company/mfe-angular.
  The storage adapter and a documented shell override bootstrap opt out through this rule's
  `allowedScopes` option.  mfe/no-raw-storage
```

Call the injection helper inside a component or service injection context.

</Tab>
</Tabs>

Read it from the ends in. The file, line and column say where. The rule name at the far right says
which rule. The message between them says what it found and what to write instead.

</Step>

</Steps>

## Check it works

All checks exit successfully and the build publishes only its generated artifact. CI repeats your repository's commands. Lint repairs identify the adapter API to call. Run any browser integration checks against the separately started shell.

## Errors

<Callout type="error" title="was not found by the project service">

```text shared
Parsing error: /home/you/operations/src/routes/probe.tsx was not found by the project service.
Consider either including it in the tsconfig.json or including it in allowDefaultProject
```

**Fix.** Add the file to your `tsconfig.json`, or set `tsconfigRootDir` in `eslint.config.ts` when
ESLint runs from another directory. The rules that need types cannot read a file no project owns.

</Callout>
