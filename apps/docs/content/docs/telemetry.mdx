Apps and Widgets. Use the mount's telemetry service to record events, errors and workflows.
The framework adds your definition's identity. The shell decides where records go.

## Steps

<Steps>
<Step>
### 1. Get your mount telemetry

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/lab/src/routes/telemetry.tsx (adapted)"
import { useTelemetry } from '@company/mfe-react'

export function RecordEvent() {
  const telemetry = useTelemetry()
  return (
    <button onClick={() => telemetry.event('lab.probe', { source: 'button' })}>Record event</button>
  )
}
```

In a route loader or `beforeLoad`, use `context.mfe.telemetry` instead of a hook.

</Tab>
<Tab value="Angular">

```ts title="examples/fieldwork/src/overview.component.ts (adapted)"
import { Component } from '@angular/core'
import { injectTelemetry } from '@company/mfe-angular'

@Component({
  selector: 'fieldwork-record-event',
  template: `<button (click)="record()">Record event</button>`,
})
export class RecordEventComponent {
  readonly telemetry = injectTelemetry()

  record(): void {
    this.telemetry.event('fieldwork.probe', { source: 'button' })
  }
}
```

Get the service in an injection context, such as a component constructor or field initializer.

</Tab>
</Tabs>

The handle stays stable for the mount's lifetime. Recording does not subscribe your component to state changes.

</Step>
<Step>
<span id="record-events-measurements-and-caught-errors" />

### 2. Record events, measurements and caught errors

```ts shared title="examples/lab/src/routes/telemetry.tsx (adapted)"
telemetry.info('Export started', { format: 'csv' })
telemetry.event('lab.export.started', { format: 'csv' })
telemetry.measure('lab.export.rows', 128, { unit: 'count' })
telemetry.error(new Error('Export failed'), { step: 'export' })
```

Both frameworks expose the same service. `error` reports a caught failure without throwing it or handling the UI.
Use scalar attributes only: strings, numbers and booleans. Keep bodies, credentials and raw URLs out of records.
The framework owns `mfe.*` attributes and drops any values you supply there.

</Step>
<Step>
<span id="trace-a-workflow-across-clicks" />

### 3. Trace a workflow across clicks and a request

A workflow is one piece of user-facing work, such as a checkout, recorded as one trace.
`telemetry.workflow(name)` returns the mount's workflow with that name, the same object every call.

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/lab/src/routes/telemetry.tsx (adapted)"
import { fetch } from '#mfe/fetch'
import { useTelemetry } from '@company/mfe-react'

export function Checkout({ cart }: { cart: readonly CartItem[] }) {
  const telemetry = useTelemetry()
  const checkout = telemetry.workflow('checkout')

  function start() {
    checkout.start({ items: cart.length })
  }

  function chooseShipping(option: string) {
    checkout.step('shipping chosen', { option })
  }

  async function placeOrder() {
    checkout.step('place order')
    try {
      const body = JSON.stringify(cart)
      const response = await fetch('orders', { method: 'POST', body, headers: checkout.headers() })
      if (!response.ok) throw new Error(`Order failed: ${response.status}`)
      checkout.succeed()
    } catch (error) {
      checkout.fail(error)
    }
  }

  // ...render a button for each
}
```

</Tab>
<Tab value="Angular">

```ts title="src/checkout.component.ts (Angular)"
import { Component, input } from '@angular/core'
import { fetch } from '#mfe/fetch'
import { injectTelemetry } from '@company/mfe-angular'

@Component({
  selector: 'app-checkout',
  template: `...a button for each`,
})
export class CheckoutComponent {
  readonly cart = input.required<readonly CartItem[]>()
  private readonly checkout = injectTelemetry().workflow('checkout')

  start(): void {
    this.checkout.start({ items: this.cart().length })
  }

  chooseShipping(option: string): void {
    this.checkout.step('shipping chosen', { option })
  }

  async placeOrder(): Promise<void> {
    this.checkout.step('place order')
    try {
      const body = JSON.stringify(this.cart())
      const headers = this.checkout.headers()
      const response = await fetch('orders', { method: 'POST', body, headers })
      if (!response.ok) throw new Error(`Order failed: ${response.status}`)
      this.checkout.succeed()
    } catch (error) {
      this.checkout.fail(error)
    }
  }
}
```

</Tab>
</Tabs>

`start` begins a new trace. Each `step` is a child of the workflow and lasts until the next step or the end.
`succeed` and `fail` end the workflow. `fail` also reports the error, linked to the trace, so you do not call `telemetry.error` as well.
Steps and `succeed` are ignored while the workflow is not open; `fail` still reports its error, without a trace. Starting it again while it is open abandons the open run first.
If the mount ends while a workflow is open, its spans are closed as cancelled, not failed.

A request joins the workflow only when you spread `headers()` into it. It returns a W3C `traceparent` for the current step, or `{}` when nothing is open or tracing is off.
Requests you send without it, such as background refreshes, never land in a workflow.
Your API must accept the `traceparent` header in its CORS settings and continue the trace with its OpenTelemetry SDK.

</Step>

### 4. Link records to a workflow

A workflow has the same record methods as `telemetry`: `event`, `debug`, `info`, `warn`, `error` and `measure`.
A record made through it is linked to the current step, or to the workflow before its first step.

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="src/checkout.tsx (React)"
async function getQuote(carrier: string) {
  checkout.step('quote')
  const response = await fetch(`quotes/${carrier}`, { headers: checkout.headers() })
  if (response.ok) checkout.info('quote received', { carrier })
  else checkout.warn('quote unavailable', { carrier, status: response.status })
}
```

</Tab>
<Tab value="Angular">

```ts title="src/checkout.component.ts (Angular)"
async getQuote(carrier: string): Promise<void> {
  this.checkout.step('quote')
  const headers = this.checkout.headers()
  const response = await fetch(`quotes/${carrier}`, { headers })
  if (response.ok) this.checkout.info('quote received', { carrier })
  else this.checkout.warn('quote unavailable', { carrier, status: response.status })
}
```

</Tab>
</Tabs>

While the workflow is not open, or tracing is off, the record is still sent, just not linked. A log is never lost for want of a `start()`.
The shell's level filter applies as it does to `telemetry.info`. Use `fail`, not `error`, to end the workflow with an error.

</Step>

### 5. Run several at once with a key

Only one run of a workflow is open at a time. To trace several uploads at once, pass each one's id as a key.
`telemetry.workflow(name, key)` returns the same object for the same name and key, and a run of its own for each key.

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="src/upload-row.tsx (React)"
import { fetch } from '#mfe/fetch'
import { useTelemetry } from '@company/mfe-react'

export function UploadRow({ file }: { file: QueuedFile }) {
  const upload = useTelemetry().workflow('upload', file.id)

  async function send() {
    upload.start({ bytes: file.size })
    try {
      const body = file.blob
      const response = await fetch('files', { method: 'POST', body, headers: upload.headers() })
      if (!response.ok) throw new Error(`Upload failed: ${response.status}`)
      upload.succeed()
    } catch (error) {
      upload.fail(error)
    }
  }

  // ...render the row and a send button
}
```

</Tab>
<Tab value="Angular">

```ts title="src/upload-row.component.ts (Angular)"
import { Component, computed, input } from '@angular/core'
import { fetch } from '#mfe/fetch'
import { injectTelemetry } from '@company/mfe-angular'

@Component({
  selector: 'app-upload-row',
  template: `...the row and a send button`,
})
export class UploadRowComponent {
  readonly file = input.required<QueuedFile>()
  private readonly telemetry = injectTelemetry()
  private readonly upload = computed(() => this.telemetry.workflow('upload', this.file().id))

  async send(): Promise<void> {
    const upload = this.upload()
    upload.start({ bytes: this.file().size })
    try {
      const body = this.file().blob
      const response = await fetch('files', { method: 'POST', body, headers: upload.headers() })
      if (!response.ok) throw new Error(`Upload failed: ${response.status}`)
      upload.succeed()
    } catch (error) {
      upload.fail(error)
    }
  }
}
```

</Tab>
</Tabs>

The key only picks the run. It is never recorded, so an order or file id is safe to use. Without a key, a name has one run at a time.

</Step>
</Steps>

## Check it works

Use your test environment's `telemetry.events()`, `telemetry.logs('error')` and `telemetry.spansNamed('checkout')` to inspect records.
Check the definition attribution and confirm `telemetry.endedSpans()` includes completed workflows.
The development shell retains no records unless you configure a collector, so test records are the reliable check.

## Errors

<Callout type="error" title="mount/failure, outside a mount">

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```text
<unmounted> failed to call useTelemetry: expected a component rendered inside an App or Widget
mount, received a component rendered outside any mount.
```

</Tab>
<Tab value="Angular">

`injectTelemetry()` requires a component or service created inside an App or Widget mount.
A consumer created outside a mount reports `mount/failure`.

**Fix.** Capture telemetry in a component constructor or field initializer inside the mount.
Resolvers can inject it before any `await`.

</Tab>
</Tabs>

**Fix.** Get telemetry inside your mounted component. React route callbacks use `context.mfe.telemetry`.

</Callout>

<Callout type="error" title="config/invalid, a workflow that is not open">

```text shared
lab@1.0.0 failed to end workflow "checkout" as succeeded: expected workflow "checkout" to be
started with start(), received workflow "checkout", which was not open.
```

**Fix.** Call `start()` before the workflow's steps and its end. The call was ignored. In development only.

</Callout>

## Runtime snapshots for a shell bug report

Call `runtime.getSnapshot()` when your shell collects a bug report.

```ts shared title="src/shell/diagnostics.ts (adapted)"
const runtimeSnapshot = runtime.getSnapshot()
const attachment = JSON.stringify(runtimeSnapshot, null, 2)
```

Append `attachment` as a JSON code block in your report, or send it through your shell's issue tracker integration.
The example shell includes it in the bug dialog's copied Markdown report and both **Copy diagnostics** actions.
The dialog captures when it opens. The copy actions capture when they run.

Use `runtimeSnapshot.mounts` to describe current placements, including Widgets and failed mounts.
An empty list means no placements. A URL names a page, but cannot tell you which definitions actually mounted.

Review rejection reasons and redact sensitive text before sharing.
Your shell adds deployment context and decides where reports go. Snapshots need no telemetry collector.
See [Runtime snapshots](/docs/reference/hooks-and-components#runtime-snapshots) for fields, lifecycle states and framework exports.
