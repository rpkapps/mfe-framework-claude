---
title: 'Read or write storage outside render'
description: 'Take the imperative storage handle with useMfeStorage for handlers, loaders and cleanups.'
---

`useMfeStorage()` gives you a handle you can call from an event handler, a loader or a cleanup. It
reads and writes the same records `useStoredState` binds. Apps and Widgets.

## Steps

<Steps>
<Step>
### 1. Take the handle

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/lab/src/routes/storage.tsx"
import { useMfeStorage } from '@company/mfe-react'

// Inside your component.
const local = useMfeStorage()
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular component field"
import { injectMfeStorage } from '@company/mfe-angular'

// Inside your component class, in an injection context.
readonly local = injectMfeStorage()
```

Use `this.local` in component methods. In a resolver, capture the handle before any `await`.

</Tab>
</Tabs>

Both return the same handle API. Pass `'session'` for tab-only records.
See [browser storage scope](/docs/remember-a-value) before choosing what to save.

</Step>
<Step>
### 2. Read and write in a handler

```tsx title="examples/lab/src/routes/storage.tsx"
const draft = local.key('draft', draftSchema).get()
local.key('draft', draftSchema).set({ note: 'filed', pinned: true })
local.remove('draft')
```

`get()` returns the value, or `null` when the key is absent. It reads the browser store again
rather than a cached value, and it never subscribes. Anything you render still uses
[useStoredState](/docs/remember-a-value).

</Step>
<Step>
### 3. Reach it from a route callback

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```ts title="Illustrative React route options"
loader: ({ context }) => {
  const site = context.mfe.storage.local.key('last-site', siteSchema).get()
  return context.queryClient.ensureQueryData(assetsQueryOptions(site ?? 'north'))
}
```

Loaders, actions and `beforeLoad` callbacks receive `context.mfe.storage.local` and `context.mfe.storage.session`.

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular resolver"
import { injectMfeStorage } from '@company/mfe-angular'
import type { ResolveFn } from '@angular/router'

export const lastSiteResolver: ResolveFn<string | null> = () =>
  injectMfeStorage().key('last-site', siteSchema).get()
```

Import your module-level `siteSchema`. The resolver returns the saved site or `null`.

</Tab>
</Tabs>

</Step>
<Step>
### 4. Clear your own records

```ts
local.clear()
```

`clear()` removes only the keys under your own `lab:` prefix. A definition called `acme-orders`
never touches `acme-orders-legacy:`, the shell's keys or another team's.

</Step>
</Steps>

## Check it works

Write through the handle while a `useStoredState` on the same key is on screen. The rendered value
updates, because a write here notifies that key's subscribers. Pass the same schema object and the
same options both places. Remove the key and the rendered value falls back to your declared
default.

To read or clear a Widget tile's own preference, give it an `instanceId` in the host and pass
`scope: 'instance'`:

```ts
local.key('camera', cameraSchema, { scope: 'instance' }).set(camera)
local.remove('camera', { scope: 'instance' })
local.clear({ scope: 'instance' })
```

These are the same records `useStoredState` or `injectStoredState` reads with `scope: 'instance'`.
Clearing one tile leaves the other tiles and definition-wide values alone. `local.clear()` still
clears only definition-wide records. The shell's `storage.clearDefinition(id)` removes every
record for that definition, its instances included.

## Errors

<Callout type="error" title="mount/failure, outside a mount">

```text
<unmounted> failed to call useMfeStorage: expected a component rendered inside an App or Widget
mount, received a component rendered outside any mount.
```

**Fix.** Move the call into a component your App or Widget renders. A module-level helper runs
before the mount exists.

</Callout>

<Callout type="error" title="mfe/no-raw-storage">

```text
`localStorage` bypasses the MFE storage boundary: the key is not namespaced, so another MFE in this
origin can read or overwrite it, it carries no version to migrate a changed shape from, and a quota
failure escapes as an unhandled exception.
```

**Fix.** Take the handle with `useMfeStorage()`, or bind the key with `useStoredState()`. Angular uses `injectMfeStorage()` or `injectStoredState()` instead.

</Callout>
