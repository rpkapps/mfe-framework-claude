---
title: 'Deploy to production with separate repositories'
description: 'Publish a container artifact, update the shell registry, and configure each deployment.'
---

Each container and the shell have separate repositories and release pipelines. Your container publishes its compiled assets and `mfe-registry.json`. Your platform combines those records into the registry the shell reads.

## Steps

<Steps>

<Step>

### 1. Build in the container repository

<Tabs items={['React', 'Angular']} defaultIndex={0}>
<Tab value="React">

```sh
# Run from the React package directory, such as apps/field-notes.
pnpm install --frozen-lockfile
pnpm run build
```

</Tab>
<Tab value="Angular">

```sh
pnpm install --frozen-lockfile
pnpm exec nx build operations --configuration=production
```

Replace `operations` with your own Nx project name.

</Tab>
</Tabs>

</Step>

<Step>

### 2. Publish the artifact with deployment configuration

Publish the entire container output directory, including chunks, CSS, the federation manifest and
`mfe-registry.json`. React writes `dist/` relative to its package directory. Angular writes to the
Nx project's configured output path.

If your container declares env values, package its generated `runtime-config.sh` with those assets.
Use the [release-artifact and Docker procedure](/docs/supply-values-per-deployment#package-your-containers-release-artifact)
to stage the correct files and supply each deployment's values.

</Step>

<Step>

### 3. Pass the published record to your registry integration

```sh shared
curl --fail "$CONTAINER_URL/mfe-registry.json" -o mfe-registry.json
```

Your platform's registration pipeline consumes this generated record and its deployment origin. Resolve the record's relative `manifestUrl` against that origin. Preserve generated definitions and compatibility metadata.

The framework supplies no production registry aggregation CLI or registration endpoint. Use your platform's service or shell-repository pipeline.

</Step>

<Step>

### 4. Deploy the registry from the shell repository

```ts title="src/boot.ts (shell repository)" shared
const response = await fetch('/registry.json')
```

Serve the assembled registry at the URL your shell reads. A registry update is a separate shell/platform release. Existing pages discover it on reload. The shell may override presentation labels without changing the generated contract.

</Step>

</Steps>

## Check it works

Open the deployed shell and its **Registry** panel. Confirm the definition loads from the container's deployment origin. Open a screen and check its API calls use that environment's configuration. A container release should require no framework source checkout.
