---
title: 'Render a Widget inside your App'
description: 'Call lazyWidget at module scope, then render the Widget as an ordinary component.'
---

React loads a known Widget with `lazyWidget`. Angular renders `<mfe-widget>` with its id, inputs, and contract.
Both can host a Widget built with either framework.

## Steps

<Steps>

<Step>

### 1. Depend on the provider's container

```json title="examples/operations/package.json" shared
"dependencies": {
  "@example/alert-panel": "workspace:*"
}
```

You import the contract from that package, and the Widget itself arrives over the network at run
time.

</Step>

<Step>

### 2. Bind the Widget's contract

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```ts title="examples/operations/src/widgets.ts"
import { lazyWidget } from '@company/mfe-react'

import { inputSchema, outputSchema } from '@example/alert-panel/contracts'

export const AlertPanel = lazyWidget('alert-panel', { contract: { inputSchema, outputSchema } })
```

</Tab>
<Tab value="Angular">

```ts title="src/alert-consumer.component.ts"
import { Component } from '@angular/core'
import { MfeWidgetComponent } from '@company/mfe-angular'
import { inputSchema, outputSchema } from '@example/alert-panel/contracts'

@Component({
  selector: 'alert-consumer',
  imports: [MfeWidgetComponent],
  template: `<mfe-widget
    widgetId="alert-panel"
    [contract]="contract"
    [inputs]="{ alertId: 'a-1001', severity: 'warning' }"
  />`,
})
export class AlertConsumer {
  readonly contract = { inputSchema, outputSchema }
}
```

</Tab>
</Tabs>

React calls `lazyWidget` at module scope. Angular binds a contract object to `<mfe-widget>`. Contracts are optional but validate consumer expectations.

</Step>

<Step>

### 3. Render it with inputs, a placeholder and a fallback

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/operations/src/routes/index.tsx (trimmed)"
<AlertPanel
  alertId="a-1001"
  severity="warning"
  pending={<Skeleton className="h-24 w-full" />}
  onAcknowledged={payload => {
    setAcknowledged(payload.acknowledgedAt)
  }}
  fallback={({ error, retry }) => (
    <div role="alert">
      <p>{error.message}</p>
      <Button onClick={retry}>Retry</Button>
    </div>
  )}
/>
```

</Tab>
<Tab value="Angular">

```ts title="src/alert-consumer.component.ts"
import { Component, signal } from '@angular/core'
import { MfeWidgetComponent, type MfeWidgetOutput } from '@company/mfe-angular'
import { inputSchema, outputSchema } from '@example/alert-panel/contracts'

@Component({
  selector: 'alert-consumer',
  imports: [MfeWidgetComponent],
  template: `<mfe-widget
      widgetId="alert-panel"
      [contract]="contract"
      [inputs]="{ alertId: 'a-1001', severity: 'warning' }"
      [pending]="loading"
      [fallback]="failed"
      (output)="onOutput($event)"
    />
    <ng-template #loading>Loading alert…</ng-template>
    <ng-template #failed let-error let-retry="retry">
      <p role="alert">{{ error.message }}</p>
      <button (click)="retry()">Retry</button>
    </ng-template>`,
})
export class AlertConsumer {
  readonly contract = { inputSchema, outputSchema }
  readonly acknowledged = signal<string | null>(null)

  onOutput(event: MfeWidgetOutput) {
    if (event.name === 'acknowledged') {
      const payload = outputSchema.shape.acknowledged.parse(event.payload)
      this.acknowledged.set(payload.acknowledgedAt)
    }
  }
}
```

</Tab>
</Tabs>

`pending` fills the box while the container is fetched, and `fallback` receives the error and a
`retry` function, plus `reload` when the tab needs fresh code. React supplies default loading and error content. Angular shows only the pending and fallback templates you provide.

</Step>

</Steps>

## Check it works

The panel renders inside your page, styled by its own container. Change an input and the mounted
Widget updates without remounting or losing its state. A Widget that fails to load loses its own
box, and the rest of the page keeps working. React's default error content offers Retry or Reload page. Angular's fallback template receives those functions. `examples/lab/src/routes/widgets.tsx` shows the cases side by side.

## Errors

<Tabs items={['React', 'Angular']}>
<Tab value="React">

<Callout type="error" title="mfe/stable-definitions">

```text
`lazyWidget` (`lazyWidget` from @company/mfe-react) has to be called once, at module scope.
```

**Fix.** Move the call to the top level of the module and render the resulting component.

</Callout>

</Tab>
<Tab value="Angular">

Angular renders `MfeWidgetComponent` directly. It has no `lazyWidget` factory or module-scope call requirement.
Import `MfeWidgetComponent` in the consuming component and bind its `widgetId`, `inputs`, and optional `contract`.

</Tab>
</Tabs>

<Callout type="error" title="registry/invalid-entry">

```text shared
alert-panel failed to resolve Widget: no registry entry with this id.
```

**Fix.** Check the id against the generated registry. In development, point the shell at your dev
server.

</Callout>

<Callout type="error" title="contract/input-mismatch">

```text shared
alert-panel@1.4.0 failed to accept input alertId: 7; ✖ Invalid input: expected string, received number
  → at alertId.
```

**Fix.** Send the type the contract declares, for example `String(alert.id)`.

</Callout>

A failed first mount renders your fallback. Angular leaves the region empty when you supply no fallback template.
On a later rejected update, the Widget keeps its last valid inputs.
React reports the rejection through `onInputRejected(error)` and optional `inputFallback` content.
Angular reports it through `(inputRejected)` and your `[inputFallback]` template. A valid update clears the rejection.
