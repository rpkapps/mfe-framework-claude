---
title: 'Call your API'
description: 'Use the generated #mfe/fetch to send requests that carry the shell session token.'
---

Apps and Widgets, in React and Angular. Every container gets `#mfe/fetch`, a standard `fetch` that resolves a relative URL against your
API base and attaches the shell's session token. The browser's own `fetch` is left alone.

<Diagram
  src="/diagrams/capability-requests.svg"
  alt="How React and Angular containers connect to the shell for requests."
  caption="How your container connects to the shell"
>
  Both frameworks import the same `#mfe/fetch` module. It resolves relative URLs against your
  configured API base. The shell supplies the current token for declared API origins. Your API
  receives the request and authorizes it.
</Diagram>

## Steps

<Steps>

<Step>

### 1. Import the generated fetch

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```ts title="examples/operations/src/queries/assets.ts"
import { fetch } from '#mfe/fetch'
```

</Tab>
<Tab value="Angular">

```ts title="examples/fieldwork/src/inspections.ts (adapted)"
import { fetch } from '#mfe/fetch'
```

The generated fetch has the same behavior in Angular. Existing `HttpClient` calls can use the [authentication interceptor setup](https://github.com/rpkapps/mfe-framework-claude/blob/dev/packages/mfe-angular/README.md#authenticated-httpclient-calls).

</Tab>
</Tabs>

Every container has this module, whether or not it declares configuration.

</Step>

<Step>

### 2. Send the request

```ts title="examples/operations/src/queries/assets.ts"
const response = await fetch(`assets?site=${encodeURIComponent(siteId)}`, { signal })

if (!response.ok) {
  throw new Error(`Loading assets for site ${siteId} failed with ${response.status}.`)
}

return z.array(assetSchema).parse(await response.json())
```

The signature is `fetch`'s own, so pass a `signal`, a method and a body as you always would.

</Step>

<Step>

### 3. Take the token for anything that is not HTTP

```ts
import { getAccessToken } from '#mfe/fetch'

const token = await getAccessToken()
```

Await it, call it once per connection, and never store what it returns.

</Step>

</Steps>

## Check it works

Run `pnpm dev`, which also starts a stand-in API on port 3010 that the examples point at. Open
`/lab/config` in the shell and send the probe request. The response reports what arrived: your
relative path resolved against the configured base, and an `Authorization` header you did not
write. A 401 is handled once, and a 403 passes through untouched.

## Errors

<Callout type="error" title="config/missing">

```text
operations failed to resolve the request URL: expected an absolute URL, or an apiBaseUrl to
resolve a relative one against, received the relative URL "assets?site=north" and no configured
apiBaseUrl.
```

**Fix.** Declare a value with `{ api: true }`, or pass an absolute URL. A relative URL is never
resolved against the shell document.

</Callout>

<Callout type="error" title="auth/undeclared-origin">

```text
operations failed to attach the access token for https://reports.example.test: expected a request
to an origin the author declared as an API with { api: true }, received a request to
https://reports.example.test, which is not declared.
```

**Fix.** Declare the origin if it is yours. The request was sent without a token, so a 401 from it
is this missing declaration.

</Callout>

<Callout type="error" title="config/invalid">

```text
operations failed to retry POST https://api.example.test after 401: expected a request the
framework can send a second time, received a ReadableStream body, which is consumed as it is sent
and cannot be read a second time.
```

**Fix.** Buffer the body first, as a string, `Blob`, `ArrayBuffer`, `FormData` or
`URLSearchParams`. The original 401 is returned unchanged and the token is refreshed for the next
request.

</Callout>
