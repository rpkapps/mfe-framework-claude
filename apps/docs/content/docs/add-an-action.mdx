---
title: 'Add an action to the palette'
description: 'Register an action from React or Angular, choose where it appears, and run it from the palette, a shortcut or your own button.'
---

Apps and Widgets. An action is one operation your container offers to the shell. By default the shell lists it in the command palette and offers it to its agent. Your container owns its implementation and when it may run.

<Diagram
  src="/diagrams/capability-actions.svg"
  alt="How React and Angular containers connect to the shell for actions."
  caption="How your container connects to the shell"
>
  Your component registers through `useAction` or `injectAction`. The shell lists the action and
  checks `canExecute` before calling your implementation. Your own button runs the same
  registration. Leaving the component removes it.
</Diagram>

## Steps

<Steps>

<Step>

### 1. Register an action and connect your button

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/alert-panel/src/alert-panel.tsx (adapted)"
import { useState } from 'react'
import { allow, deny, useAction } from '@company/mfe-react'

export function AcknowledgeButton() {
  const [acknowledged, setAcknowledged] = useState(false)
  const acknowledge = useAction({
    name: 'acknowledge',
    label: 'Acknowledge alert',
    canExecute: () => (acknowledged ? deny('Already acknowledged.') : allow()),
    execute: () => {
      setAcknowledged(true)
    },
  })
  return <button onClick={() => void acknowledge()}>Acknowledge</button>
}
```

</Tab>
<Tab value="Angular">

```ts title="examples/fieldwork/src/overview.component.ts (adapted)"
import { Component, signal } from '@angular/core'
import { allow, deny, injectAction } from '@company/mfe-angular'

@Component({
  selector: 'fieldwork-acknowledge',
  template: `<button (click)="acknowledge()">Acknowledge</button>`,
})
export class AcknowledgeComponent {
  readonly acknowledged = signal(false)
  readonly acknowledge = injectAction(() => ({
    name: 'acknowledge',
    label: 'Acknowledge alert',
    canExecute: () => (this.acknowledged() ? deny('Already acknowledged.') : allow()),
    execute: () => {
      this.acknowledged.set(true)
    },
  }))
}
```

Use a factory when the registration reads signals. Call `injectAction` in a constructor or field initializer.

</Tab>
</Tabs>

The palette and your button use the same availability checks. A denied action stays visible with its reason.
Keep `canExecute` a state check, and authorize requests in your API.
The registration ends when its component unmounts or injector is destroyed.

</Step>

<Step>
<span id="choose-where-it-appears" />

### 2. Choose where it appears

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/reports/src/routes/__root.tsx (trimmed)"
useAction({
  name: 'copy-ranking',
  label: 'Reports: copy the ranking',
  placements: ['palette'],
  execute: () => {
    void navigator.clipboard.writeText(rows.join('\n'))
  },
})
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular component constructor"
import { injectAction } from '@company/mfe-angular'

// Inside a component constructor; rows is your component's signal.
injectAction(() => ({
  name: 'copy-ranking',
  label: 'Reports: copy the ranking',
  placements: ['palette'],
  execute: () => navigator.clipboard.writeText(this.rows().join('\n')),
}))
```

</Tab>
</Tabs>

`placements` lists where the shell offers the action. Leave it out to offer the action in both places.

| `placements`           | Command palette | Agent's tools |
| ---------------------- | --------------- | ------------- |
| left out, the default  | yes             | yes           |
| `['palette', 'agent']` | yes             | yes           |
| `['palette']`          | yes             | no            |
| `['agent']`            | no              | yes           |
| `[]`                   | no              | no            |

The shortcut and your own button run the action whatever `placements` lists.
`'palette'` and `'agent'` are the only placements. Any other value throws `action/invalid-registration`.

</Step>

<Step>
<span id="add-a-shortcut" />

### 3. Choose the lifetime and optional shortcut

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="examples/operations/src/routes/__root.tsx (trimmed)"
useAction({
  name: 'open-wells',
  label: 'Operations: open the wells inventory',
  shortcut: 'o w',
  execute: () => {
    void navigate({ to: '/wells' })
  },
})
```

</Tab>
<Tab value="Angular">

```ts title="examples/fieldwork/src/overview.component.ts (trimmed)"
this.logInspectionAction = injectAction(() => ({
  name: 'log-inspection',
  label: 'Fieldwork: log an inspection at the chosen pad',
  shortcut: 'f l',
  canExecute: () => (this.padId() === null ? deny('Choose a well pad first.') : allow()),
  execute: () => {
    this.logInspection()
  },
}))
```

</Tab>
</Tabs>

Register in a layout component for App-wide actions, or a page component for page actions.
An App's shortcut fires while the page is inside your App. Widgets cannot register shortcuts.
Use `+` for chords such as `mod+s`, and spaces for sequences such as `o w`. `mod` means Command on macOS and Control elsewhere.
A shortcut without Control, Command or Alt does not fire while the user types in a field.
Press `?` in the shell to see every key in use. The [shortcut syntax](/docs/reference/hooks-and-components#shortcut-syntax) lists every key name.

</Step>

</Steps>

## Check it works

Open the palette with Command+K or Control+K while your component is mounted. Find “Acknowledge alert” under “From the mounted application”, then run it.
Reopen the palette. The row is now disabled and reads “Already acknowledged.”
If the action has a shortcut, press `?` and find it in the key list. Leave the component and confirm the action disappears.

## Errors

<Callout type="error" title="expected a name of letters, digits and hyphens">

```text shared
alert-panel failed to register action: expected a name of letters, digits and hyphens starting
with a letter (for example "refresh"), received "acknowledge alert".
```

**Fix.** Rename the action to `acknowledge-alert`. Spaces, dots and colons are not allowed.

</Callout>

<Callout type="error" title="expected one registration per action name within a mount">

```text shared
alert-panel failed to register action 'refresh': expected one registration per action name
within a mount, received a second registration of 'refresh' in the same mount.
```

**Fix.** Rename one of the two. Neither is dropped in favour of the other, so the second one
throws instead.

</Callout>

<Callout type="error" title="expected a non-empty label">

```text shared
alert-panel failed to register action 'refresh': expected a non-empty label, received an empty
string.
```

**Fix.** Give the action the words you want in the palette. It is the only text the reader sees.

</Callout>

<Callout type="error" title="expected keys no other live action can be pressed for at the same time">

```text shared
operations failed to register the shortcut 'o w' for action 'open-wells': expected keys no other
live action can be pressed for at the same time, received 'orders:open-work' (o w) already claims
them.
```

**Fix.** Give one of the two actions different keys. Neither shortcut fires while both are registered. Both actions stay in the palette.

</Callout>
