---
title: 'Add an action to the palette'
description: 'Register an action with useAction, and the shell lists it in the command palette and offers it to its agent for as long as your component is on the page.'
---

Apps and Widgets. Call `useAction` and your action appears in the shell's command palette. The
shell's agent can call it too, as a tool. You decide what it does, whether it may run right now and
what it changes.

## Steps

<Steps>

<Step>

### 1. Register the action

```tsx title="examples/alert-panel/src/alert-panel.tsx"
import { useAction } from '@company/mfe-react'

export function AlertPanel({ inputs, emit }: WidgetRenderProps<typeof alertPanelContract>) {
  const [state, setState] = useState<'open' | 'acknowledged' | 'dismissed'>('open')

  useAction({
    name: 'acknowledge-alert',
    label: 'Acknowledge this alert',
    execute: () => {
      setState('acknowledged')
      emit('acknowledged', { alertId: inputs.alertId, acknowledgedAt: new Date().toISOString() })
    },
  })

  return <Alert>{/* … */}</Alert>
}
```

`name` is letters, digits and hyphens, starting with a letter. The action lives as long as the
component renders, so leaving the page takes it out of the palette.

</Step>

<Step>

### 2. Say when it may run

```tsx title="examples/alert-panel/src/alert-panel.tsx"
import { allow, deny, useAction } from '@company/mfe-react'

useAction({
  name: 'acknowledge-alert',
  label: 'Acknowledge this alert',
  canExecute: () => (state === 'open' ? allow() : deny('This alert was already acknowledged.')),
  execute: () => {
    setState('acknowledged')
  },
})
```

A denied action stays in the list, greyed out, with your reason beside it. Keep `canExecute` a
plain read of state you already have, and do the work in `execute`. It decides for every caller,
but it is not a permission check. Your API still authorizes the request.

</Step>

<Step>

### 3. Describe it for the agent

```tsx title="examples/lab/src/routes/actions.tsx"
useAction({
  name: 'export-results',
  label: 'Export results',
  description: 'Exports the simulation results to a file the user downloads.',
  canExecute: () =>
    groups.includes('well-planning.read')
      ? allow()
      : deny('You need the well-planning.read group to export.'),
  execute: () => {
    record('Exported the results')
  },
})
```

`label` is the menu text. `description` is for the agent: say what the action does and when to use
it, in one or two sentences.

</Step>

<Step>

### 4. Say what it changes

```tsx title="examples/operations/src/routes/__root.tsx (trimmed)"
useAction({
  name: 'open-wells',
  label: 'Operations: open the wells inventory',
  // Opening a page changes nothing the user keeps, so the agent may do it without asking.
  effect: 'read',
  canExecute: () => allow(),
  execute: () => {
    void navigate({ to: '/wells' })
  },
})
```

`effect` decides whether the agent asks the user before it runs the action.

| `effect`               | What a run changes                    | An agent's call     |
| ---------------------- | ------------------------------------- | ------------------- |
| `'read'`               | No data. It may change what is shown. | runs without asking |
| `'write'`, the default | Data the user could change back.      | asks the user first |
| `'destructive'`        | Data the user could not change back.  | asks the user first |

Mark an action that only opens or shows something `'read'`. Left undeclared, it counts as a write,
and the agent asks before every call. A user who runs the action from the palette, the keys or your
own button is never asked. To ask for some calls only, set `needsApproval` to a check of the input
([useAction](/docs/reference/hooks-and-components#useaction) has every field).

</Step>

<Step>

### 5. Take input

```tsx title="examples/lab/src/routes/actions.tsx (trimmed)"
import { z } from 'zod'

/** At module scope: the registry converts it to JSON Schema whenever its identity changes. */
const simulationInput = z.object({ runs: z.number().int().min(1).max(1000).default(100) })

useAction({
  name: 'run-simulation',
  label: 'Run the simulation',
  description: 'Runs the well-planning simulation. More runs take longer and smooth the result.',
  inputSchema: simulationInput,
  effect: 'read',
  canExecute: () => (armed ? allow() : deny('Arm the simulation first.')),
  execute: ({ runs }) => {
    record(`Ran the simulation ${runs} times`)
  },
})
```

`inputSchema` is one `z.object`, declared at module scope. Every caller's input is checked against
it before `execute` runs, and `execute` receives the parsed value with its defaults filled in. An
action without `inputSchema` takes no input.

`outputSchema` declares the value `execute` returns. The caller gets the parsed value, and a value
that does not match fails the run.

</Step>

<Step>

### 6. Run it from your own button

```tsx title="examples/lab/src/routes/actions.tsx (trimmed)"
const runSimulation = useAction({
  name: 'run-simulation',
  label: 'Run the simulation',
  inputSchema: simulationInput,
  effect: 'read',
  canExecute: () => (armed ? allow() : deny('Arm the simulation first.')),
  execute: ({ runs }) => {
    record(`Ran the simulation ${runs} times`)
  },
})

return (
  <Button
    variant="outline"
    onPress={() => {
      void runSimulation({ runs: 10 }).then(result => {
        if (result.status !== 'executed') record(`Not run: ${result.status}`)
      })
    }}
  >
    Run the simulation 10 times
  </Button>
)
```

`useAction` returns a function that runs the action. Your button then goes through the same checks
as the palette, the keys and the agent. The input is optional when the schema accepts `{}`. The run
resolves to one result:

| `status`      | What happened                                                                       |
| ------------- | ----------------------------------------------------------------------------------- |
| `executed`    | `execute` ran. `value` holds what it returned.                                      |
| `denied`      | `canExecute` refused, with its `reason`. The shell also shows the user your reason. |
| `declined`    | The user was asked about an agent's call and said no.                               |
| `invalid`     | The input did not match `inputSchema`, so nothing ran.                              |
| `unavailable` | The component that registered the action is gone.                                   |
| `failed`      | `execute` threw, or its value did not match `outputSchema`. `error` says which.     |

In an Angular component, `injectAction` returns the same function. See the
[Angular adapter](/docs/reference/angular-adapter#read-the-shell-from-inside-a-mount).

</Step>

<Step>

### 7. Register App-wide actions from your layout

```tsx title="examples/operations/src/routes/__root.tsx"
useAction({
  name: 'open-wells',
  label: 'Operations: open the wells inventory',
  effect: 'read',
  canExecute: () => allow(),
  execute: () => {
    void navigate({ to: '/wells' })
  },
})
```

An action registered by a layout route lasts as long as the App is mounted. An action registered
by a page lasts as long as that page.

</Step>

<Step>

### 8. Give it a shortcut

```tsx title="examples/operations/src/routes/__root.tsx"
useAction({
  name: 'open-wells',
  label: 'Operations: open the wells inventory',
  effect: 'read',
  shortcut: 'o w',
  canExecute: () => allow(),
  execute: () => {
    void navigate({ to: '/wells' })
  },
})
```

A chord joins modifiers and one key with `+`: `mod+s`, `shift+?`, `alt+enter`. A sequence is
chords separated by spaces: `o w`. `mod` is <Kbd>⌘</Kbd> on a Mac and <Kbd>Ctrl</Kbd> elsewhere.
Spell a named key out: `escape`, `enter`, `space`, `plus`, `arrowup`, `f1`.

The shell runs the action when the keys are pressed, the same way the palette runs it, so
`canExecute` still decides. The palette shows the keys beside the action, and the help sheet
lists them.

- **When it fires.** An App's shortcut works while the page is inside that App. A Widget's is
  ignored, because a Widget does not own the page's keys.
- **Typing.** A key without <Kbd>Ctrl</Kbd>, <Kbd>⌘</Kbd> or <Kbd>Alt</Kbd> typed into a field
  stays in the field.
- **Keys you cannot have.** The shell's own keys are reserved: <Kbd>mod+k</Kbd>, <Kbd>?</Kbd>,
  <Kbd>mod+j</Kbd> and every sequence starting with <Kbd>g</Kbd>. Pick keys that neither equal nor
  begin nor extend one of those.

</Step>

<Step>

### 9. Keep it away from the agent

```tsx title="examples/reports/src/routes/__root.tsx (trimmed)"
useAction({
  name: 'copy-ranking',
  label: 'Reports: copy the ranking',
  // The clipboard is the user's, so only they are offered it.
  placements: ['palette'],
  canExecute: () => (alternatives.length === 0 ? deny('There is nothing to copy.') : allow()),
  execute: () => {
    void navigator.clipboard.writeText(rows.join('\n'))
  },
})
```

`placements` lists where the action is offered. Left out, it is `['palette', 'agent']`. List only
`'palette'` to keep the action from the agent, or `[]` to list it nowhere. Its shortcut and your own
button still run it either way.

</Step>

</Steps>

## Check it works

Run `pnpm dev` and open the shell at `http://localhost:3000`. Add the Alert panel to the dashboard
from the palette, under "Add to the dashboard". Open the palette again with <Kbd>⌘</Kbd> <Kbd>K</Kbd>
or <Kbd>Ctrl</Kbd> <Kbd>K</Kbd>, and look under "From the mounted application". The right-hand
column names the App or Widget that owns the action, and a denied one shows your reason there
instead. The lab App's Actions page has a button that calls the function `useAction` returned.

## Errors

<Callout type="error" title="expected a name of letters, digits and hyphens">

```text
alert-panel failed to register action: expected a name of letters, digits and hyphens starting
with a letter (for example "refresh"), received "acknowledge alert".
```

**Fix.** Rename the action to `acknowledge-alert`. Spaces, dots and colons are not allowed.

</Callout>

<Callout type="error" title="expected one registration per action name within a mount">

```text
alert-panel failed to register action 'refresh': expected one registration per action name
within a mount, received a second registration of 'refresh' in the same mount.
```

**Fix.** Rename one of the two. Neither is dropped in favour of the other, so the second one
throws instead.

</Callout>

<Callout type="error" title="expected a non-empty label">

```text
alert-panel failed to register action 'refresh': expected a non-empty label, received an empty
string.
```

**Fix.** Give the action the words you want in the palette. It is the only text the reader sees.

</Callout>

<Callout type="error" title="expected an effect">

```text
lab failed to register action 'plan-visit': expected an effect (read, write, destructive),
received "safe".
```

**Fix.** Use one of the three effects, or leave `effect` out to count the action as a write.

</Callout>

<Callout type="error" title="expected an inputSchema made with z.object">

```text
lab failed to register action 'plan-visit': expected an inputSchema made with z.object, received a
schema that is not an object schema.
```

**Fix.** Wrap the values in `z.object({ … })`. An action takes named values, as a tool's arguments
are.

</Callout>

<Callout type="error" title="cannot be represented in JSON Schema">

```text
lab failed to describe the inputSchema of action 'plan-visit' as JSON Schema: Error: Date cannot
be represented in JSON Schema.
```

**Fix.** Use only what JSON Schema can express: no dates, functions or transforms. Send a date as
an ISO string, with `z.iso.datetime()`.

</Callout>

<Callout type="error" title="expected input matching the action’s inputSchema">

```text
lab failed to accept input for action 'run-simulation' runs: expected input matching the action’s
inputSchema, received ✖ Invalid input: expected number, received string → at runs.
```

**Fix.** Call the action with input its `inputSchema` accepts. The run resolves `invalid` and
nothing runs. The code is `contract/input-mismatch`.

</Callout>

<Callout type="error" title="expected a value matching the action’s outputSchema">

```text
lab failed to return a value from action 'run-simulation' mean: expected a value matching the
action’s outputSchema, received ✖ Invalid input: expected number, received string → at mean.
```

**Fix.** Return what `outputSchema` declares from `execute`, or change the schema. The action has
already run, and the result is `failed` with the code `contract/output-mismatch`.

</Callout>

<Callout type="error" title="expected a shortcut such as 'mod+s'">

```text
operations failed to register action 'open-wells': expected a shortcut such as "mod+s" —
modifiers (mod, ctrl, alt, shift, meta) and one key joined by + — or a sequence of them separated
by spaces, such as "g r", received "mod+shift": "mod+shift" is only modifiers, with no key to
press.
```

**Fix.** Add the key the modifiers are held with, such as `mod+shift+w`. The message names what it
could not read.

</Callout>

<Callout type="error" title="expected keys the host page does not use">

```text
operations failed to register the shortcut 'g w' for action 'open-wells': expected keys the host
page does not use, received the host page’s '@host:dashboard' (g w) uses them.
```

**Fix.** Choose other keys. The action stays in the palette; only the shortcut is ignored.

</Callout>

<Callout type="error" title="expected keys no other live action can be pressed for at the same time">

```text
operations failed to register the shortcut 'mod+e' for action 'export': expected keys no other
live action can be pressed for at the same time, received 'operations:print' (mod+e) already
claims them.
```

**Fix.** Give one of the two different keys. Neither runs while both are registered. Two Apps at
different URLs may use the same keys, because only one of them is live at a time.

</Callout>

<Callout type="error" title="expected a shortcut from an App or the host page">

```text
alert-panel failed to register the shortcut 'mod+e' for action 'acknowledge-alert': expected a
shortcut from an App or the host page, received a shortcut from a Widget, which does not own the
page’s keys.
```

**Fix.** Drop the shortcut. If the keys matter, emit an output and let the App that places the
Widget register the shortcut.

</Callout>
