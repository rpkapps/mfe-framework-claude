---
title: 'Test storage and the lifecycle'
description: 'Seed a stored record, render through the test environment, then change the signed-in user and see that it stays.'
---

Apps and Widgets. Seed browser storage in a memory environment, mount your component, then change the signed-in user.
React uses a provider wrapper. Angular mounts a definition with its real injection context.

## Steps

<Steps>

<Step>

### 1. Create the environment, and dispose it after each test

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="Illustrative src/routes/storage.test.tsx"
import { useStoredState } from '@company/mfe-react'
import { createMfeTestEnvironment } from '@company/mfe-react/testing'
import { renderHook } from '@testing-library/react'
import { StrictMode } from 'react'
import { afterEach, expect, it } from 'vitest'
import { z } from 'zod'

const visitsSchema = z.number().int().nonnegative()
const draftSchema = z.object({ note: z.string(), pinned: z.boolean() })

let environment: ReturnType<typeof createMfeTestEnvironment> | null = null

afterEach(async () => {
  const current = environment
  environment = null
  await current?.dispose()
})
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular storage.test.ts"
import { Component, runInInjectionContext } from '@angular/core'
import { createWidget, injectStoredState } from '@company/mfe-angular'
import { cleanup, createMfeTestEnvironment, mountWidget } from '@company/mfe-angular/testing'
import { afterEach, expect, it } from 'vitest'
import { z } from 'zod'

const visitsSchema = z.number().int().nonnegative()
const draftSchema = z.object({ note: z.string(), pinned: z.boolean() })

@Component({ selector: 'storage-probe', template: '' })
class StorageProbe {}

const definition = createWidget({
  id: 'lab',
  inputSchema: z.object({}),
  outputSchema: z.object({}),
  component: StorageProbe,
})
let environment: ReturnType<typeof createMfeTestEnvironment> | null = null

afterEach(async () => {
  await cleanup()
  environment?.dispose()
  environment = null
})
```

</Tab>
</Tabs>

Declare each schema once, at module scope. The test and the component have to hand the framework
the same schema for the same key.

</Step>

<Step>

### 2. Seed the records before you render

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="Illustrative src/routes/storage.test.tsx"
environment = createMfeTestEnvironment({ definitionId: 'lab' })
const env = environment
const storage = env.mount.storage.local

storage.key('visits', visitsSchema).set(3)
storage.key('draft', draftSchema).set({ note: 'rig 4', pinned: true })
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular storage.test.ts"
environment = createMfeTestEnvironment({ definitions: [definition] })
const env = environment
const storage = env.runtime.storage.storageFor('lab')

storage.key('visits', visitsSchema).set(3)
storage.key('draft', draftSchema).set({ note: 'rig 4', pinned: true })
```

</Tab>
</Tabs>

The stores are in memory and start empty, so a test that reads a record writes it first.
`definitionId` becomes the key prefix, which makes the record above `lab:visits`. Hold the environment in a local so the steps below have one that is never `null`.
Place steps 2–5 inside an `it` callback. Use separate React test cases for the two `result` declarations.

</Step>

<Step>

### 3. Render inside the mount

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="Illustrative src/routes/storage.test.tsx"
const { result } = renderHook(() => useStoredState('visits', visitsSchema, { defaultValue: 0 }), {
  wrapper: env.wrapper,
})

expect(result.current[0]).toBe(3)
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular storage.test.ts"
const widget = await mountWidget(definition, { environment: env })
const state = runInInjectionContext(widget.injector, () =>
  injectStoredState('visits', visitsSchema, { defaultValue: 0 }),
)

expect(state.value()).toBe(3)
```

</Tab>
</Tabs>

React's wrapper supplies the mount providers. Angular's `mountWidget` supplies the mount injector.
Run each Angular injector call synchronously inside `runInInjectionContext`.
The awaited mount supplies a live injector; an `await` inside that injection callback would end its context.

</Step>

<Step>

### 4. Change the signed-in user

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="Illustrative src/routes/storage.test.tsx"
env.setShellState({ user: { id: 'u-2', name: 'Sam Reyes' } })

expect(result.current[0]).toBe(3)
expect(storage.key('draft', draftSchema).get()).toEqual({ note: 'rig 4', pinned: true })
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular storage.test.ts"
env.setShellState({ user: { id: 'u-2', name: 'Sam Reyes' } })
await widget.whenStable()

expect(storage.key('visits', visitsSchema).get()).toBe(3)
expect(storage.key('draft', draftSchema).get()).toEqual({ note: 'rig 4', pinned: true })
```

</Tab>
</Tabs>

`setShellState` runs the identity change the shell runs. Browser storage keeps both records after the identity changes. The old Angular mount may be disposed, so check persistence through the environment's storage handle. Keep nothing
personal in storage.

</Step>

<Step>

### 5. Check a remount

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```tsx title="Illustrative src/routes/storage.test.tsx"
const options = { defaultValue: 0 } as const

const { result } = renderHook(() => useStoredState('visits', visitsSchema, options), {
  wrapper: ({ children }) => (
    <StrictMode>
      <env.wrapper>{children}</env.wrapper>
    </StrictMode>
  ),
})
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular storage.test.ts"
await widget.dispose()
const remounted = await mountWidget(definition, { environment: env })
const next = runInInjectionContext(remounted.injector, () =>
  injectStoredState('visits', visitsSchema, { defaultValue: 0 }),
)

expect(next.value()).toBe(3)
```

</Tab>
</Tabs>

React's StrictMode checks repeated setup and cleanup. Angular checks explicit disposal and remounting.
Both should keep the stored record while ending the old subscriptions.

</Step>

</Steps>

## Check it works

The suite passes, and the assertions above hold in either order. Pass `shellState` to start with a
different user, groups or theme. The environment carries the rest of the mount too.

| Field           | For                                           |
| --------------- | --------------------------------------------- |
| `telemetry`     | the events, logs and spans the mount recorded |
| `diagnostics`   | what the framework reported                   |
| `navigation`    | where the mount asked to go                   |
| `routerContext` | calling a React route callback                |
| `storageAreas`  | inspecting what was written                   |
| `runtime`       | the registry, the stores and the shell state  |

## Errors

<Callout type="error" title="mount/failure, outside a mount">

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```text
<unmounted> failed to call useMfeStorage: expected a component rendered inside an App or Widget
mount, received a component rendered outside any mount.
```

</Tab>
<Tab value="Angular">

```text
<unmounted> failed to call injectMfeStorage(): expected a component or service created inside an App or Widget mount, received one created outside any mount.
```

</Tab>
</Tabs>

**Fix.** Render React through `environment.wrapper`. Mount the Angular definition with `mountWidget` before calling its injectors.

</Callout>

<Callout type="error" title="the same schema object every active consumer already declared">

```text shared
lab failed to bind the local storage key visits: expected the same schema object every active
consumer already declared, received a different schema object.
```

**Fix.** Import the one schema into the test instead of writing a second copy of it.

</Callout>
