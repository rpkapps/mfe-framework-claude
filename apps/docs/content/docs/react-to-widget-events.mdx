---
title: "React to a Widget's events"
description: 'Handle each declared event with an onX prop, typed from the published contract.'
---

Each event a Widget declares arrives as one `onX` prop, so `acknowledged` becomes
`onAcknowledged`. The payload is validated on its way out of the Widget, so your handler runs on
data that matches the contract.

## Steps

<Steps>

<Step>

### 1. Pass the contract, so the handlers are typed

```ts title="examples/operations/src/widgets.ts"
import { lazyWidget } from '@company/mfe-react'

import { events, inputs } from '@example/alert-panel/contracts'

export const AlertPanel = lazyWidget('alert-panel', { contract: { inputs, events } })
```

With a contract your editor knows every handler name and payload field, and without one the
component still works.

</Step>

<Step>

### 2. Add one handler per event

```tsx title="examples/lab/src/routes/widgets.tsx (trimmed)"
<AlertPanel
  alertId={alertId}
  severity={severity}
  onAcknowledged={event => {
    record(`acknowledged ${event.alertId} at ${event.acknowledgedAt}`)
  }}
  onDismissed={event => {
    record(`dismissed ${event.alertId}`)
  }}
/>
```

Subscribe to the events you care about, and leave the rest out.

</Step>

<Step>

### 3. Name the payload type where you need it

```ts
import type { Events } from '@example/alert-panel/contracts'

const [latest, setLatest] = useState<Events['acknowledged'] | null>(null)
```

The generated contract module exports the types `Events` and `Inputs` beside the schemas.

</Step>

</Steps>

## Check it works

Press the control inside the Widget and your handler runs with the payload. Payloads are JSON
only, so a date arrives as the string the Widget sent. An `onX` prop that matches no declared
event is ignored, and never reaches the Widget as an input. Changing a handler re-renders nothing
inside the Widget, so an inline arrow function is fine. The lab's Widgets page logs every event it
receives, which is the quickest way to see the shape of one.

<Callout type="warning" title="The handler never fires">

Check the name first. An event called `acknowledged` is `onAcknowledged`, with one capital letter
and no other change. Then check that the Widget declares it, as a property of `contract.events`
on its registry entry.

</Callout>

## Errors

<Callout type="error" title="contract/event-mismatch">

```text
alert-panel@1.4.0 failed to emit event 'acknowledged' acknowledgedAt: "2026-05-04T10:15:00.000Z"; ✖ Invalid input: expected number, received string
  → at acknowledgedAt.
```

**Fix.** Update the contract package you import. Your copy is older than the Widget that is
deployed, and your handler is not called while the two disagree.

</Callout>
