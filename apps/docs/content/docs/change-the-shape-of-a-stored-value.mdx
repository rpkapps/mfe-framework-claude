---
title: 'Change the shape of a stored value'
description: 'Raise version and declare migrate on the key so an old value is converted instead of failing the read.'
---

A stored value written by an older build no longer matches your schema. Raise `version` on the key
and declare `migrate` beside it, and the next read converts the old value. Apps and Widgets, in
every storage area.

## Steps

<Steps>
<Step>
### 1. Raise the version and convert

<Tabs items={['React', 'Angular']} defaultValue="React">
<Tab value="React">

```ts title="src/storage.ts"
import { storedKey } from '@company/mfe-react'
import { z } from 'zod'

export const draft = storedKey(
  'draft',
  z.object({ note: z.string(), pinned: z.boolean() }).default({ note: '', pinned: false }),
  {
    version: 2,
    migrate: (value, fromVersion) =>
      fromVersion === 0
        ? { note: '', pinned: false }
        : { note: (value as { text: string }).text, pinned: false },
  },
)
```

</Tab>
<Tab value="Angular">

```ts title="src/storage.ts"
import { storedKey } from '@company/mfe-angular'
import { z } from 'zod'

export const draft = storedKey(
  'draft',
  z.object({ note: z.string(), pinned: z.boolean() }).default({ note: '', pinned: false }),
  {
    version: 2,
    migrate: (value, fromVersion) =>
      fromVersion === 0
        ? { note: '', pinned: false }
        : { note: (value as { text: string }).text, pinned: false },
  },
)
```

</Tab>
</Tabs>

`version` starts at `1` and is an integer. Raise it whenever the stored shape changes. Every place
that reads the key keeps calling `useStoredState(draft)` or `injectStoredState(draft)` unchanged.

</Step>
<Step>
### 2. Handle version 0

```ts shared
if (fromVersion === 0) return { note: '', pinned: false }
```

Older, unversioned JSON in browser storage arrives as `fromVersion` 0. Handle it explicitly.

</Step>
<Step>
### 3. Keep migrate synchronous and free of side effects

```ts shared
// No fetch, no await, no set() on another key: migrate runs inside a read.
migrate: (value, fromVersion) => convert(value, fromVersion)
```

The framework converts the value, then validates it against your schema. A local or session value
is written back at once. A user value is written back on the owner's next save, never on read.
Nothing is written when `migrate` throws or returns a value your schema rejects.

</Step>
</Steps>

## Check it works

Store a value on the old build, then load the new one. The value on screen is the converted one,
and the local record now carries the new version. Run it a second time and nothing converts. In a
test, seed the old record and read it back through the new key.

## Errors

<Callout type="error" title="storage/invalid-value, at read">

```text shared
lab failed to read a user value draft: a value written at version 1. Add migrate() to 'draft' to
convert from version 1.
```

**Fix.** Declare `migrate` beside the raised `version`. The key reads its default with status
`error` until then, and the stored value is untouched.

</Callout>

<Callout type="error" title="storage/invalid-value, at read">

```text shared
lab failed to read a user value draft: a value written at version 3, newer than this key's 2.
Deploy the newer reader, or keep versions in step across apps.
```

**Fix.** Reload into the current build. A value from a newer build is never overwritten by a read.

</Callout>

<Callout type="error" title="storage/invalid-value, at migrate">

```text shared
lab failed to read a user value draft: migrate() threw: TypeError: …. Fix migrate().
```

**Fix.** Guard the fields you read in `migrate`. The previous value is preserved, so a fixed
conversion can try again. Local and session keys report the same failures, read from the browser.

</Callout>
