---
title: 'Change the shape of a stored value'
description: 'Raise version and declare migrate so an old record is converted instead of failing the read.'
---

A stored record written by an older build no longer matches your schema. Raise `version` and
declare `migrate` beside it, and the next read converts the old record. Apps and Widgets.

## Steps

<Steps>
<Step>
### 1. Raise the version and convert

```ts title="Illustrative shared migration options"
const draftOptions = {
  defaultValue: { note: '', pinned: false },
  version: 2,
  migrate: (value: unknown, fromVersion: number) =>
    fromVersion === 0
      ? { note: '', pinned: false }
      : { note: (value as { text: string }).text, pinned: false },
}
```

<Tabs items={['React', 'Angular']}>
<Tab value="React">

```tsx title="Illustrative React component body"
import { useStoredState } from '@company/mfe-react'

const [draft] = useStoredState('draft', draftSchema, draftOptions)
```

</Tab>
<Tab value="Angular">

```ts title="Illustrative Angular component field"
import { injectStoredState } from '@company/mfe-angular'

readonly draft = injectStoredState('draft', draftSchema, draftOptions)
```

</Tab>
</Tabs>

Declare `draftSchema` and `draftOptions` at module scope. Both frameworks use the same migration options.

`version` starts at `1` and is an integer. Raise it whenever the stored shape changes.

</Step>
<Step>
### 2. Handle version 0

```ts
if (fromVersion === 0) return { note: '', pinned: false }
```

Older, unversioned JSON arrives as `fromVersion` 0. Handle those records explicitly in your migration.

</Step>
<Step>
### 3. Keep migrate synchronous and free of side effects

```ts
// No fetch, no await, no set() on another key: migrate runs inside a read.
migrate: (value, fromVersion) => convert(value, fromVersion)
```

The framework converts the value, validates it against your schema, then writes it back. Nothing is
written when `migrate` throws or returns a value your schema rejects. The old record is left as it
was.

</Step>
</Steps>

## Check it works

Store a value on the old build, then load the new one. The value on screen is the converted one,
and the record in Local storage now carries the new version. Run it a second time and nothing
converts, because the record already matches. In a test, seed the old record and read it back
through the new declaration.

## Errors

<Callout type="error" title="storage/failure, at read">

```text
lab failed to read the local storage key draft: expected version 2, received version 1 with no
migrate() declared.
```

**Fix.** Declare `migrate` beside the raised `version`, or remove the key.

</Callout>

<Callout type="error" title="storage/failure, at read">

```text
lab failed to read the local storage key draft: expected version 1, received version 2, written by
a newer build.
```

**Fix.** Reload into the current build. A record from the future is never overwritten, so nothing
was lost.

</Callout>

<Callout type="error" title="storage/failure, at migrate">

```text
lab failed to migrate the local storage key draft: expected a value at version 2, received
migrate() threw (TypeError: …).
```

**Fix.** Guard the fields you read in `migrate`. The previous record is preserved, so you can try
again with a fixed conversion.

</Callout>
