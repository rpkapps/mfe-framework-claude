---
title: 'Use the design system'
description: 'Connect React or Angular styling to the shell-owned theme, scoped stylesheet and overlay roots.'
---

Apps and Widgets. The shell owns document styles and theme variables. Your container renders inside
its mount and overlay roots. This guide covers framework styling constraints.

## Steps

<Steps>
<Step>
### 1. Keep the framework's build integration

<Tabs items={['React', 'Angular']}>
<Tab value="React">

Keep `@tecton/react` in your container's dependencies. `pluginMfe()` needs its stylesheet scope plugin,
even when your component renders no Tecton control. Use the workspace override to select the built design-system checkout.

The build scans your source classes and generates one scoped stylesheet under `.mfe/`.
Do not add a second stylesheet entry or `postcss.config`. Those bypass the generated scope.

</Tab>
<Tab value="Angular">

Keep the generated Nx build integration and `src/primeng.ts` providers.
The Angular adapter itself supports any UI library. The scaffold uses PrimeNG with no preset;
the shell supplies its design tokens before the first Angular container mounts.

PrimeNG writes unscoped styles. Every Angular container on the page must use the same PrimeNG version.
Each container bundles its own copy. See [Angular styling constraints](/docs/reference/angular-adapter#use-primeng).

</Tab>
</Tabs>

</Step>
<Step>
### 2. Let shell styles inherit into the mount

Use the shell's theme variables. The shell owns the reset, fonts and document-level registrations.
Your generated stylesheet scopes container rules to its mount and overlay roots.

Do not declare another theme root, add a document-level dark class, or restyle `html` or `body`.
The build's scope root is a container element. A descendant selector such as `.card :root` cannot
select the document root inside it.

Use [the theme bindings](/docs/follow-the-shell-theme) when a rendered value depends on light or dark.

</Step>
<Step>
### 3. Keep overlays inside their supplied root

A menu or dialog must portal into the mount's overlay root so it retains the mount's styling context.
Tecton reads that root from the framework integration. In Angular, the generated providers route
supported PrimeNG overlays there. Dialog, ConfirmDialog and Drawer require explicit
`[appendTo]="mount.overlayRoot"`, with `mount = injectMfeMount()`.

Follow [Render dialogs, menus and tooltips](/docs/render-dialogs-and-tooltips) for the overlay integration.

</Step>
</Steps>

## Check it works

Switch the theme in the shell and confirm the container and its overlays follow it.
Inspect the generated stylesheet and verify container rules stay inside the mount roots.
Run `pnpm verify:page` for the repository's browser checks.
For PrimeNG, inspect the shell-supplied tokens and confirm every Angular container uses the same version.

## Errors

<Callout type="error" title="The scope plugin could not be resolved">

```text shared
/work/alert-panel/package.json: the build failed to load the stylesheet scope plugin: expected to
resolve '@tecton/react/postcss/scope' from the container or from the build plugin, found no copy of
@tecton/react beside either.
```

**Fix.** Keep `@tecton/react` in the React container's dependencies and build the linked checkout.

</Callout>

<Callout type="error" title="A root selector in a container stylesheet">

```text shared
`.card :root` matches nothing inside `@scope`: the scope root is not the document root, so `:root`,
`:host`, `html` and `body` only mean anything as the leading compound.
```

**Fix.** Target an element your container renders. Check dependencies' stylesheets too.

</Callout>
