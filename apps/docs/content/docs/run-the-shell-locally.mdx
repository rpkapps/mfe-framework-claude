---
title: 'Run the shell with your container'
description: 'Start your container and shell separately, then connect their local deployments.'
---

Apps and Widgets. Run your container in its own repository and the shell in its own repository. The shell needs a registry entry for your definition before a development override can redirect it.

## Steps

<Steps>

<Step>

### 1. Start your container

<Tabs items={['React', 'Angular']} defaultIndex={0}>
<Tab value="React">

```sh
pnpm install --frozen-lockfile
pnpm run dev
```

Run inside your React package directory, such as `apps/field-notes` in the quickstart repository. Its script generates local modules and starts the Rsbuild server.

</Tab>
<Tab value="Angular">

```sh
pnpm install --frozen-lockfile
pnpm exec nx serve operations
```

Run inside your container's Nx workspace. Replace `operations` with the project name. Its serve target generates local modules first.

</Tab>
</Tabs>

Install released dependencies from your configured registry. Record the port the server prints. Its `mf-manifest.json` must be reachable from the shell origin.

</Step>

<Step>

### 2. Register the local container with the shell

Give the shell's registry integration your generated `mfe-registry.json` and local deployment origin. This record is generated under the container project's `.mfe/` directory and published with build assets.

Your shell repository or registry service must assemble an entry for every exported definition. An override changes an existing entry's URL; it does not register a new definition.

</Step>

<Step>

### 3. Start the shell in a separate terminal

```sh title="shell repository" shared
pnpm install --frozen-lockfile
pnpm run dev
```

Use the development script your shell repository defines. Open the address it prints; its port belongs to that repository's configuration.

</Step>

<Step>

### 4. Point the registered definition at your server

Open the shell's **Overrides** panel. Enter your container's development manifest URL and apply the override. Give every definition from one container the same URL.

Your container owns its local runtime configuration and API fixtures. Starting the shell does not start your repository's server or API.

</Step>

</Steps>

## Check it works

The shell's **Registry** panel shows your definition and development origin. Open your App or mount your Widget, then edit its component. Keep both terminals running.

Framework maintainers can use the framework repository's combined example harness. Those commands are separate from this consumer workflow; see [CLI and scripts](/docs/reference/cli-and-scripts).
