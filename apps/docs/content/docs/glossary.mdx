---
title: 'Glossary'
description: 'Every term the guides use, defined once in plain words, with a link to the guide that explains it.'
---

Each guide defines its own terms where it uses them; this page repeats the definitions in one place
so you can look one up without reading around it. Every entry ends with a link to the guide that
explains the term in context.

| Term                         | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| adapter                      | Which implementation mounts a registry entry: `react` or `legacy-angular`. The first rule whose detection matches owns the entry, including when its validation then fails. A host registers a second adapter by passing its rule to `createMfeRuntime({ rules })`, which evaluates the framework contract rule first and the given rules after it. — [10. Shipping and failures](/docs/guides/shipping-and-failures#why-an-entry-is-quarantined-and-the-fix-for-each) |
| App                          | A micro-frontend that is routable: it owns a stretch of the URL and routes everything below it with its own TanStack Router instance. Declared with `createApp`. — [1. The shape](/docs/guides/shape)                                                                                                                                                                                                                                                                  |
| base path                    | The literal string form of the boundary, handed to your router factory as `AppRouterOptions.basePath` and passed straight into `createRouter({ basepath })`. After that it never appears again: every route, `Link` and `navigate` is relative to it. — [2. Declaring it](/docs/guides/declaring)                                                                                                                                                                      |
| boundary                     | The stretch of URL assigned to one App mount — the prefix the shell hands it. The shell owns `/<id>`; everything below belongs to that App. — [1. The shape](/docs/guides/shape)                                                                                                                                                                                                                                                                                       |
| boundary history             | The `RouterHistory` the framework builds for one App mount and hands to your factory. It exists because TanStack's `createBrowserHistory()` reassigns `window.history.pushState`, which makes two routers on a page fight over the URL. — [2. Declaring it](/docs/guides/declaring)                                                                                                                                                                                    |
| breadcrumb                   | One item in the trail the shell's header renders. The shell contributes its own at the top; an App contributes the rest from its router matches. — [4. What the shell gives you](/docs/guides/what-the-shell-gives-you)                                                                                                                                                                                                                                                |
| BuildProvenance              | `{ hash, time }` on a registry entry, saying which build the container came from. It never gates loading, and its only reader is the bug report. — [10. Shipping and failures](/docs/guides/shipping-and-failures#how-the-record-reaches-the-shells-registry)                                                                                                                                                                                                          |
| capability page              | A route inside an App that the shell can open by name without loading the App first: `settings`, `help` or `releaseNotes`. Declared with `staticData: { capability, label, icon? }` on a file route. — [4. What the shell gives you](/docs/guides/what-the-shell-gives-you)                                                                                                                                                                                            |
| command                      | An action a mount publishes into the shell's command palette. The mount owns it and decides whether it may run; the shell lists it and runs it. — [4. What the shell gives you](/docs/guides/what-the-shell-gives-you)                                                                                                                                                                                                                                                 |
| container                    | One deployable unit: a package with its own build, its own port in development, its own deployed origin and one `src/mfe.ts`. It exports at most one App and any number of Widgets. — [1. The shape](/docs/guides/shape)                                                                                                                                                                                                                                               |
| contract (inputs and events) | A Widget's two Zod schemas: `inputs`, one `z.object`, and `events`, a record of event name to payload schema. They are the single source of truth for runtime validation and for the author-facing types. — [2. Declaring it](/docs/guides/declaring)                                                                                                                                                                                                                  |
| contract major               | The framework contract version a container was built against, advertised as `mfe.contractMajor` on its registry entry. It is `1`; anything else is quarantined. — [10. Shipping and failures](/docs/guides/shipping-and-failures#three-versions-and-what-each-one-does)                                                                                                                                                                                                |
| `data-tecton-root`           | The marker the design system's `ThemeRoot` puts on its element. The generated style root also sets it on the mount's overlay root, so the library's base border and outline colours reach portalled content. — [8. Styling](/docs/guides/styling#the-scope-root-the-style-root-and-the-overlay-root)                                                                                                                                                                   |
| deadline                     | A single total time budget for one lifecycle phase. `MountController`, in `@company/mfe-host`, is the only thing that runs under one; nothing on the React mount path does, and `createMfeRuntime` has no option that adds one, so a load suspends until it settles or fails, and retry is explicit. — [6. Lifecycle](/docs/guides/lifecycle)                                                                                                                          |
| definition                   | The plain, side-effect-free descriptor `createApp` or `createWidget` returns. It is a value, not a component, so the build can read it statically without running a render function. — [2. Declaring it](/docs/guides/declaring)                                                                                                                                                                                                                                       |
| definition id                | Your surface's name everywhere: lower-case letters, digits and single hyphens, for example `alert-panel`. It is also the storage prefix and the CSS scope value, so it has to be unambiguous in both. — [9. Daily workflow](/docs/guides/daily-workflow#scaffolding-a-container)                                                                                                                                                                                       |
| deployment                   | One place a container's build is serving from, with its own `runtime-config.json` published beside its assets. One build is deployed many times, so nothing about where it talks to is baked into the bundle. — [3. Configuration and data](/docs/guides/config-and-data)                                                                                                                                                                                              |
| `DEV`                        | `process.env['NODE_ENV'] !== 'production'`, spelled literally so a bundler folds the guarded statement away in a production build. — [5. What you must not do](/docs/guides/what-you-must-not-do)                                                                                                                                                                                                                                                                      |
| depth                        | How deeply a mount is nested: the shell is 0, a top-level App 1, an App nested inside it 2. — [6. Lifecycle](/docs/guides/lifecycle)                                                                                                                                                                                                                                                                                                                                   |
| diagnostics hub              | The fan-out point every framework validation and lifecycle failure reaches, which calls every registered sink. A sink that throws cannot stop the others, and a hub with no sinks discards everything. — [10. Shipping and failures](/docs/guides/shipping-and-failures#what-reaches-you-without-writing-any-telemetry-code)                                                                                                                                           |
| `DynamicWidget`              | The component for a host that only learns which Widgets exist when it reads the registry, so it cannot call `lazyWidget` at module scope. It takes the id as a prop, is contract-free by construction, and adds `onEvent(name, payload)`. — [1. The shape](/docs/guides/shape)                                                                                                                                                                                         |
| expose name                  | The generated Module Federation path a definition is published at: `./app` for an App, `./widgets/<id>` for a Widget. Generated, never written by hand. — [10. Shipping and failures](/docs/guides/shipping-and-failures#what-a-build-produces)                                                                                                                                                                                                                        |
| generated output             | Everything the build writes into `.mfe/`, plus `routeTree.gen.ts` and the shell's `registry.json`. None of it is in version control, none of it is edited by hand, and `pnpm run generate` is the one recovery command. — [9. Daily workflow](/docs/guides/daily-workflow#pnpm-run-generate-what-is-generated-and-where)                                                                                                                                               |
| host page                    | The document the shell owns, treated as a scope for storage, commands and breadcrumbs, as opposed to any definition mounted on it. — [7. Storage](/docs/guides/storage)                                                                                                                                                                                                                                                                                                |
| `@host` scope                | The reserved scope name for state the page owns rather than any definition on it. The `@` reserves it, because a definition id may only hold lower-case letters, digits and single hyphens. — [7. Storage](/docs/guides/storage)                                                                                                                                                                                                                                       |
| `lazyWidget`                 | `lazyWidget(id, { contract? })`, called at module scope, returning a component. The component's identity is what React uses to decide it is looking at the same element, so one built during render would remount the Widget on every pass. — [1. The shape](/docs/guides/shape)                                                                                                                                                                                       |
| `#mfe/config`                | The module the build generates for a container that has a `src/mfe.config.ts`. It fetches the deployment's `runtime-config.json`, validates it against your Zod schemas in a top-level `await`, and exports the frozen, typed result. — [3. Configuration and data](/docs/guides/config-and-data)                                                                                                                                                                      |
| `MfeError`                   | The framework's structured error, carrying a machine-readable code, the definition id, the operation and one repair step. Its message is composed from five parts. — [10. Shipping and failures](/docs/guides/shipping-and-failures#how-to-read-a-framework-message)                                                                                                                                                                                                   |
| `#mfe/fetch`                 | The module the build generates for every container, exporting `fetch` and `getAccessToken`. Relative URLs resolve against your first `{ api: true }` field, and the session token is attached only to declared API origins. — [3. Configuration and data](/docs/guides/config-and-data)                                                                                                                                                                                |
| micro-frontend               | A piece of a single web page that is built, versioned and deployed on its own, by its own team, and loaded at run time into a page it does not own. The page is one browser document with one React tree; nothing here uses iframes. — [1. The shape](/docs/guides/shape)                                                                                                                                                                                              |
| Module Federation            | The bundler mechanism that lets one page load code from another build at run time. The shell registers each container as a remote and asks for a module out of it. — [10. Shipping and failures](/docs/guides/shipping-and-failures#what-a-build-produces)                                                                                                                                                                                                             |
| mount                        | One live instance of a definition on the page, with everything it owns: a mount token, a depth, a base path, a telemetry surface, two storage surfaces, an abort signal, its own Query client and a body-level overlay root. Two mounts of one definition are independent. — [6. Lifecycle](/docs/guides/lifecycle)                                                                                                                                                    |
| mount state                  | The lifecycle state of a mount as `MountState`, a type in `@company/mfe-core`: pending, mounted, error or disposed. `@company/mfe-react` does not export it and the React adapter never produces one, so you will not observe it. — [6. Lifecycle](/docs/guides/lifecycle)                                                                                                                                                                                             |
| mount token                  | The internal per-mount discriminator, `<definitionId>#<n>`, which distinguishes two mounts of one definition. It is never public API. — [6. Lifecycle](/docs/guides/lifecycle)                                                                                                                                                                                                                                                                                         |
| origin allowlist             | The exact set of `scheme://host:port` strings that may receive the session bearer token, built from your `env(…, { api: true })` declarations. No wildcards, no substring matching. — [3. Configuration and data](/docs/guides/config-and-data)                                                                                                                                                                                                                        |
| overlay root                 | A `<div>` the framework appends to `document.body` per mount, carrying the same `data-mfe-scope` value as the in-page root. Every overlay the container raises portals into it, so the overlay stays inside the container's `@scope`. — [8. Styling](/docs/guides/styling#the-scope-root-the-style-root-and-the-overlay-root)                                                                                                                                          |
| override                     | A boot-time redirection of one definition's manifest URL to a local dev server, read from `localStorage["company:mfe:overrides"]` before any remote is registered. It is a URL only, and changing one needs a page reload. — [9. Daily workflow](/docs/guides/daily-workflow#pointing-the-shell-at-your-container-the-override)                                                                                                                                        |
| quarantined entry            | A registry entry that failed validation. It is set aside with a reason and an error rather than dropped silently, and one bad entry costs only itself. — [10. Shipping and failures](/docs/guides/shipping-and-failures#why-an-entry-is-quarantined-and-the-fix-for-each)                                                                                                                                                                                              |
| React Refresh boundary       | A module a dev server can replace in place without reloading the page, which React Refresh proves only when every export of the module is a component. `src/mfe.ts` exports a definition, so it can never be one — which is why the render lives in its own module. — [9. Daily workflow](/docs/guides/daily-workflow#why-one-edit-hot-updates-and-another-reloads-the-page)                                                                                           |
| registry                     | The JSON array the shell fetches at boot, saying which definitions exist, where each container's manifest is and what each Widget takes. It is generated, never hand-written. — [10. Shipping and failures](/docs/guides/shipping-and-failures#how-the-record-reaches-the-shells-registry)                                                                                                                                                                             |
| registry entry               | One definition's record inside the registry: its id, kind, adapter and manifest URL, plus the optional version, capabilities, contract, build, title, description, tags and icon. — [10. Shipping and failures](/docs/guides/shipping-and-failures#how-the-record-reaches-the-shells-registry)                                                                                                                                                                         |
| remote entry                 | The JavaScript file a container publishes that lets a host load code from it: `remoteEntry.js`, described by `mf-manifest.json`, which the registry entry's manifest URL points at. — [10. Shipping and failures](/docs/guides/shipping-and-failures#what-a-build-produces)                                                                                                                                                                                            |
| reserved context keys        | `mfe` and `queryClient`: the two router-context keys an App must forward unchanged rather than replace. — [2. Declaring it](/docs/guides/declaring)                                                                                                                                                                                                                                                                                                                    |
| reserved input names         | `key`, `ref` and `fallback`, plus anything matching `/^on[A-Z]/`. A Widget may not declare an input with one of these names, because they belong to the host. — [2. Declaring it](/docs/guides/declaring)                                                                                                                                                                                                                                                              |
| retention                    | Who may read a stored value back, not how long it lives. `user`, the default, is fenced by the session generation; `browser` is never cleared by the framework, so every user of that browser profile reads the same value. — [7. Storage](/docs/guides/storage)                                                                                                                                                                                                       |
| `runtime-config.json`        | The deployment's values, published next to the container's assets and never built into it. The generated loader resolves its URL against the container's own public path. — [10. Shipping and failures](/docs/guides/shipping-and-failures#runtime-configjson-belongs-to-the-deployment)                                                                                                                                                                               |
| `@scope`                     | The CSS at-rule that bounds a block of rules to a subtree. The framework emits `@scope ([data-mfe-scope="<id>"]) to ([data-mfe-scope])` per container; it has the narrowest browser support of anything the framework requires, with no fallback. — [8. Styling](/docs/guides/styling#the-scope-rule-the-framework-emits)                                                                                                                                              |
| `SCOPE_ATTRIBUTE`            | `'data-mfe-scope'`, exported from `@company/mfe-react`. It is the attribute every mount root and every overlay root carries, and the one the container's `@scope` rule selects on. — [8. Styling](/docs/guides/styling#the-scope-root-the-style-root-and-the-overlay-root)                                                                                                                                                                                             |
| scoped stylesheet            | The CSS a container ships for its own classes, wrapped by the build in an `@scope` rule so it applies only inside that container's mount roots. A container ships no preflight, no fonts and no theme variables. — [8. Styling](/docs/guides/styling#what-your-containers-build-does-to-your-css)                                                                                                                                                                      |
| scope root                   | The `display: contents` element every mount renders around its tree, carrying `data-mfe-scope="<id>"`. It anchors a selector without becoming a box in the layout. — [8. Styling](/docs/guides/styling#the-scope-root-the-style-root-and-the-overlay-root)                                                                                                                                                                                                             |
| session generation           | An opaque string the shell mints once per signed-in identity per tab, stored at `@host:session-generation`. Every `retention: 'user'` record is stamped with it, and a new one is minted when the identity or the group set changes. — [7. Storage](/docs/guides/storage)                                                                                                                                                                                              |
| share scope                  | The map of packages the host and every container agree to share one copy of. A singleton package must resolve to exactly one instance on the page; a second copy makes every hook fail with "rendered outside any mount" while both copies look correct on their own. — [5. What you must not do](/docs/guides/what-you-must-not-do)                                                                                                                                   |
| shell (host)                 | The one application on the page that is not itself listed in the registry: it fetches the registry, owns the document, the header, the routes above a boundary, the document-level CSS, the theme and the session, and mounts Apps and Widgets into itself. — [4. What the shell gives you](/docs/guides/what-the-shell-gives-you)                                                                                                                                     |
| style root                   | The component the build generates and attaches to your definition, so the design system's context — including its portal target — comes from your container's own copy of the library. — [8. Styling](/docs/guides/styling#the-scope-root-the-style-root-and-the-overlay-root)                                                                                                                                                                                         |
| transport                    | The `{ fetch, getAccessToken }` object `#mfe/fetch` is built from. It resolves the shell's installed session on the first call, so a wiring mistake is an error on that request rather than on load. — [3. Configuration and data](/docs/guides/config-and-data)                                                                                                                                                                                                       |
| Widget                       | A micro-frontend that is not routable: it takes props, renders inside somebody else's page and owns no URL. Declared with `createWidget`. Apps take URLs; Widgets take props. — [1. The shape](/docs/guides/shape)                                                                                                                                                                                                                                                     |
