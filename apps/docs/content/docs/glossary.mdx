Every term the guides use, defined once. Each entry says what the thing is and links to the page that explains it in context.

| Term                           | Meaning                                                                                                                                                                                                                                                                                  |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| adapter                        | The host-neutral choice of which implementation mounts a registry entry: `react` or `legacy-angular`. Only the chosen adapter reads that entry's adapter-private fields. — [The design map](/docs/design#how-the-adapters-fit-together)                                                  |
| adapter selection rule         | The `{ adapter, advertises, normalize }` object that takes entries for one adapter. The first rule whose `advertises` returns true owns the entry, even when its `normalize` then fails. — [The design map](/docs/design#how-the-adapters-fit-together)                                  |
| App                            | A micro-frontend that is routable: it owns a stretch of the URL and routes everything below it with its own TanStack Router instance. Declared with `createApp`. — [1. The shape](/docs/guides/shape)                                                                                    |
| base href kind                 | How a legacy Angular app gets its `APP_BASE_HREF`. It is app-pinned when the app keeps its own, and delegated when the app takes the one single-spa supplies. — [Legacy Angular](/docs/reference/legacy-angular)                                                                         |
| base path                      | The URL prefix one App mount owns, handed to your router factory as `AppRouterOptions.basePath`. Pass it straight into `createRouter({ basepath })`. — [2. Declaring it](/docs/guides/declaring)                                                                                         |
| boundary                       | The stretch of URL assigned to one App mount. The shell owns `/<id>`, and everything below it belongs to that App. — [1. The shape](/docs/guides/shape)                                                                                                                                  |
| boundary history               | The `RouterHistory` the framework builds for one App mount and hands to your factory. It keeps two routers on one page from fighting over the URL. — [2. Declaring it](/docs/guides/declaring)                                                                                           |
| breadcrumb                     | One item in the trail the shell's header renders. The shell contributes its own at the top, and an App contributes the rest from its router matches. — [4. What the shell gives you](/docs/guides/what-the-shell-gives-you)                                                              |
| BuildProvenance                | `{ hash, time }` on a registry entry, naming the build the container came from. It never gates loading, and its only reader is the bug report. — [10. Shipping and failures](/docs/guides/shipping-and-failures#how-your-record-reaches-the-registry)                                    |
| capability page                | A route the shell can open by name without loading its App first: `settings`, `help` or `releaseNotes`. Declare it with `staticData` on a file route. — [4. What the shell gives you](/docs/guides/what-the-shell-gives-you)                                                             |
| command                        | An action a mount publishes into the shell's command palette. The mount decides whether it may run, and the shell lists it and runs it. — [4. What the shell gives you](/docs/guides/what-the-shell-gives-you)                                                                           |
| container                      | One deployable unit: one package, one build, one deployed origin and one `src/mfe.ts`. It exports at most one App and any number of Widgets. — [1. The shape](/docs/guides/shape)                                                                                                        |
| contract (inputs and events)   | A Widget's two Zod schemas: `inputs`, one `z.object`, and `events`, a record of event name to payload schema. They drive runtime validation and the author-facing types. — [2. Declaring it](/docs/guides/declaring)                                                                     |
| contract major                 | The framework contract version a container was built against, declared as `mfe.contractMajor` on its registry entry. It is `1`, and the shell rejects any other value. — [10. Shipping and failures](/docs/guides/shipping-and-failures#the-three-versions)                              |
| `data-tecton-root`             | The marker the design system's `ThemeRoot` puts on its element. The style root sets it on the mount's overlay root too, so the library's colours reach portalled content. — [8. Styling](/docs/guides/styling#the-three-roots-scope-style-overlay)                                       |
| deadline                       | A single total time budget for one lifecycle phase. `MountController`, in `@company/mfe-host`, is the only thing that runs under one. — [6. Lifecycle](/docs/guides/lifecycle)                                                                                                           |
| definition                     | The plain, side-effect-free descriptor `createApp` or `createWidget` returns. It is a value, so the build can read it without running a render function. — [2. Declaring it](/docs/guides/declaring)                                                                                     |
| definition id                  | Your screen's name everywhere: lower-case letters, digits and single hyphens, for example `alert-panel`. It is also the storage prefix and the CSS scope value. — [9. Daily workflow](/docs/guides/daily-workflow#scaffold-a-container)                                                  |
| deployment                     | One place a container's build is serving from, with its own `runtime-config.json` published beside its assets. One build is deployed many times. — [3. Configuration and data](/docs/guides/config-and-data)                                                                             |
| `DEV`                          | `process.env['NODE_ENV'] !== 'production'`, spelled literally so a bundler folds the guarded statement away in a production build. — [5. What you must not do](/docs/guides/what-you-must-not-do)                                                                                        |
| depth                          | How deeply a mount is nested: the shell is 0, a top-level App 1, an App nested inside it 2. — [6. Lifecycle](/docs/guides/lifecycle)                                                                                                                                                     |
| diagnostics hub                | The fan-out point every framework validation and lifecycle failure reaches, which calls every registered sink. A sink that throws cannot stop the others. — [10. Shipping and failures](/docs/guides/shipping-and-failures#what-you-get-without-writing-telemetry-code)                  |
| `DynamicWidget`                | The component for a host that learns which Widgets exist only at run time, from the registry. It takes the id as a prop and adds `onEvent(name, payload)`. — [1. The shape](/docs/guides/shape)                                                                                          |
| expose name                    | The generated Module Federation path a definition is published at: `./app` for an App, `./widgets/<id>` for a Widget. — [10. Shipping and failures](/docs/guides/shipping-and-failures#what-your-build-produces)                                                                         |
| generated output               | Everything the build writes into `.mfe/`, plus `routeTree.gen.ts` and the shell's `registry.json`. None of it is committed, and `pnpm run generate` rebuilds all of it. — [9. Daily workflow](/docs/guides/daily-workflow#generate-the-mfe-modules)                                      |
| host page                      | The document the shell owns, treated as one scope for storage, commands and breadcrumbs. — [7. Storage](/docs/guides/storage)                                                                                                                                                            |
| `@host` scope                  | The scope name for state the page owns. The `@` keeps it reserved, because a definition id holds only lower-case letters, digits and single hyphens. — [7. Storage](/docs/guides/storage)                                                                                                |
| `lazyWidget`                   | `lazyWidget(id, { contract? })`, called at module scope, returning a component. Call it during render instead and React remounts the Widget on every pass. — [1. The shape](/docs/guides/shape)                                                                                          |
| legacy Angular adapter         | `@company/mfe-legacy-angular`: the removable adapter that mounts legacy single-spa Angular apps. It translates legacy registry fields into the neutral record and keeps legacy vocabulary out of it. — [Legacy Angular](/docs/reference/legacy-angular)                                  |
| `#mfe/config`                  | The module the build generates for a container with `src/mfe.config.ts`. It fetches the deployment's `runtime-config.json`, validates it, and exports the frozen, typed result. — [3. Configuration and data](/docs/guides/config-and-data)                                              |
| `MfeError`                     | The framework's structured error, carrying a machine-readable code, the definition id, the operation and one repair step. Its message is composed from five parts. — [10. Shipping and failures](/docs/guides/shipping-and-failures#how-to-read-a-framework-message)                     |
| `#mfe/fetch`                   | The module the build generates for every container, exporting `fetch` and `getAccessToken`. It attaches the session token to declared API origins only. — [3. Configuration and data](/docs/guides/config-and-data)                                                                      |
| micro-frontend                 | A piece of one web page that its own team builds, deploys and loads at run time into a page it does not own. One browser document, one React tree. — [1. The shape](/docs/guides/shape)                                                                                                  |
| Module Federation              | The bundler mechanism that lets one page load code from another build at run time. The shell registers each container as a remote and asks it for a module. — [10. Shipping and failures](/docs/guides/shipping-and-failures#what-your-build-produces)                                   |
| mount                          | One live instance of a definition, with the token, depth, base path, telemetry, storage, Query client and overlay root it owns. Two mounts of one definition are independent. — [6. Lifecycle](/docs/guides/lifecycle)                                                                   |
| mount state                    | The lifecycle state of a mount as `MountState`, a type in `@company/mfe-core`: pending, mounted, error or disposed. The React adapter never produces one, so you will not observe it. — [6. Lifecycle](/docs/guides/lifecycle)                                                           |
| mount token                    | The internal per-mount discriminator, `<definitionId>#<n>`, which tells two mounts of one definition apart. It is never public API. — [6. Lifecycle](/docs/guides/lifecycle)                                                                                                             |
| neutral host                   | `@company/mfe-host`: the package that normalizes the registry, picks an adapter per entry and orchestrates mounting. It imports no React, router, single-spa or Module Federation. — [The design map](/docs/design#how-the-adapters-fit-together)                                        |
| origin allowlist               | The exact set of `scheme://host:port` strings that may receive the session bearer token, built from your `env(…, { api: true })` declarations. There are no wildcards. — [3. Configuration and data](/docs/guides/config-and-data)                                                       |
| overlay root                   | A `<div>` the framework appends to `document.body` per mount, carrying the same `data-mfe-scope` value as the in-page root. Every overlay the container raises portals into it. — [8. Styling](/docs/guides/styling#the-three-roots-scope-style-overlay)                                 |
| override                       | A boot-time redirection of one definition's manifest URL to your dev server, read from `localStorage["company:mfe:overrides"]`. Changing one needs a page reload. — [9. Daily workflow](/docs/guides/daily-workflow#point-the-shell-at-your-container)                                   |
| parcel                         | The single-spa mount and unmount lifecycle the legacy adapter drives: `mountRootParcel`, then `parcel.mountPromise`, then `parcel.unmount()`. A remount creates a fresh parcel. — [Legacy Angular](/docs/reference/legacy-angular)                                                       |
| React Refresh boundary         | A module a dev server can replace in place without reloading the page. React Refresh allows it only when every export of the module is a component. — [9. Daily workflow](/docs/guides/daily-workflow#keep-hot-updates-working)                                                          |
| registry                       | The JSON array the shell fetches at boot, naming every definition, where its container's manifest lives and what each Widget takes. It is generated, never hand-written. — [10. Shipping and failures](/docs/guides/shipping-and-failures#how-your-record-reaches-the-registry)          |
| registry entry                 | One definition's record in the registry: its id, kind, adapter and manifest URL, plus the optional version, capabilities, contract, build, title, description, tags and icon. — [10. Shipping and failures](/docs/guides/shipping-and-failures#how-your-record-reaches-the-registry)     |
| rejected entry (`quarantined`) | A registry entry that failed validation. The registry sets it aside with a reason and an error, and every other entry still loads. — [10. Shipping and failures](/docs/guides/shipping-and-failures#why-an-entry-is-rejected-and-how-to-fix-it)                                          |
| remote entry                   | The JavaScript file a container publishes for a host to load code from: `remoteEntry.js`. `mf-manifest.json` describes it, and your registry entry points at that manifest. — [10. Shipping and failures](/docs/guides/shipping-and-failures#what-your-build-produces)                   |
| reserved context keys          | `mfe` and `queryClient`: the two router-context keys an App forwards unchanged rather than replaces. — [2. Declaring it](/docs/guides/declaring)                                                                                                                                         |
| reserved input names           | `key`, `ref` and `fallback`, plus anything matching `/^on[A-Z]/`. They belong to the host, so a Widget may not declare an input with one. — [2. Declaring it](/docs/guides/declaring)                                                                                                    |
| retention                      | Who may read a stored value back. `user`, the default, is cleared when the signed-in identity changes, and the framework never clears `browser`. — [7. Storage](/docs/guides/storage)                                                                                                    |
| `runtime-config.json`          | The deployment's values, published next to the container's assets and never built into it. The generated loader resolves its URL against the container's own public path. — [10. Shipping and failures](/docs/guides/shipping-and-failures#runtime-configjson-belongs-to-the-deployment) |
| `@scope`                       | The CSS at-rule that bounds a block of rules to a subtree. The framework emits one per container, and no fallback exists for a browser without it. — [8. Styling](/docs/guides/styling#the-scope-rule)                                                                                   |
| `SCOPE_ATTRIBUTE`              | `'data-mfe-scope'`, exported from `@company/mfe-react`. Every mount root and every overlay root carries it, and the container's `@scope` rule selects on it. — [8. Styling](/docs/guides/styling#the-three-roots-scope-style-overlay)                                                    |
| scope root                     | The `display: contents` element every mount renders around its tree, carrying `data-mfe-scope="<id>"`. It anchors a selector without becoming a box in the layout. — [8. Styling](/docs/guides/styling#the-three-roots-scope-style-overlay)                                              |
| scoped stylesheet              | The CSS a container ships for its own classes, wrapped by the build in an `@scope` rule so it applies only inside that container's mount roots. — [8. Styling](/docs/guides/styling#the-stylesheet-your-build-writes)                                                                    |
| session generation             | An opaque string the shell creates once per signed-in identity per tab, stored at `@host:session-generation`. Every `retention: 'user'` record is stamped with it. — [7. Storage](/docs/guides/storage)                                                                                  |
| share scope                    | The map of packages the host and every container share one copy of. A second copy of a singleton makes every hook fail with "rendered outside any mount". — [5. What you must not do](/docs/guides/what-you-must-not-do)                                                                 |
| shell (host)                   | The application that serves the page, owns the document and mounts containers into it. It is the only application on the page with no registry entry. — [4. What the shell gives you](/docs/guides/what-the-shell-gives-you)                                                             |
| style root                     | The component the build generates and attaches to your definition, so the design system's context comes from your container's own copy of the library. — [8. Styling](/docs/guides/styling#the-three-roots-scope-style-overlay)                                                          |
| transport                      | The `{ fetch, getAccessToken }` object `#mfe/fetch` is built from. It resolves the shell's session on the first call, so a wiring mistake fails that request rather than the load. — [3. Configuration and data](/docs/guides/config-and-data)                                           |
| Widget                         | A micro-frontend that takes props and renders inside somebody else's page, owning no URL. Declared with `createWidget`. — [1. The shape](/docs/guides/shape)                                                                                                                             |
