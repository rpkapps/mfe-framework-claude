A <Term>micro-frontend</Term> is one piece of a web page, built and deployed on its own by its own
team. A page somebody else owns loads that piece at run time and renders it beside pieces from
other teams. The page stays one browser document with one React tree, and nothing here uses an
iframe. These pages show you how to build a piece with React and TanStack Router.

## The two things you can build

You can build two things: an App or a Widget. Apps take URLs, and Widgets take props. A screen a
user can link to is an App. A screen placed by whoever renders the page around it is a Widget.

### An App takes a URL

An <Term>App</Term> owns a stretch of the URL and routes everything below it with its own TanStack
Router instance. One container exports at most one App.

```ts title="examples/operations/src/mfe.ts (trimmed)"
function makeRouter({ basePath, history, context }: AppRouterOptions) {
  return createRouter({ routeTree, basepath: basePath, history, context: { ...context } })
}

export default createApp({ id: 'operations', version: '2.1.0', router: makeRouter })
```

### A Widget takes props

A <Term>Widget</Term> owns no URL. It takes props from whoever renders it, and tells that consumer
what happened by emitting a declared event. One container may export any number of Widgets.

```ts title="examples/alert-panel/src/mfe.ts (trimmed)"
export const alertPanel = createWidget({
  id: 'alert-panel',
  version: '1.4.0',
  inputs: z.object({ alertId: z.string() }),
  events: { acknowledged: z.object({ alertId: z.string() }) },
  render: AlertPanel,
})
```

## Three words used on every page

Every page below uses these three words.

| Word                   | What it is                                                                                                                                                                                                |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <Term>container</Term> | One deployable unit: one package, one build, one deployed origin, one `src/mfe.ts`. What you build and ship is a container.                                                                               |
| <Term>shell</Term>     | The application that serves the page, owns the document and mounts containers into it. It owns the header, the theme, the session and the routes above your App. Other documents call that role the host. |
| <Term>registry</Term>  | The JSON list the shell fetches at boot: which definitions exist, where each container's manifest is, and what each Widget takes. The build generates it.                                                 |
