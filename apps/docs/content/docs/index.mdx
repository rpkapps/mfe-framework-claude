You build one piece of a page somebody else owns: an App or a Widget. An App owns a stretch of the
URL and routes everything under it. A Widget owns no URL, takes props from whoever renders it, and
reports back by emitting a declared output. A screen a user can link to is an App, and a screen the
page around it places is a Widget. One container exports at most one App and any number of Widgets.

### An App takes a URL

```ts title="examples/operations/src/mfe.ts (trimmed)"
function makeRouter({ basePath, history, context }: AppRouterOptions) {
  return createRouter({ routeTree, basepath: basePath, history, context: { ...context } })
}

export default createApp({ id: 'operations', version: '2.1.0', router: makeRouter })
```

### A Widget takes props

```ts title="examples/alert-panel/src/mfe.ts (trimmed)"
export const alertPanel = createWidget({
  id: 'alert-panel',
  version: '1.4.0',
  inputSchema: z.object({ alertId: z.string() }),
  outputSchema: z.object({
    acknowledged: z.object({ alertId: z.string(), acknowledgedAt: z.string() }),
  }),
  render: AlertPanel,
})
```

## Three words used on every page

| Word                   | What it is                                                                                                                                                                                                |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <Term>container</Term> | One deployable unit: one package, one build, one deployed origin, one `src/mfe.ts`. What you build and ship is a container.                                                                               |
| <Term>shell</Term>     | The application that serves the page, owns the document and mounts containers into it. It owns the header, the theme, the session and the routes above your App. Other documents call that role the host. |
| <Term>registry</Term>  | The JSON list the shell fetches at boot: which definitions exist, where each container's manifest is, and what each Widget takes. The build generates it.                                                 |
